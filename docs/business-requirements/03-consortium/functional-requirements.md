# BP-03.2. Функциональные требования: консорциум

## 1. Запуск и настройка дискуссии (BP-03, шаг 1; назначение и триггер)

### FR-01 — Запуск консорциума в чате
Система должна давать запустить консорциум в чате — живую дискуссию 2–4 ИИ по одной теме.
**Приёмка:** консорциум запускается из чата; тема дискуссии — первое сообщение пользователя (решение
владельца); участников — от 2 до 4 (FR-03).
(Триггер и назначение BP-03; определения, требования чата; решение владельца)

### FR-02 — Выбор формата
Система должна давать выбрать формат дискуссии из фиксированного набора: совет, дебаты, мозговой штурм,
ред-тим, roast.
**Приёмка:** доступны для выбора только пять перечисленных форматов; выбранный формат применяется к
дискуссии; чем форматы различаются — источники не описывают (BP-03.1, «Область вне требований»).
(BP-03, шаг 1; требования чата; назначение BP-03)

### FR-03 — Выбор участников (2–4 ИИ)
Система должна давать выбрать участников — от 2 до 4 подключённых ИИ.
**Приёмка:** можно выбрать 2, 3 или 4 ИИ; выбор одного ИИ или более четырёх недоступен; поведение при менее
чем двух подключённых ИИ не описано (BP-03.1, «Область вне требований»).
(BP-03, шаг 1; требования чата)

### FR-04 — Число раундов
Система должна давать задать число раундов и вести дискуссию заданное число раундов.
**Приёмка:** пользователь задаёт число раундов; дискуссия идёт столько раундов, сколько задано (FR-07);
значение по умолчанию не описано (BP-03.1, «Область вне требований»).
(BP-03, шаг 1; требования чата)

### FR-05 — Выбор суммаризатора
Система должна давать выбрать суммаризатора — ИИ, который подведёт итог дискуссии.
**Приёмка:** пользователь выбирает, какой ИИ подводит итог; итог готовит выбранный суммаризатор (FR-11);
является ли суммаризатор участником — не описано (BP-03.1, «Область вне требований»).
(BP-03, шаг 1; требования чата; описание архитектуры («Консорциум») — «кто подводит итог»)

### FR-06 — Лимит длины реплик
Система должна давать задать лимит длины реплик и применять его к репликам участников.
**Приёмка:** реплики ограничены заданным лимитом длины; единицы измерения и значение по умолчанию не описаны
(BP-03.1, «Область вне требований»).
(BP-03, шаг 1; требования чата; описание архитектуры («Консорциум») — «длина реплик»)

## 2. Ведение дискуссии (BP-03, шаг 2)

### FR-07 — Дискуссия по очереди и роли
Система должна вести дискуссию по очереди по раундам с фиксированными ролями: ведущий ведёт, участники
выступают, суммаризатор подводит итог (FR-05, FR-11).
**Приёмка:** за раунд участники выступают по одному разу в порядке очереди; роли закреплены: ведущий,
участники, суммаризатор (решение владельца); число раундов — FR-04.
(BP-03, шаг 2; требования чата; описание архитектуры («Консорциум») — «по очереди», «роли»; решение владельца)

### FR-08 — Память по правам участника
Система должна давать каждому участнику память только по его правам доступа.
**Приёмка:** участник получает память только по своим правам доступа; скрытые части, скрытые теги и
факт-архив не передаются (тема 4.1; BP-07); настройка доступов — BP-12.
(BP-03, шаг 2; тема 4.1; BP-07)

## 3. Остановка «Стоп» (BP-03, шаг 3)

### FR-09 — «Стоп» ставит дискуссию на паузу
Система должна по команде «Стоп» ставить дискуссию на паузу: останавливать текущего ИИ, сохраняя сказанное;
дискуссию можно продолжить.
**Приёмка:** генерация текущей реплики прекращается; сказанное до остановки сохраняется в чате; дискуссия на
паузе; продолжение — по команде пользователя (решение владельца).
(BP-03, шаг 3 и результат; требования чата; решение владельца)

## 4. Спор под ответом (BP-03, шаг 4)

### FR-10 — Спор под любым ответом
Система должна поддерживать «спор» под любым ответом дискуссии: автор ответа защищает его, остальные
участники ищут слабости.
**Приёмка:** под любым ответом можно запустить спор; в споре автор ответа защищается, остальные ищут
слабости; допущение: реплики спора идут в чате по правилам дискуссии (FR-07, FR-08) — порядок и права в
споре, а также чем спор завершается, в источниках не описаны (BP-03.1, «Область вне требований»).
(BP-03, шаг 4; требования чата)

## 5. Итог дискуссии (результат BP-03)

### FR-11 — Итог суммаризатора в чате
Система должна по завершении раундов готовить итог дискуссии силами выбранного суммаризатора и показывать
его в чате.
**Приёмка:** итог от выбранного суммаризатора (FR-05) появляется в чате по завершении заданного числа
раундов (FR-04).
(Результат BP-03; требования чата; описание архитектуры («Консорциум»))

## 6. Действия участников и сбои провайдеров (BP-03, шаг 5)

### FR-12 — Действия участников — по правилам BP-04
Система должна исполнять действия, запрошенные участниками, по правилам BP-04.
**Приёмка:** действия участников проходят через BP-04 (разрешения, лимиты, отмена) без изменений; механика —
см. BP-04.
(BP-03, шаг 5; BP-04)

### FR-13 — Сбои и лимит вызова провайдеров участников
Система должна применять к провайдерам участников единые правила темы 4.3 (сбои; лимит вызова) — в том
виде, как они заданы темой.
**Приёмка:** правила темы 4.3 применены к репликам участников без изменений; дальнейший ход дискуссии при
сбое не описан (BP-03.1, «Область вне требований»).
(BP-03, шаг 5; тема 4.3; краевые состояния)

## 7. Сквозные темы, применённые к репликам

### FR-14 — Язык реплик
Система должна вести реплики участников на языке общения, заданном в профиле.
**Приёмка:** реплики следуют выбранному языку общения; язык общения задаётся в профиле — BP-12. Тема 4.5 в
каталоге привязана к BP-01/BP-12; правило «ответы ИИ следуют выбранному языку» применимо к репликам
участников как к ответам ИИ.
(Тема 4.5; онбординг и приложение)

Примечание: скрытие секретов и журнал исходящих (тема 4.1) и правила общения (BP-12) к BP-03 каталогом не
привязаны — см. BP-03.1, «Область вне требований»; отдельные FR для них не вводятся.
