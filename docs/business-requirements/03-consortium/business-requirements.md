# BP-03.1. Бизнес-требования: консорциум

## Цель

Обеспечить пользователю возможность вести в чате живую дискуссию 2–4 ИИ по одной теме в выбранном формате и получить её итог.

## Бизнес-результат

Итог дискуссии появляется в чате; при остановке «Стопом» сказанное сохраняется. Участники выступают по очереди заданное число раундов, каждый получает память только по своим правам доступа.

## Требования

- Система должна позволять запустить консорциум в чате — живую дискуссию 2–4 ИИ по одной теме.
- Тему дискуссии система должна принимать первым сообщением пользователя.
- Система должна позволять выбрать формат из фиксированного набора: совет, дебаты, мозговой штурм, ред-тим, roast.
- Система должна позволять выбрать участников — от 2 до 4 ИИ, число раундов, суммаризатора и лимит длины реплик.
- Система должна вести дискуссию по фиксированным ролям: ведущий, участники, суммаризатор.
- Система должна вести дискуссию по очереди: участники выступают по очереди по раундам.
- Система должна давать каждому участнику память только по его правам доступа.
- Система должна по команде «Стоп» ставить дискуссию на паузу: останавливать текущего ИИ, сохраняя сказанное; дискуссию можно продолжить.
- Система должна поддерживать спор под любым ответом: автор ответа защищает его, остальные участники ищут слабости.
- Система должна по завершении раундов готовить итог дискуссии силами выбранного суммаризатора и показывать его в чате.
- Действия, которые запрашивают участники, система должна исполнять по правилам BP-04; сбои провайдеров — по правилам BP-02 и темы 4.3.

## Бизнес-правила

- Форматы фиксированы: совет, дебаты, мозговой штурм, ред-тим, roast.
- Роли фиксированы: ведущий, участники, суммаризатор.
- Тема дискуссии — первое сообщение пользователя.
- Участник — ИИ со своим клиентом: права доступа и скрытые теги — как в чате; скрытые части памяти и факт-архив участнику не передаются.
- Итог подводит выбранный суммаризатор.
- Один вызов провайдера — не более 300 с — применим и к репликам участников.
- Пользователь выбирает формат, участников, число раундов, суммаризатора и лимит длины и не вводит системные идентификаторы.

## Область вне требований

- Чем форматы различаются, не описано.
- Является ли суммаризатор участником, в каких единицах задаётся лимит длины и есть ли значение по умолчанию — не описаны.
- Поведение при менее чем двух подключённых ИИ и при сбое провайдера участника не описано.
- Скрытие секретов и журнал исходящих (тема 4.1) и правила общения (BP-12) к консорциуму каталогом не привязаны.
- Обычный чат задан в BP-02, запись в память — в BP-07, настройка провайдеров — в BP-12, обучение — в BP-08; здесь они не описываются.
