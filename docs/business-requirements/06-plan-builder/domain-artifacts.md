# BP-06.4. Артефакты предметной области: конструктор схем

Сущности схемы: цепочка и шаг, варианты, смета и бюджет, экономия, исполнители; правила подбора
исполнителей; словарь причин остановки шага; словарь терминов. Механика чата, действий, памяти, цен
провайдеров и лимитов не дублируется — ссылки на BP-02, BP-04, BP-07, BP-12 и темы 4.1, 4.3, 4.8.
Факты, которые вводные не задают, отмечены ссылкой на BP-06.1 («Область вне требований») или словом
«допущение» — и в диаграмме, и в таблицах.

## 1. Модель состояний схемы

```
Пользователь описывает задачу и просит варианты (триггер BP-06)
        │
        ▼
Подбор: планировщик подбирает шаги и исполнителей из подключённых ИИ (BP-06, шаг 1; FR-01)
        │   [нет подключённых ИИ — не описано, BP-06.1, «Область вне требований»]
        ▼
Варианты предложены: Быстро / Оптимально / Качественно, до 6 шагов («Качественно» — до 5)
        │   (BP-06, шаг 2; FR-02, FR-03)  смета: время/токены — по таблице средних показателей моделей,
        │   цена (FR-02, FR-04); экономия применяется всегда (BP-06, шаг 4; FR-07)
        ├─ правка шагов и исполнителей до запуска (FR-16)
        ├─ рекомендуемый бюджет — из дешёвой сметы (BP-06, шаг 3; FR-05)   [какая смета «дешёвая» — допущение, 2.6]
        └─ свой бюджет ($) ──► пересчёт: дорогие шаги → дешёвые модели (FR-06)
                └─ не влезает ──► честно показан минимум (FR-06)   [что показывает «минимум» — не описано, BP-06.1]
        │
        ▼
Запуск («Запустить») ──► Выполняется в чате (BP-06, шаг 5; FR-08)
        │   live-статусы шагов, обновление ≥ 1 раз в 200 мс (FR-09);
        │   лимиты шага: вызов ≤ 300 с, действий ≤ 80 → стоп с сообщением, «да» ≤ 600 с (FR-14);
        │   закрытие окна — цепочка продолжает выполняться в фоне (FR-08)
        ├─ остановка пользователем ──► шаг помечен с понятной причиной; цепочка остановлена (FR-10, FR-13)
        ├─ цикл (3 одинаковых действия подряд) ──► шаг остановлен, причина «цикл» (FR-11, FR-13)
        ├─ сбой провайдера ──► замена исполнителя (фолбэк) ──► шаг повторён [порядок — допущение, BP-06.1]
        │        └─ замены нет ──► шаг помечен с причиной; цепочка остановлена [допущение]
        └─ все шаги выполнены ──► Итог в чате (результат BP-06; FR-08)
```

| Переход | Откуда → куда | Правило |
|---|---|---|
| Описание задачи | — → Подбор | Триггер BP-06; FR-01 |
| Подбор шагов и исполнителей | Подбор → Варианты предложены | BP-06, шаг 1; FR-01 |
| Показ вариантов | — → Варианты предложены (3 шт., ≤ 6 шагов) | BP-06, шаг 2; FR-02, FR-03 |
| Рекомендуемый бюджет | Варианты → Бюджет (из дешёвой сметы) | BP-06, шаг 3; FR-05 (допущение — 2.6) |
| Свой бюджет | Бюджет → пересчёт (понижение дорогих шагов; минимум) | BP-06, шаг 3; FR-05, FR-06 |
| Экономия | Подбор → шаги простые и самодостаточные; дорогие модели — при окупаемости | BP-06, шаг 4; FR-07 |
| Запуск | Варианты → Выполняется в чате | BP-06, шаг 5; FR-08 |
| Live-статусы | Выполняется → статусы шагов обновляются (≥ 1 раз в 200 мс) | BP-06, шаг 5; FR-09; действующие лимиты |
| Шаг выполнен | Выполняется → следующий шаг → Итог в чате | BP-06, шаг 5; FR-08; результат BP-06 |
| Остановка пользователем | Выполняется → шаг помечен; цепочка остановлена | BP-06, шаги 5–6; FR-10, FR-13 |
| Цикл | Выполняется → шаг остановлен, причина «цикл» | BP-06, шаги 5–6; FR-11, FR-13; действующие лимиты |
| Сбой провайдера | Выполняется → замена исполнителя → повтор шага [допущение] | BP-06, шаг 5; FR-12; краевые состояния; тема 4.3 |
| Замены нет | Сбой провайдера → шаг помечен; цепочка остановлена [допущение] | BP-06, шаг 6; FR-12, FR-13; BP-06.1 |
| Пометка прерванного шага | Прерывание → шаг помечен с причиной; не «зависает», не продолжается молча | BP-06, шаг 6; FR-13; краевые состояния |

## 2. Сущности, состояния и переходы

### 2.1 Схема (план) / цепочка

| Поле | Значение |
|---|---|
| Определение | Набор шагов с исполнителями и бюджетом, который запускается в чате (словарь терминов; BP-06, назначение) |
| Атрибуты | Описание задачи (FR-01); шаги (2.2), до 6; исполнители (2.4); бюджет (2.6); вариант (2.3) |
| Состояния | Предложена → (правка до запуска, FR-16) → Запущена → Выполняется → Выполнена (итог в чате); Остановлена (с понятной причиной; шаг помечен); выполнение продолжается в фоне при закрытии окна (FR-08) |
| Переходы | См. модель состояний (раздел 1) |
| Примечание | Общий лимит времени выполнения цепочки не описан (BP-06.1, «Область вне требований») |

### 2.2 Шаг схемы

| Поле | Значение |
|---|---|
| Определение | Элемент цепочки с назначенным исполнителем; выполняется вызовом ИИ (описание конструктора схем; BP-06, шаги 1, 5) |
| Атрибуты | Исполнитель (2.4); действия шага (до 80, при превышении — стоп с сообщением «Слишком много действий подряд — шаг остановлен»: FR-14; BP-04, шаг 5; тема 4.8); live-статус (FR-09); причина остановки (2.8) |
| Состояния | Ожидает → Выполняется → Выполнен; Остановлен (причина: пользователь / провайдер / цикл — 2.8) |
| Переходы | Запуск цепочки (FR-08); выполнение исполнителем (FR-08); остановка пользователем (FR-10); «цикл» (FR-11); сбой провайдера — замена исполнителя и повтор (FR-12, допущение); пометка при прерывании (FR-13) |
| Примечание | При трёх одинаковых действиях подряд шаг останавливается с причиной «цикл» (действующие лимиты; FR-11) |

### 2.3 Вариант

| Поле | Значение |
|---|---|
| Определение | Один из трёх предложенных способов выполнить задачу: «Быстро», «Оптимально», «Качественно» (описание конструктора схем; BP-06, шаг 2) |
| Атрибуты | Название из фиксированного набора из трёх; оценка времени, токенов и цены (FR-02); шаги (2.2); исполнители (2.4) |
| Правила | Длина цепочки варианта — до 6 шагов; «Качественно» — до 5 (FR-03; BR-03) |
| Состояния | Предложен → Выбран (запускается выбранный вариант — допущение) → Выполнен / Остановлен |
| Примечание | Чем варианты различаются по существу (кроме оценок и длины), источники не описывают (BP-06.1, «Область вне требований») |

### 2.4 Исполнитель

| Поле | Значение |
|---|---|
| Определение | ИИ из подключённых, назначенный на шаг цепочки (описание конструктора схем; BP-06, шаги 1, 5) |
| Атрибуты | ИИ — провайдер/модель (тема 4.3); назначение на шаг (FR-01); понижение до дешёвой модели при бюджете (FR-06); замена при сбое (FR-12) |
| Состояния | Назначен → Выполняет шаг → Выполнил; Понижен (дешёвая модель, FR-06); Заменён (фолбэк, FR-12) |
| Переходы | Подбор из подключённых ИИ (FR-01); понижение (FR-06); замена при сбое провайдера (FR-12; тема 4.3; краевые состояния); повтор шага после замены (допущение) |
| Правило окупаемости | Дорогая модель — только если окупается: не дороже удвоенной цены дешёвого шага (FR-07; решение владельца, 20.11.2026) |

### 2.5 Смета (оценка варианта)

| Поле | Значение |
|---|---|
| Определение | Оценка варианта: время, токены и цена (описание конструктора схем; BP-06, шаг 2) |
| Атрибуты | Время и токены — по таблице средних показателей моделей (решение владельца, 20.11.2026); цена (по ценам темы 4.3) |
| Правила цены | Точные цены — только для моделей OpenRouter (вход/выход за 1M токенов); у остальных — ориентир по имени модели, может расходиться (FR-04; BR-06; описание конструктора схем) |
| Примечание | Точные цены показываются в смете, бюджете и списке выбора моделей (описание конструктора схем; FR-04) |

### 2.6 Бюджет схемы

| Поле | Значение |
|---|---|
| Определение | Предел стоимости схемы: рекомендуемый или свой, в долларах (описание конструктора схем; BP-06, шаг 3) |
| Правила | Рекомендуемый рассчитывается из дешёвой сметы (FR-05); все варианты укладываются в бюджет; дорогие шаги понижаются до дешёвых моделей; не влезает — честно показан минимум (FR-06) |
| Допущение | Какая смета считается «дешёвой» — не описано; допущение: смета варианта с дешёвыми исполнителями (BP-06.1, «Область вне требований») |
| Пробел | Что именно показывает «минимум» — не описано (BP-06.1, «Область вне требований») |

### 2.7 Экономия

| Поле | Значение |
|---|---|
| Определение | Правило подбора, действующее всегда: задача дробится на простые самодостаточные шаги, дорогие модели — только если окупаются (описание конструктора схем; BP-06, шаг 4; решения владельца, 20.11.2026) |
| Правила | Применяется всегда, выключить нельзя (FR-07); шаги — простые и самодостаточные (FR-07); дорогая модель — не дороже удвоенной цены дешёвого шага (FR-07; решение владельца, 20.11.2026) |

### 2.8 Причина остановки шага

| Поле | Значение |
|---|---|
| Определение | Понятная человеку причина, с которой прерванный шаг помечается (BP-06, шаги 5–6; краевые состояния) |
| Словарь причин | «Остановка пользователем» (FR-10; описание конструктора схем); «Сбой провайдера» — упал / лимит / нет денег / ключ отклонён (тема 4.3; краевые состояния); «Цикл» — три одинаковых действия подряд (FR-11; действующие лимиты; системный код `loop`) |
| Правила | Шаг помечается с причиной при любом прерывании; цепочка не «зависает» и не продолжается молча (FR-13; BP-06, шаг 6) |

### 2.9 Планировщик

| Поле | Значение |
|---|---|
| Определение | Роль ИИ, который по описанию задачи подбирает шаги и исполнителей (описание конструктора схем; каталог BP-06, «Акторы») |
| Правила | Подбор — из подключённых ИИ (FR-01); экономия (FR-07); длина цепочки — в лимитах (FR-03) |
| Примечание | Какой именно ИИ выполняет роль планировщика — источники не уточняют (BP-06.1, «Область вне требований») |

## 3. Правила процесса и подбора исполнителей

- **Правило подбора.** По описанию задачи планировщик подбирает шаги и исполнителей из подключённых ИИ;
  схема — набор шагов с исполнителями и бюджетом (BP-06, шаг 1; BR-01; FR-01).
- **Правило трёх вариантов.** Предлагаются ровно три варианта — «Быстро», «Оптимально», «Качественно» —
  с оценкой времени, токенов и цены (BP-06, шаг 2; BR-02; FR-02).
- **Правило длины.** Цепочка — до 6 шагов; «Качественно» — до 5 (BP-06, шаг 2; BR-03; FR-03).
- **Правило экономии.** Экономия действует всегда: задача дробится на простые самодостаточные шаги;
  дорогая модель — только если окупается, то есть не дороже удвоенной цены дешёвого шага (BP-06, шаг 4;
  BR-05; FR-07).
- **Правило цен.** Точные цены — только для OpenRouter (вход/выход за 1M токенов; смета, бюджет, список
  выбора моделей); у остальных — ориентир по имени, может расходиться (BP-06, шаг 4; BR-06; FR-04;
  тема 4.3).
- **Правило бюджета.** Рекомендуемый (из дешёвой сметы) или свой, в долларах; все варианты укладываются
  в бюджет; дорогие шаги понижаются до дешёвых моделей; не влезает — честно показан минимум (BP-06,
  шаг 3; BR-04; FR-05, FR-06).
- **Правило запуска и live-статусов.** Цепочка запускается в чате; live-статусы шагов обновляются не
  реже чем каждые 200 мс; при закрытии окна цепочка продолжает выполняться в фоне (BP-06, шаг 5; BR-07;
  FR-08, FR-09; действующие лимиты).
- **Правило остановки.** Пользователь может остановить цепочку; причины остановки понятны (BP-06,
  шаг 5; BR-08; FR-10).
- **Правило цикла.** Три одинаковых действия подряд на шаге → остановка шага с причиной «цикл» (BP-06,
  шаг 5; BR-09; FR-11; действующие лимиты).
- **Правило фолбэка.** При сбое провайдера исполнитель подменяется (фолбэк); причина сообщается;
  провайдер помечается нерабочим и не попадает в списки моделей (BP-06, шаг 5; BR-10; FR-12; краевые
  состояния; тема 4.3).
- **Правило прерванного шага.** Прерванный шаг (остановка, падение провайдера, цикл) помечается с
  причиной; цепочка не «зависает» и не продолжается молча (BP-06, шаг 6; BR-11; FR-13; краевые
  состояния).
- **Правило лимитов.** На шаге схемы: вызов провайдера — не более 300 с; действий — до 80, при превышении
  шаг останавливается с сообщением; «да» на карточку разрешения — не более 600 с (BP-06, шаг 5; BR-13;
  FR-14; действующие лимиты; BP-04, шаг 5; темы 4.3, 4.8).
- **Правило скрытия секретов.** К облачным вызовам шагов применяются единые правила темы 4.1 (BR-14;
  FR-15; приватность и безопасность).
- **Правило языка.** Ответы исполнителей следуют языку общения, заданному в профиле (BR-15; тема 4.5).

## 5. Идентификаторы и коды

- Системные id генерирует система (общее правило каталога).
- Человекочитаемые коды, вводимые пользователем, в BP-06 отсутствуют: в источниках они не описаны
  («Область вне требований» каталога). Если такие коды появятся — проверка уникальности по общему
  правилу каталога.
- Системные коды причин остановки шага (`loop` — действующие лимиты) пользователем не вводятся и не
  редактируются.
