# BP-10.3. Сценарии использования: встречи, голос, OCR

Цепочка прослеживаемости: сценарий ввода → BP-10 (каталог процессов) → BP-10.1…4 (эта папка). Каждый UC
трассирован «UC → FR → BP-10 шаг»; FR альтернативных потоков включены в трассировку.

## 0. Сценарий ввода → BP-10

Отдельного пути «встреча» в описании клиентского пути нет; его разделы 2.6 и 3 упоминают голос и
локальную транскрипцию как факты кода (примечание — BP-10.1). Сценарий покрывается UC-01–UC-06.

## UC-01. Запись и расшифровка встречи с итогом

- **Актор:** Пользователь (ведёт запись), ИИ (готовит итог), Система.
- **Предусловие:** приложение запущено; пользователь хочет записать встречу (триггер BP-10).
- **Основной поток:**
  1. Пользователь начинает запись встречи. (FR-01)
  2. Система пишет микрофон и звук компьютера двумя дорожками — видно, кто говорит. (FR-01)
  3. Запись длится не более 5 часов; пользователь останавливает запись (FR-01; допущение: как
     останавливается запись — не описано, BP-10.1, раздел 7).
  4. Система распознаёт запись: локально (бесплатно) или облачным сервисом — по пресету. (FR-02, FR-04)
  5. Система вырезает тишину, фразы-ошибки и эхо. (FR-03)
  6. Итог — решения, задачи и их владельцы — готовит любой подключённый ИИ, включая локальный; итог
     появляется в чате, на языке общения из профиля. (FR-05, FR-08)
- **Альтернативные потоки:**
  - А1 (пресет): до начала пользователь выбирает пресет — весь путь записи и распознавания сразу (FR-04;
    UC-02).
  - А2 (облако): облачное распознавание — цена внешнего сервиса на дату, ориентир ≈ $0.36/час (FR-02;
    UC-05).
  - А3 (офлайн): локальное распознавание выполняется на компьютере — допущение: скрайб с локальным
    распознаванием работает офлайн (FR-02; BP-10.1, раздел 7).
  - А4 (нет ИИ): без подключённых ИИ итог невозможен — поведение не описано (FR-05; BP-10.1, раздел 7).
  - А5 (запись в память): решения и задачи из итога записываются в память по правилам BP-07 (FR-05;
    см. BP-07).
  - А6 (выход): пользователь передумал и не начинает запись — ничего не записывается.
- **Постусловие:** расшифровка и итог встречи (решения, задачи, владельцы) в чате (результат BP-10).
- **Трассировка:** UC-01 → FR-01, FR-02, FR-03, FR-04, FR-05, FR-08 → триггер BP-10; BP-10, шаги 1–4;
  тема 4.5.

## UC-02. Пресеты Private / Quality / Fast

- **Актор:** Пользователь (выбирает пресет), Система.
- **Предусловие:** пользователь готовится к записи встречи.
- **Основной поток:**
  1. Пользователь выбирает один из трёх пресетов: Private, Quality или Fast. (FR-04)
  2. Пресет задаёт весь путь записи и распознавания сразу: Private — только локальные модели; Quality —
     облачное распознавание при наличии ключа, иначе локальное (пресет по умолчанию); Fast — короткие
     записи локально, длинные — в облако (FR-04; допущение: пресет применяется к следующей встрече —
     порядок применения не описан, BP-10.1, раздел 7).
  3. Пользователь начинает запись; запись и распознавание идут по выбранному пресету (FR-01, FR-02;
     UC-01).
- **Альтернативные потоки:**
  - А1 (отказ): пользователь не выбирает пресет — действует пресет по умолчанию Quality (FR-04).
  - А2 (повтор): для следующей встречи пресет выбирается заново (допущение, FR-04).
  - А3 (смена): смена пресета во время записи не описана (FR-04; BP-10.1, раздел 7).
- **Постусловие:** путь записи и распознавания задан пресетом.
- **Трассировка:** UC-02 → FR-01, FR-02, FR-04 → BP-10, шаги 1–3.

## UC-03. Итог встречи любым ИИ (включая локальный)

- **Актор:** ИИ (готовит итог), Пользователь (читает итог), Система.
- **Предусловие:** запись распознана и очищена (UC-01, шаги 1–5); подключён хотя бы один ИИ.
- **Основной поток:**
  1. Система готовит итог — решения, задачи и их владельцев — выбранным ИИ (FR-05; допущение: как
     выбирается ИИ для итога — не описано, BP-10.1, раздел 7).
  2. Итог следует языку общения, заданному в профиле. (FR-08)
  3. Итог появляется в чате. (FR-05; результат BP-10)
- **Альтернативные потоки:**
  - А1 (сбой): провайдер упал / лимит / нет денег / ключ отклонён → сообщение с причиной, провайдер
    нерабочий — по правилам BP-02, темы 4.3 (FR-05).
  - А2 (офлайн): итог готовит локальная модель («включая локальный» — требования, раздел 6); облачные
    провайдеры недоступны (FR-05; BP-02, шаг 8).
  - А3 (нет ИИ): без подключённых ИИ итог невозможен — поведение не описано (FR-05; BP-10.1, раздел 7).
  - А4 (блокировка памяти): запросы, которым нужна память, отклоняются — BP-15 (краевые состояния
    требований); запись решений и задач — BP-07.
- **Постусловие:** итог в чате; решения, задачи и их владельцы названы.
- **Трассировка:** UC-03 → FR-05, FR-08 → BP-10, шаг 4; результат BP-10; тема 4.5.

## UC-04. Голосовая команда

- **Актор:** Пользователь (произносит команду), Система (распознаёт и отправляет).
- **Предусловие:** пользователь хочет отправить сообщение голосом (триггер BP-10).
- **Основной поток:**
  1. Пользователь произносит голосовую команду.
  2. Система распознаёт речь на компьютере. (FR-06)
  3. Система отправляет распознанный текст в чат сообщением. (FR-06)
  4. Дальнейшая обработка сообщения — по правилам BP-02.
- **Альтернативные потоки:**
  - А1 (нет ИИ): сообщение отправлено в чат, но запрос не уходит — BP-02, шаг 7 (FR-06).
  - А2 (офлайн): распознавание выполняется на компьютере — допущение: голосовая команда работает офлайн
    (FR-06; BP-10.1, раздел 7).
  - А3 (повтор): команда произносится заново — распознавание и отправка повторяются (FR-06).
  - А4 (платформа): голос доступен там, где есть локальные движки (FR-07; UC-06).
- **Постусловие:** голосовое сообщение отправлено в чат (результат BP-10).
- **Трассировка:** UC-04 → FR-06, FR-07 → триггер BP-10; BP-10, шаг 5; тема 4.7; BP-02.

## UC-05. Облачное распознавание (цена на дату)

- **Актор:** Пользователь (выбирает пресет), Система.
- **Предусловие:** запись есть; пресет предполагает облачное распознавание (FR-02, FR-04).
- **Основной поток:**
  1. Облачное распознавание выбирается пресетом: Quality — при наличии ключа, Fast — для длинных записей
     (FR-02, FR-04).
  2. Система отправляет запись в облачный сервис и получает расшифровку; цена внешнего сервиса на дату,
     ориентир ≈ $0.36/час. (FR-02)
  3. Тишина, фразы-ошибки и эхо вырезаются (FR-03); далее — итог (UC-01, UC-03).
- **Альтернативные потоки:**
  - А1 (локально): пресет Private (или Quality без ключа) распознаёт локально — бесплатно (FR-02, FR-04).
  - А2 (сбой): облачный сервис недоступен — поведение не описано (FR-02; BP-10.1, раздел 7).
  - А3 (лимит): лимит вызова 300 с (тема 4.3) к облачному распознаванию не применяется (FR-02).
  - А4 (приватность): применяются ли правила темы 4.1 к отправке записи — не описано (FR-02; BP-10.1,
    раздел 7).
- **Постусловие:** расшифровка получена; цена учтена как ориентир на дату.
- **Трассировка:** UC-05 → FR-02, FR-03, FR-04 → BP-10, шаги 2–3; тема 4.3 (ссылка).

## UC-06. Платформы: голос и распознавание там, где есть локальные движки

- **Актор:** Пользователь, Система.
- **Предусловие:** пользователь работает на платформе с локальными движками (или без них).
- **Основной поток:**
  1. Система предоставляет голос и распознавание речи там, где есть локальные движки. (FR-07)
  2. Матрица платформ уточняется (FR-07; BP-10.1, раздел 7).
- **Альтернативные потоки:**
  - А1 (нет движков): на платформе без локальных движков голос и распознавание недоступны — поведение
    интерфейса не описано (FR-07; BP-10.1, раздел 7).
  - А2 (OCR): распознавание сканов и картинок — BP-11; к BP-10 только ссылка (FR-07; BP-11).
- **Постусловие:** доступность голоса и распознавания соответствует матрице после её уточнения.
- **Трассировка:** UC-06 → FR-07 → тема 4.7; требования, раздел 8.
