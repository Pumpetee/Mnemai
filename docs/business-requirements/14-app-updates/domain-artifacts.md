# BP-14.4. Артефакты предметной области: обновления приложения

Процесс: BP-14 каталога бизнес-процессов; основание — человеко-требования (разделы «Термины и роли», «Desktop и жизненный цикл», «Ограничения», «Решения и открытые вопросы»). Сущности, их состояния и переходы, правила установки и словарь терминов процесса. Жизненный цикл окна не дублируется — ссылка на тему 4.7; выпуск релизов — вне процесса (тема 4.8).

## 1. Модель состояний обновления

```
Триггер: проверка при каждом запуске приложения / нажатие кнопки Update (триггер BP-14)
        │
        ▼
Проверка релизов: при каждом запуске и по кнопке Update, из GitHub-релизов по стабильному каналу (FR-01, FR-09)
  ├─ новая версия не найдена → работа продолжается, кнопки нет (FR-02)
  └─ новая версия найдена → кнопка Update (FR-02)
        │
        ▼
Установка по нажатию кнопки (FR-03)
  ├─ Windows → при выходе из приложения (FR-04; выход — тема 4.7, см. BP-12)
  ├─ Linux → замена установочного файла + перезапуск (FR-05)
  └─ macOS → открытие образа установки + инструкция в окне (FR-06)
        │
        ▼
Проверка целостности: метаданные релиза, фолбэк — отдельный файл суммы (FR-07)
  ├─ сумма совпала → обновление применено (результат BP-14)
  └─ сумма не совпала / сбой установки / сбой проверки → не применено, цикл пропущен (FR-08)
```

(Решения владельца: проверка при каждом запуске и по кнопке Update; канал стабильный; источник —
GitHub-релизы; бета-каналов нет; откат — переустановка; macOS — инструкция в окне; сбой проверки —
пропуск цикла.)

| Переход | Откуда → куда | Правило |
|---|---|---|
| Проверка релизов | — → Проверено | При каждом запуске и по кнопке Update, тихо — BP-14, шаг 1; FR-01, FR-09 |
| Новая версия найдена | Проверено → Предложено | Кнопка Update — BP-14, шаг 1; FR-02 |
| Нажатие кнопки | Предложено → Установка | Триггер BP-14; FR-03 |
| Установка на Windows | Установка → При выходе | BP-14, шаг 2; FR-04; выход — тема 4.7 |
| Установка на Linux | Установка → Замена файла + перезапуск | BP-14, шаг 2; FR-05 |
| Установка на macOS | Установка → Образ открыт + инструкция в окне | BP-14, шаг 2; FR-06 |
| Проверка целостности | Установка → Проверено | Метаданные релиза; фолбэк — отдельный файл суммы — BP-14, шаг 3; FR-07 |
| Применение | Проверено (совпало) → Применено | Результат BP-14 |
| Отказ | Проверено (не совпало) / сбой установки / сбой проверки → Не применено, цикл пропущен | BP-14, шаг 3; FR-08 |

## 2. Сущности, состояния и переходы

### 2.1 Релиз (новая версия)

| Поле | Значение |
|---|---|
| Определение | Новая версия приложения, обнаруживаемая тихой проверкой (раздел «Desktop и жизненный цикл») |
| Атрибуты | Версия; метаданные релиза с контрольной суммой; запасной файл контрольной суммы (раздел «Desktop и жизненный цикл») |
| Состояния | Не обнаружен → Обнаружен → Предложен (кнопка Update) → Применён / Не применён |
| Переходы | Тихая проверка (FR-01); показ кнопки (FR-02); установка (FR-03–FR-06); применение или отказ (FR-07, FR-08) |
| Примечание | Источник релизов — GitHub-релизы; канал проверки стабильный; бета-каналы не предусмотрены (решение владельца) |

### 2.2 Контрольная сумма

| Поле | Значение |
|---|---|
| Определение | Значение для проверки целостности обновления; основной источник — метаданные релиза, запасной вариант — отдельный файл (раздел «Desktop и жизненный цикл») |
| Атрибуты | Значение суммы; источник (метаданные релиза / отдельный файл) |
| Состояния | Основной источник доступен → используется запасной файл (при недоступности основного) |
| Переходы | Проверка перед применением (FR-07); несовпадение → отказ (FR-08) |

### 2.3 Установка по ОС

| Поле | Значение |
|---|---|
| Windows | Установка при выходе из приложения (FR-04; сам выход — тема 4.7, см. BP-12) |
| Linux | Замена установочного файла и перезапуск приложения (FR-05) |
| macOS | Открытие образа установки и инструкция по установке в окне (FR-06) |

### 2.4 Причины отказа

| Поле | Значение |
|---|---|
| Несовпадение контрольной суммы | Обновление не применяется (BP-14, шаг 3; FR-08) |
| Сбой установки | Обновление не применяется (BP-14, шаг 3; FR-08) |
| Сбой самой проверки релизов | Цикл пропускается без установки (BP-14, шаг 3; FR-08; решение владельца) |
| Примечание | Перечень конкретных сбоев в источниках не детализирован; откат версии — переустановка (решение владельца) |

## 3. Правила процесса

- Проверка релизов при каждом запуске приложения и по кнопке Update; канал стабильный; источник —
  GitHub-релизы; бета-каналы не предусмотрены (BP-14, шаг 1; FR-01, FR-02, FR-09; решение владельца).
- Установка по ОС: Windows — при выходе; Linux — замена установочного файла и перезапуск; macOS —
  открытие образа установки и инструкция по установке в окне (BP-14, шаг 2; FR-04, FR-05, FR-06).
- Целостность — по контрольной сумме: метаданные релиза, запасной вариант — отдельный файл суммы
  (BP-14, шаг 3; FR-07).
- Несовпадение суммы, сбой установки или сбой самой проверки → обновление не применяется; при сбое
  проверки цикл пропускается без установки (BP-14, шаг 3; FR-08).
- Выпуск релизов — вне процесса: партиями, только по прямой просьбе владельца (тема 4.8; раздел «Ограничения»; BR-05).
- Откат на прежнюю версию — переустановка (решение владельца).
- Человекочитаемые коды в процессе не используются: в источниках не описаны (раздел 6 каталога);
  системные id генерирует система (раздел 1 каталога).

## 4. Словарь терминов процесса

Термины согласованы с раздел «Термины и роли» Этапа 1; определения раздел «Термины и роли» приводятся дословно, новые термины процесса
выводятся из раздел «Desktop и жизненный цикл».

| Термин | Определение | Источник |
|---|---|---|
| Пользователь (владелец) | Человек, чья это память и компьютер. В массовом продукте — любой человек | раздел «Термины и роли» (дословно) |
| Тихая проверка | Фоновая проверка наличия новых релизов при каждом запуске приложения и по кнопке Update | раздел «Desktop и жизненный цикл»; решение владельца |
| Стабильный канал | Канал проверки релизов — стабильный; бета-каналы не предусмотрены | Решение владельца |
| GitHub-релизы | Источник релизов для проверки | Решение владельца |
| Откат версии | Возврат на прежнюю версию — переустановкой | Решение владельца |
| Инструкция по установке | Показывается в окне после открытия образа на macOS | Решение владельца |
| Кнопка Update | Кнопка, показываемая при обнаружении новой версии; нажатие запускает установку | раздел «Desktop и жизненный цикл» |
| Релиз | Новая версия приложения; выпуск — вне процесса (тема 4.8) | раздел «Desktop и жизненный цикл», раздел «Ограничения» |
| Метаданные релиза | Основной источник контрольной суммы для проверки целостности | раздел «Desktop и жизненный цикл» |
| Контрольная сумма | Значение для проверки целостности обновления; запасной вариант — отдельный файл | раздел «Desktop и жизненный цикл» |
| Установочный файл | Файл, заменяемый при обновлении на Linux | раздел «Desktop и жизненный цикл» |
| Образ установки | Образ, открываемый при обновлении на macOS | раздел «Desktop и жизненный цикл» |
| Перезапуск | Перезапуск приложения после замены файла на Linux | раздел «Desktop и жизненный цикл» |
| Не применено | Итог при несовпадении контрольной суммы или сбое установки: приложение остаётся на текущей версии | раздел «Desktop и жизненный цикл» |

## 5. Идентификаторы и коды

- Системные id генерирует система (правило каталога, раздел 1).
- Человекочитаемые коды, вводимые пользователем, в BP-14 отсутствуют: в источниках они не описаны
  (раздел 6 каталога). Если такие коды появятся — проверка уникальности по общему правилу каталога
  (раздел 1).
