# BP-03.3. Сценарии использования: консорциум

## 0. Сценарий ввода → BP-03

В описании пути клиента сценария консорциума нет: упомянут только модуль «дискуссия 2–4 ИИ» без
сценария. Сценарии ниже выведены из каталога BP-03 и требований чата; пробелы источников отмечены по BP-03.1,
«Область вне требований». Покрытие: UC-01–UC-05.

## UC-01. Запуск консорциума и дискуссия до итога

- **Актор:** Пользователь (участники — ИИ; система — исполнитель).
- **Предусловие:** подключены хотя бы два ИИ (иначе — А3); открыт чат.
- **Основной поток:**
  1. Пользователь запускает консорциум в чате; тема дискуссии — его первое сообщение. (FR-01)
  2. Пользователь выбирает формат (FR-02), участников — от 2 до 4 ИИ (FR-03), число раундов (FR-04),
     суммаризатора (FR-05) и лимит длины реплик (FR-06).
  3. Система ведёт дискуссию по очереди по раундам с ролями — ведущий, участники, суммаризатор (решение
     владельца); каждый участник получает память только по своим правам; реплики — на языке общения.
     (FR-07, FR-08, FR-14)
  4. По завершении заданного числа раундов выбранный суммаризатор подводит итог; итог — в чате. (FR-11)
- **Альтернативные потоки:**
  - А1 (действие): участник просит действие → исполнение по правилам BP-04, результат возвращается
    участнику (FR-12; см. BP-04).
  - А2 (спор): пользователь запускает спор под ответом — UC-03. (FR-10)
  - А3 (участников меньше двух): поведение консорциума при менее чем двух подключённых ИИ не описано
    (BP-03.1, «Область вне требований»); для чата — BP-02, шаг 7 (краевые состояния).
  - А4 (сбой): сбой провайдера участника — UC-05. (FR-13)
  - А5 (отказ): пользователь отменяет запуск до начала дискуссии → дискуссия не начинается.
  - А6 (выход): пользователь закрывает окно приложения; восстановление окна и черновика — тема 4.7
    (см. BP-01); поведение дискуссии при выходе не описано.
- **Постусловие:** итог дискуссии в чате; дискуссия велась заданное число раундов (результат BP-03).
- **Трассировка:** UC-01 → FR-01, FR-02, FR-03, FR-04, FR-05, FR-06, FR-07, FR-08, FR-11, FR-12, FR-13,
  FR-14 → BP-03, шаги 1, 2, 5; результат BP-03; тема 4.5 (FR-14).

## UC-02. Дискуссия в выбранном формате (совет / дебаты / мозговой штурм / ред-тим / roast)

- **Актор:** Пользователь.
- **Предусловие:** подключены хотя бы два ИИ; консорциум не запущен (настройка — UC-01, шаги 1–2).
- **Основной поток:**
  1. Пользователь выбирает формат: совет, дебаты, мозговой штурм, ред-тим или roast. (FR-02)
  2. Система ведёт дискуссию в выбранном формате по общему ходу UC-01. (FR-07)
  3. Итог — по UC-01, шаг 4. (FR-11)
- **Альтернативные потоки:**
  - А1 (отказ): до запуска пользователь меняет формат на другой из набора (FR-02).
  - А2 (повтор): повторный запуск — с тем же или другим форматом (FR-02).
  - А3 (остановка): «Стоп» — UC-04 (FR-09); спор под ответом — UC-03 (FR-10).
- **Постусловие:** дискуссия проведена в выбранном формате; итог в чате.
- **Примечание:** чем форматы различаются, источники не описывают; сценарий фиксирует только выбор формата
  и общий ход дискуссии (BP-03.1, «Область вне требований»). В описание архитектуры («Консорциум») четыре
  формата без roast — расхождение отмечено в BP-03.1.
- **Трассировка:** UC-02 → FR-02, FR-07, FR-11 → BP-03, шаги 1, 2; результат BP-03.

## UC-03. Спор под ответом

- **Актор:** Пользователь; участники (автор ответа и остальные).
- **Предусловие:** в дискуссии выведен ответ участника (реплика).
- **Основной поток:**
  1. Пользователь запускает «спор» под любым ответом. (FR-10)
  2. Автор ответа защищает его; остальные участники ищут слабости. (FR-10)
  3. Реплики спора идут в чате по правилам дискуссии: по очереди, память по правам, язык общения —
     допущение, в источниках не уточнено (BP-03.1, «Область вне требований»). (FR-07, FR-08, FR-14)
- **Альтернативные потоки:**
  - А1 (отказ): пользователь не запускает или отменяет спор → дискуссия продолжается обычным ходом.
  - А2 (повтор): спор запускается под другим ответом — «под любым ответом» (FR-10).
  - А3 (остановка): «Стоп» во время спора — UC-04 (FR-09).
  - А4 (сбой): сбой провайдера участника спора — UC-05 (FR-13).
- **Постусловие:** спор проведён: автор защитил ответ, остальные искали слабости; сказанное сохранено в
  чате; чем спор завершается (итог спора) — не описано (BP-03.1, «Область вне требований»).
- **Трассировка:** UC-03 → FR-07, FR-08, FR-09, FR-10, FR-13, FR-14 → BP-03, шаги 2, 3, 4, 5;
  тема 4.5 (FR-14).

## UC-04. «Стоп» — пауза на полуслове

- **Актор:** Пользователь.
- **Предусловие:** идёт реплика участника (генерация).
- **Основной поток:**
  1. Пользователь жмёт «Стоп».
  2. Система ставит дискуссию на паузу и останавливает текущего ИИ. (FR-09)
  3. Сказанное до остановки сохраняется в чате. (FR-09)
- **Альтернативные потоки:**
  - А1 (повтор): «Стоп», когда реплика уже остановлена, — без эффекта.
  - А2 (продолжение): пользователь продолжает дискуссию — она возобновляется с паузы (решение владельца).
    (FR-09)
  - А3 (выход): закрытие окна во время дискуссии — тема 4.7 (см. BP-01); поведение дискуссии не описано.
- **Постусловие:** дискуссия на паузе: текущая реплика остановлена, сказанное сохранено; дискуссию можно
  продолжить (результат BP-03; решение владельца).
- **Трассировка:** UC-04 → FR-09 → BP-03, шаг 3; результат BP-03; решение владельца.

## UC-05. Сбой провайдера участника

- **Актор:** Пользователь.
- **Предусловие:** во время реплики провайдер участника упал / лимит / нет денег / ключ отклонён — или вызов
  идёт дольше 300 с.
- **Основной поток:**
  1. Система показывает сообщение с причиной сбоя — по единым правилам темы 4.3. (FR-13)
  2. Система помечает провайдера нерабочим; в списки моделей он не попадает (списки — BP-12).
     (FR-13; тема 4.3)
- **Альтернативные потоки:**
  - А1 (таймаут): вызов участника длится более 300 с → завершается по лимиту (FR-13; лимиты).
  - А2 (повтор): дальнейший ход дискуссии при сбое участника (повтор реплики, замена участника, остановка)
    не описан — пробел (BP-03.1, «Область вне требований»); замена исполнителя в цепочке схемы — BP-06, к
    консорциуму не привязана.
- **Постусловие:** сбой зафиксирован с причиной; провайдер нерабочий; ход дискуссии — пробел (BP-03.1,
  «Область вне требований»).
- **Трассировка:** UC-05 → FR-13 → BP-03, шаг 5; тема 4.3.
