# BP-04.3. Сценарии использования: действия и разрешения

Цепочка прослеживаемости: сценарий ввода → BP-04 (каталог процессов) → BP-04.1…4 (эта папка). Каждый UC
трассирован «UC → FR → BP-04 шаг».

## 0. Сценарий ввода → BP-04

Путь клиента из описания клиентского пути (раздел 2.2): «…→ карточка действия (если модель попросила
инструмент) → „Да / Нет / Да для этого разговора“ → ответ…»; раздел 2.3: «модель просит действие → карточка
→ клиент жмёт „да“ → инструмент выполняется → результат модели». Формулировка карточки совпадает с
требованиями (раздел 2) — расхождений нет (BP-04.1). Сценарий покрывается UC-01–UC-08.

## UC-01. Действие без вопроса (тумблер выключен)

- **Актор:** ИИ (запрашивает), Пользователь (наблюдает и отменяет), Система (исполняет).
- **Предусловие:** тумблер разрешений выключен (настройка — BP-12); модель в чате просит действие из
  каталога (FR-01), не являющееся вызовом внешнего MCP-инструмента или проверочным прогоном.
- **Основной поток:**
  1. Модель запрашивает действие. (FR-01)
  2. Система проверяет тумблер: выключен — вопрос не задаётся. (FR-02)
  3. Система проверяет запрещённые пути: если действие их затрагивает — А1. (FR-12)
  4. Система исполняет действие и возвращает результат модели; ответ продолжается. (FR-07)
  5. Записи действия направляются в журнал и отменяемы через «Историю». (FR-08)
- **Альтернативные потоки:**
  - А1 (отказ): действие затрагивает запрещённый путь → не выполняется ни при каком разрешении; отказ
    возвращён модели (FR-12; UC-06).
  - А2 (отмена): пользователь отменяет запись через «Историю» (FR-08; см. BP-07).
  - А3 (лимит): «до 12 действий на ответ» в чате задано инструкцией модели (FR-09; UC-08).
  - А4 (повтор): третье одинаковое действие подряд → остановка с причиной «цикл» (FR-10; UC-05).
  - А5 (sudo): действие требует прав администратора → UC-04 (FR-06).
- **Постусловие:** действие выполнено без вопроса; результат у модели; записи в журнале и отменяемы.
- **Трассировка:** UC-01 → FR-01, FR-02, FR-06, FR-07, FR-08, FR-09, FR-10, FR-12 → BP-04, границы;
  шаги 1, 3–6.

## UC-02. Карточка «Да / Нет / Да для этого разговора» (тумблер включён)

- **Актор:** Пользователь (решает), ИИ (запрашивает), Система.
- **Предусловие:** тумблер разрешений включён (BP-12); модель просит действие, не требующее обязательного
  вопроса (иначе — UC-03).
- **Основной поток:**
  1. Модель запрашивает действие. (FR-01)
  2. Система показывает карточку с кнопками «Да / Нет / Да для этого разговора». (FR-03)
  3а. «Да» → система выполняет действие один раз и возвращает результат модели. (FR-03, FR-07)
  3б. «Нет» → действие не выполняется; отказ возвращён модели. (FR-03, FR-07)
  3в. «Да для этого разговора» → действие заносится в список разрешённых действий этого разговора и
  выполняется (допущение: «да для этого разговора» включает «да» — источники прямо не описывают
  выполнение текущего действия); далее в этом чате выполняется без вопроса. (FR-04)
- **Альтернативные потоки:**
  - А1 (таймаут): «да» не получено за 600 с → действие отменяется, генерация останавливается (FR-11).
  - А2 (обязательный вопрос): действие — вызов внешнего MCP-инструмента или проверочный прогон → правила
    UC-03 (FR-05).
  - А3 (другой чат): «Да для этого разговора» действует только в пределах этого чата; в другом чате то же
    действие спрашивается заново (FR-04).
  - А4 (sudo): действие требует прав администратора → UC-04 (FR-06).
  - А5 (запрещённый путь): → UC-06 (FR-12).
  - А6 (повтор): третье одинаковое действие подряд → «цикл» (FR-10; UC-05).
- **Постусловие:** действие выполнено (один раз или «для этого разговора») либо отклонено; решение
  зафиксировано; при «Да для этого разговора» список разговора пополнен.
- **Трассировка:** UC-02 → FR-01, FR-03, FR-04, FR-06, FR-07, FR-10, FR-11, FR-12 → BP-04, границы;
  шаги 1–6.

## UC-03. Обязательный вопрос: вызов внешнего MCP-инструмента или проверочный прогон

- **Актор:** Пользователь (подтверждает), ИИ (запрашивает), Система.
- **Предусловие:** модель просит вызов внешнего MCP-инструмента или проверочный прогон; тумблер — в любом
  положении.
- **Основной поток:**
  1. Модель запрашивает вызов внешнего MCP-инструмента (или проверочный прогон).
  2. Система спрашивает отдельное «да» — всегда, независимо от тумблера. (FR-05)
  3. Пользователь жмёт «да»; система выполняет вызов (прогон — по FR-13; UC-07). (FR-07, FR-13)
  4. Результат возвращён модели. (FR-07)
- **Альтернативные потоки:**
  - А1 (отказ): «нет» → вызов не выполняется; отказ возвращён модели (FR-05, FR-07).
  - А2 (повтор): каждый следующий вызов или прогон — отдельное «да»; «Да для этого разговора» к ним не
    применяется, список разговора ими не пополняется (FR-05, FR-04).
- **Постусловие:** вызов выполнен с отдельным подтверждением — или отклонён; список разрешённых действий
  разговора не изменён.
- **Трассировка:** UC-03 → FR-04, FR-05, FR-07, FR-13 → BP-04, шаги 2, 4, 7.

## UC-04. Действие с правами администратора (sudo)

- **Актор:** Пользователь (вводит пароль), ИИ (запрашивает), Система.
- **Предусловие:** модель в чате просит действие, требующее прав администратора.
- **Основной поток:**
  1. Модель запрашивает действие; по правилам тумблера — сразу или с карточкой (FR-02, FR-03).
  2. Система спрашивает пароль администратора. (FR-06)
  3. Пользователь вводит пароль; система выполняет действие. (FR-06, FR-07)
  4. Пароль не сохраняется ни в файле чата, ни в запросах модели. (FR-06)
- **Альтернативные потоки:**
  - А1 (отказ): пароль не введён → действие не выполняется; отказ возвращён модели (FR-07).
  - А2 (повтор): пароль спрашивается один раз — повторные действия с правами администратора идут без
    повторного ввода (FR-06).
  - А3 (запрещённый путь): действие затрагивает запрещённые пути → UC-06 (FR-12): запрет действует ни при
    каком разрешении, включая sudo.
- **Постусловие:** действие выполнено; пароль нигде не сохранён.
- **Трассировка:** UC-04 → FR-02, FR-03, FR-06, FR-07, FR-12 → BP-04, шаги 1, 3, 4, 6.

## UC-05. Три одинаковых действия подряд (защита от цикла)

- **Актор:** ИИ (запрашивает), Система (останавливает), Пользователь (наблюдает).
- **Предусловие:** модель в ходе ответа (или шага схемы) повторила одно и то же действие (с теми же
  аргументами) дважды подряд и запрашивает его третий раз.
- **Основной поток:**
  1. Модель запрашивает то же действие с теми же аргументами третий раз подряд.
  2. Система не выполняет его и фиксирует причину «цикл». (FR-10)
  3. На шаге схемы останавливается шаг с этой причиной; цепочка не «зависает» и не продолжается молча
     (BP-06; краевые состояния требований).
- **Альтернативные потоки:**
  - А1 (выход): пользователь останавливает генерацию — stop (см. BP-02).
  - А2 (другие аргументы): запрошено действие с другими аргументами — счётчик повторов не срабатывает
    (FR-10: одинаковость — с учётом аргументов).
- **Постусловие:** повтор остановлен с причиной «цикл»; в чате что именно останавливается — не описано
  (BP-04.1, раздел 7).
- **Трассировка:** UC-05 → FR-10 → BP-04, шаг 5; BP-06; краевые состояния требований.

## UC-06. Запрещённый путь (deny-list)

- **Актор:** ИИ (запрашивает), Система (отклоняет), Пользователь (не может разрешить).
- **Предусловие:** модель просит файловое действие или команду, затрагивающие запрещённые пути секретов.
- **Основной поток:**
  1. Модель запрашивает действие с запрещённым путём.
  2. Система отклоняет: файловые инструменты не читают и не пишут эти пути, команды с этими путями
     отклоняются — ни при каком разрешении. (FR-12)
  3. Отказ возвращён модели. (FR-07)
- **Альтернативные потоки:**
  - А1 (подтверждение): даже «да» пользователя на карточке не открывает доступ — запрет действует при
    любом положении тумблера (FR-12).
  - А2 (расширение): расширение доступа — только с явного разрешения пользователя и после ревью; deny-list
    остаётся чёрным списком защиты секретов, а не песочницей (требования, раздел 9; тема 4.1).
- **Постусловие:** действие не выполнено; секреты не затронуты.
- **Трассировка:** UC-06 → FR-12 → BP-04, шаг 6; тема 4.1; требования, разделы 3 и 9.

## UC-07. Полный проверочный прогон инструментов (mcp_smoke_all)

- **Актор:** Пользователь (подтверждает), ИИ (запрашивает), Система (исполняет прогон).
- **Предусловие:** модель запросила полный проверочный прогон всех инструментов; пользователь дал «да»
  (прогон требует «да» всегда — FR-05).
- **Основной поток:**
  1. Система выполняет полный прогон всех инструментов в безопасной приватной временной папке. (FR-13)
  2. Тестовые записи помечаются и удаляются; буфер обмена восстанавливается; инструменты рабочего стола
     пропускаются. (FR-13)
  3. Результат прогона возвращён модели. (FR-07)
- **Альтернативные потоки:**
  - А1 (отказ): «нет» → прогон не выполняется (FR-05).
  - А2 (повтор): каждый следующий прогон — отдельное «да» (FR-05).
- **Постусловие:** прогон завершён; тестовые записи удалены; буфер обмена восстановлен; инструменты
  рабочего стола не запускались.
- **Трассировка:** UC-07 → FR-05, FR-13 → BP-04, шаги 2, 7.

## UC-08. Лимиты действий на ответ и на шаге схемы

- **Актор:** ИИ (запрашивает), Система (следит за лимитами), Пользователь (отвечает на карточки).
- **Предусловие:** идёт ответ в чате (или шаг схемы), модель запрашивает действия.
- **Основной поток:**
  1. Модель запрашивает действия одно за другим; в чате «до 12 действий на ответ» задано инструкцией
     модели, на шаге схемы — жёсткий стоп при более чем 80 действиях с сообщением. (FR-09)
  2. На карточках система ждёт «да» не более 600 с; по истечении действие отменяется и генерация
     останавливается. (FR-11)
  3. Три одинаковых действия подряд — остановка с причиной «цикл». (FR-10)
- **Альтернативные потоки:**
  - А1 (чат): «до 12 действий на ответ» задано инструкцией модели — жёсткого счётчика нет (FR-09).
  - А2 (схема): на шаге схемы — жёсткий стоп при более чем 80 действиях с сообщением (FR-09); остановка
    шага по «циклу» — BP-06 (краевые состояния требований).
- **Постусловие:** действия выполнены в пределах лимитов; лимиты соблюдены.
- **Трассировка:** UC-08 → FR-09, FR-10, FR-11 → BP-04, шаг 5; тема 4.8; требования, раздел 10.
