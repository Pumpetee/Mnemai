# BP-07.2. Функциональные требования: память: чтение, правка, история, undo

## 1. Папка памяти и раскладка (BP-07, шаг 1)

### FR-01 — Память как папка Markdown
Система должна хранить память как папку Markdown по фиксированной раскладке и позволять читать и
править её без приложения, пока шифрование выключено (поведение при включённом шифровании — см. BP-15).
**Приёмка:** память доступна как обычная папка Markdown без приложения; после включения шифрования —
по правилам BP-15.
(BP-07, шаг 1; раздел 1)

### FR-02 — Раскладка по скоупам
Система должна вести память в фиксированной раскладке: «00 Inbox», «10 Now», «20 Projects»,
«30 People», «60 Events», «70 Memory» (профиль, правила, мысли, карточки, факт-архив), «90 System»
(журнал, рецепты), «95 Saves», служебная папка «.mnema».
**Приёмка:** созданная память содержит перечисленные разделы; назначение разделов соответствует разделу 1.
(BP-07, шаг 1; раздел 1)

## 2. Факты, статусы и факт-архив (BP-07, шаг 2)

### FR-03 — Факт одной строкой с датой
Система должна записывать факт одной строкой с датой — в Inbox, карточке или журнале проекта.
**Приёмка:** записанный факт — одна строка с датой в одном из трёх мест (Inbox, карточка, журнал
проекта).
(BP-07, шаг 2; раздел 1)

### FR-04 — Статус с заменой и архивом
Система должна вести статус вида «(статус ДД.ММ.ГГГГ)»: новая версия заменяет старую, старая уходит в
факт-архив, изменение попадает в ленту событий.
**Приёмка:** после нового статуса в записи остаётся последняя версия; старая версия доступна в
факт-архиве; изменение видно в ленте событий.
(BP-07, шаг 2; раздел 1)

### FR-05 — Факт-архив не отправляется модели
Система должна никогда не отправлять содержимое факт-архива модели.
**Приёмка:** содержимое факт-архива не попадает в запросы моделей ни при каком скоупе (тема 4.1 каталога).
(BP-07, шаг 2; раздел 1; тема 4.1)

## 3. Индекс (BP-07, шаг 3)

### FR-06 — Автоматический индекс
Система должна собирать индекс автоматически из заметок и пересобирать его при правке источников;
руками индекс не пишется.
**Приёмка:** индекс соответствует заметкам и обновляется после правки источников; ручная правка
индекса не предусмотрена.
(BP-07, шаг 3; раздел 1)

## 4. Портрет и карта памяти (BP-07, шаги 4–5)

### FR-07 — Портрет вверху профиля
Система должна вести портрет из 2–3 предложений вверху профиля — первое, что читает каждый ИИ;
портрет правится руками, пополняется обучением (см. BP-08).
**Приёмка:** портрет из 2–3 предложений размещён вверху профиля; доступен для ручной правки; пополнение
обучением — по правилам BP-08.
(BP-07, шаг 4; раздел 1)

### FR-08 — Карта памяти
Система должна показывать карту памяти: темы-пузыри (размер — сколько Mnemai знает), пульс у недавно
изменённых, замок у тем, скрытых от части ИИ.
**Приёмка:** размер пузыря отражает объём знаний о теме; недавние изменения помечаются пульсом; темы,
скрытые от части ИИ, помечаются замком; скрытые теги (#money, #health, #private) — по правилам темы
4.1, настройка — BP-12.
(BP-07, шаг 5; раздел 1; тема 4.1)

## 5. Устаревшие статусы (BP-07, шаг 6)

### FR-09 — Переспрос статусов старше 30 дней
Система должна переспрашивать статус старше 30 дней, а не подавать его как текущий: задавать вопрос в
чате при первом упоминании темы.
**Приёмка:** статус старше 30 дней не выдаётся как текущий; при первом упоминании темы в чате система
задаёт вопрос о нём.
(BP-07, шаг 6; раздел 1; решение владельца 20.11.2026)

## 6. Журнал, отмена и источник (BP-07, шаг 7)

### FR-10 — Журнал чтений и записей
Система должна вести журнал каждой записи и чтения памяти, со снапшотами.
**Приёмка:** каждая запись и чтение отражены в журнале; доступны снапшоты.
(BP-07, шаг 7; раздел 1; тема 4.2)

### FR-11 — Отмена через «Память → История»
Система должна давать отмену сделанной записи через «Память → История» (undo).
**Приёмка:** через «Память → История» запись отменяется, память возвращается к предыдущему состоянию.
(BP-07, шаг 7; раздел 1; тема 4.2)

### FR-12 — «Откуда я это знаю»
Система должна показывать «откуда я это знаю» — ссылку на источник факта.
**Приёмка:** для факта доступна ссылка на его источник.
(BP-07, шаг 7; раздел 1)

### FR-13 — Экспорт журнала и ротация
Система должна экспортировать журнал из «Память → История» в Markdown/JSON и ротировать его: при
превышении 10 МБ файл архивируется с датой, хранится последних 5 архивов (решение владельца 20.11.2026).
Экспорт выполняется по правилам BP-16.
**Приёмка:** журнал экспортируется в Markdown/JSON из «Память → История»; при превышении 10 МБ файл
архивируется с датой; хранится последних 5 архивов.
(BP-07, шаг 7; раздел 12; тема 4.2; экспорт — BP-16; числа — решение владельца 20.11.2026)

## 7. Дополнительные папки (BP-07, шаг 8)

### FR-14 — Дополнительные папки только для чтения
Система должна подключать дополнительные папки (Obsidian-хранилища, командные папки) только для
чтения и блокировать запись в них.
**Приёмка:** содержимое подключённой папки читается; любая запись в неё блокируется; авторизация
командных папок не вводится (решение владельца 20.11.2026).
(BP-07, шаг 8; раздел 1)

## 8. Сквозные темы, применённые к памяти (тема 4.6)

### FR-15 — Достижения за события в памяти
Система должна начислять достижения (опыт, уровни, серии, бейджи) за события в памяти — по правилам
темы 4.6.
**Приёмка:** события в памяти отражаются в достижениях; детали игрового слоя — тема 4.6 (раздел 8).
(тема 4.6; раздел 8)
