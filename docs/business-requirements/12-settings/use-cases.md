# BP-12.3. Сценарии использования: настройки

Цепочка прослеживаемости: сценарий ввода → BP-12 (каталог бизнес-процессов) → BP-12.1…4 (эта папка).
Каждый UC трассирован «UC → FR → BP-12 шаг», включая FR альтернативных потоков и «триггер BP-12».

## 0. Сценарий ввода → BP-12

Путь клиента из описания клиентского пути (настройки): шестерёнка → разделы (ИИ и модели / движок /
правила / память / приватность / программа) — совпадает с шагами BP-12; VPN, язык, тема, автозапуск и трей
отдельными разделами в описании клиентского пути не названы — детализация каталога следует разделам о
приватности и о приложении (BP-12.1). Сценарий покрывается UC-01–UC-13.

## UC-01. Подключить ИИ (ключ API, подписка, Harness-агент)

- **Актор:** Пользователь (подключает), Система (проверяет, ведёт списки).
- **Предусловие:** пользователь открыл настройки (триггер BP-12); раздел «ИИ и модели».
- **Основной поток:**
  1. Пользователь выбирает тип подключения: подписка Claude (Claude Code) / ChatGPT (Codex), ключ API,
     Harness-агент. (FR-02)
  2. Пользователь вводит данные подключения (например, ключ API). (FR-02)
  3. Система проверяет работоспособность подключения. (FR-03)
  4. Система показывает списки моделей подключения. (FR-03)
  5. Изменение сохранено и применяется в чате, обучении, инструментах и интерфейсе. (FR-01; допущение:
     применяется сразу, без перезапуска — BP-12.4, 2.1)
- **Альтернативные потоки:**
  - А1 (проверка не прошла): провайдер упал / лимит / нет денег / ключ отклонён — сообщение с причиной,
    провайдер помечается нерабочим и не попадает в списки моделей (FR-03; тема 4.3).
  - А2 (локальная модель): включается без облака — UC-02 (FR-02).
  - А3 (хранение ключа): ключ хранится по правилам темы 4.1 — BP-16 (FR-02; данные пользователя).
  - А4 (удаление ключа): удаление секрета — UC-13, BP-16 (FR-17).
  - А5 (первый ИИ): подключение первого ИИ после визарда — BP-01, шаг 4 (FR-02).
- **Постусловие:** подключение проверено, модели в списках; настройка сохранена и применяется.
- **Трассировка:** UC-01 → FR-01, FR-02, FR-03, FR-17 → триггер BP-12; BP-12, шаг 1; результат BP-12;
  тема 4.3; BP-16.

## UC-02. Включить локальную модель

- **Актор:** Пользователь (включает), Система.
- **Предусловие:** раздел «ИИ и модели» открыт (UC-01); локальная модель — встроенная, Ollama или Strata
  (FR-02; описание чата).
- **Основной поток:**
  1. Пользователь выбирает локальную модель. (FR-02)
  2. Система включает модель и показывает её в списках. (FR-03)
  3. Локальная модель видит всю память — с компьютера ничего не уходит. (FR-06; приватность и
     безопасность; тема 4.1)
  4. Изменение сохранено и применяется. (FR-01)
- **Альтернативные потоки:**
  - А1 (движок не установлен): поведение при отсутствии Ollama/Strata не описано (BP-12.1, «Область вне
    требований»).
  - А2 (офлайн): локальные модели работают, облачные недоступны — BP-02, шаг 8 (краевые состояния).
  - А3 (проверка): работоспособность проверяется по правилам темы 4.3 (FR-03).
- **Постусловие:** локальная модель включена и в списках; работает без облака.
- **Трассировка:** UC-02 → FR-01, FR-02, FR-03, FR-06 → триггер BP-12; BP-12, шаги 1, 4; результат BP-12;
  тема 4.1.

## UC-03. Скрыть тему от части ИИ (доступы к памяти)

- **Актор:** Пользователь (задаёт доступы), Система.
- **Предусловие:** раздел приватности открыт; у памяти есть части с тегами (описание памяти; приватность
  и безопасность).
- **Основной поток:**
  1. Пользователь чек-боксами задаёт части памяти, которые ИИ может читать и куда может писать. (FR-06)
  2. Пользователь ставит замок на тему, скрытую от части ИИ. (FR-06)
  3. Система сохраняет доступы; они применяются едино для чата и внешних MCP-клиентов. (FR-06, FR-01;
     тема 4.1)
- **Альтернативные потоки:**
  - А1 (локальная модель): локальная модель видит всё — настройка на неё не действует (FR-06; приватность
    и безопасность).
  - А2 (применение): память по правам выдаётся при сборке ответа — BP-02, BP-07 (FR-06; тема 4.1).
  - А3 (скрытые теги): `#money`/`#health`/`#private` скрывают раздел (описание памяти; FR-06).
  - А4 (факт-архив): модели не получают факт-архив никогда — BP-07 (тема 4.1).
- **Постусловие:** доступы заданы; скрытые темы не видны выбранным ИИ; правило едино для чата и MCP.
- **Трассировка:** UC-03 → FR-01, FR-06 → триггер BP-12; BP-12, шаг 4; результат BP-12; тема 4.1; BP-02,
  BP-07.

## UC-04. Настроить VPN

- **Актор:** Пользователь (настраивает), Система.
- **Предусловие:** раздел VPN настроек открыт (BP-12, шаг 5).
- **Основной поток:**
  1. Пользователь запускает автодетект рабочего VPN (Windows) — без ввода данных. (FR-10)
  2. Система находит рабочий VPN и применяет его. (FR-10)
  3. Изменение сохранено и применяется. (FR-01)
- **Альтернативные потоки:**
  - А1 (ключ): пользователь подключается по VPN-ключу или ссылке-подписке вместо автодетекта (FR-10).
  - А2 (автодетект не нашёл VPN): система показывает ошибку и предлагает ввести ключ вручную (FR-10;
    решение владельца, 20.11.2026).
  - А3 (неверный ключ): система показывает ошибку и предлагает ввести ключ вручную (FR-10; решение
    владельца, 20.11.2026).
  - А4 (macOS/Linux): автодетект описан только для Windows; на остальных ОС — ключ/туннели (FR-10;
    тема 4.1; приватность и безопасность).
  - А5 (хранение ключа): VPN-ключ хранится в защищённом хранилище системы — тема 4.1, BP-16 (FR-10).
  - А6 (изоляция): локальный прокси — только для Mnemai, система не трогается (FR-10; приватность и
    безопасность).
- **Постусловие:** VPN найден или подключён по ключу; прокси действует только для Mnemai.
- **Трассировка:** UC-04 → FR-01, FR-10 → триггер BP-12; BP-12, шаг 5; результат BP-12; тема 4.1; BP-16.

## UC-05. Сменить язык интерфейса и язык общения

- **Актор:** Пользователь (выбирает язык), Система.
- **Предусловие:** раздел языка настроек открыт (BP-12, шаг 6).
- **Основной поток:**
  1. Пользователь выбирает один из девяти языков интерфейса. (FR-11)
  2. Пользователь задаёт язык общения в профиле. (FR-11)
  3. Изменение сохранено и применяется в интерфейсе и чате. (FR-01)
- **Альтернативные потоки:**
  - А1 (ответы ИИ): ответы ИИ следуют выбранному языку общения — тема 4.5, BP-02 (FR-11).
  - А2 (первый запуск): язык выбирается в визарде — BP-01 (FR-11).
  - А3 (возврат к визарду): язык меняется и через возврат к шагу онбординга — UC-11 (FR-15).
- **Постусловие:** интерфейс на выбранном языке; ответы ИИ следуют языку общения.
- **Трассировка:** UC-05 → FR-01, FR-11, FR-15 → триггер BP-12; BP-12, шаг 6; результат BP-12; тема 4.5;
  BP-01.

## UC-06. Настроить правила общения и тумблер разрешений

- **Актор:** Пользователь (переключает тумблеры), Система.
- **Предусловие:** разделы правил и приватности открыты (BP-12, шаги 3–4).
- **Основной поток:**
  1. Пользователь тумблерами включает/выключает правила общения по темам: как говорить, работа с
     задачей, факты, память, приватность, оформление. (FR-05)
  2. Пользователь включает тумблер разрешений на действия. (FR-07)
  3. Изменения сохранены и применяются. (FR-01)
- **Альтернативные потоки:**
  - А1 (сборка ответа): включённые правила участвуют в сборке ответа — BP-02, шаг 2 (FR-05).
  - А2 (тумблер выключен): по умолчанию тумблер разрешений выключен — действия выполняются сразу, отмена
    — в «Истории» (FR-07; описание чата; BP-04).
  - А3 (тумблер включён): карточка «Да / Нет / Да для этого разговора» — BP-04 (FR-07; описание чата).
  - А4 (обязательный вопрос): вызовы внешних MCP-инструментов и проверочные прогоны спрашивают «да»
    всегда, при любом положении тумблера — BP-04 (FR-07; описание чата).
- **Постусловие:** правила и тумблер настроены; поведение действий — по правилам BP-04.
- **Трассировка:** UC-06 → FR-01, FR-05, FR-07 → триггер BP-12; BP-12, шаги 3–4; результат BP-12; BP-02,
  BP-04.

## UC-07. Настроить движок и лимиты (пресеты)

- **Актор:** Пользователь (выбирает пресет), Система.
- **Предусловие:** раздел движка открыт (BP-12, шаг 2).
- **Основной поток:**
  1. Пользователь выбирает пресет движка: «Быстрый», «Сбалансированный» или «Качественный». (FR-04)
  2. Система применяет пресет к движку. (FR-04)
  3. Пользователь при необходимости задаёт числа лимитов в продвинутом разделе. (FR-04)
  4. Изменение сохранено и применяется. (FR-01)
- **Альтернативные потоки:**
  - А1 (пресеты): доступны три пресета — «Быстрый», «Сбалансированный», «Качественный» (FR-04; решение
    владельца, 20.11.2026).
  - А2 (числа лимитов): числа лимитов настраиваются в продвинутом разделе (FR-04; решение владельца,
    20.11.2026); конкретные значения — целевые показатели, подтверждаются замерами (тема 4.8).
  - А3 (применение лимитов): действующие лимиты применяются в чате, действиях и схемах — тема 4.8,
    BP-02, BP-04, BP-06 (FR-04).
- **Постусловие:** пресет применён; лимиты действуют по правилам темы 4.8.
- **Трассировка:** UC-07 → FR-01, FR-04 → триггер BP-12; BP-12, шаг 2; результат BP-12; тема 4.8;
  решение владельца, 20.11.2026.

## UC-08. Настроить обучение: порог автозаписи и кулдаун

- **Актор:** Пользователь (задаёт числа), Система.
- **Предусловие:** раздел памяти/обучения настроек открыт (BP-12, шаг 4).
- **Основной поток:**
  1. Пользователь задаёт порог автозаписи (по умолчанию 0.8 = 80 %). (FR-08)
  2. Пользователь задаёт кулдаун повторного вопроса (по умолчанию 10 минут). (FR-08)
  3. Изменение сохранено и применяется. (FR-01)
- **Альтернативные потоки:**
  - А1 (применение порога): факт с уверенностью не ниже порога записывается сразу — BP-08, шаг 4 (FR-08;
    описание обучения).
  - А2 (вопрос под разговором): вопрос задаётся с учётом кулдауна и порога — BP-08, шаг 5 (FR-08;
    описание обучения).
  - А3 (кулдаун по умолчанию): кулдаун по умолчанию — 10 минут (FR-08; решение владельца, 20.11.2026).
- **Постусловие:** порог и кулдаун заданы; обучение применяет их по правилам BP-08.
- **Трассировка:** UC-08 → FR-01, FR-08 → триггер BP-12; BP-12, шаг 4; результат BP-12; BP-08.

## UC-09. Подключить дополнительную папку памяти

- **Актор:** Пользователь (подключает папку), Система.
- **Предусловие:** раздел памяти настроек открыт (BP-12, «Входит» — память).
- **Основной поток:**
  1. Пользователь выбирает дополнительную папку: Obsidian-хранилище или командную папку. (FR-09)
  2. Система подключает папку только для чтения и блокирует запись в неё. (FR-09; BP-07, шаг 8)
  3. Изменение сохранено и применяется. (FR-01)
- **Альтернативные потоки:**
  - А1 (запись в папку): запись блокируется — BP-07 (FR-09; описание памяти).
  - А2 (авторизация командных папок): открытый вопрос о ролях станции и командных папок (BP-12.1,
    «Область вне требований»; BP-07).
- **Постусловие:** папка подключена только для чтения; запись в неё заблокирована.
- **Трассировка:** UC-09 → FR-01, FR-09 → триггер BP-12; BP-12, «Входит»; результат BP-12; BP-07.

## UC-10. Сменить тему, автозапуск и трей

- **Актор:** Пользователь (переключает), Система.
- **Предусловие:** раздел программы настроек открыт (BP-12, шаг 7).
- **Основной поток:**
  1. Пользователь переключает тему: светлая/тёмная. (FR-12)
  2. Пользователь включает или выключает автозапуск. (FR-13)
  3. Пользователь видит иконку приложения в трее. (FR-14)
  4. Изменения сохранены и применяются. (FR-01)
- **Альтернативные потоки:**
  - А1 (выход): выход останавливает обучение, трей и окно — тема 4.7 (FR-14).
  - А2 (первый запуск): тема выбирается в визарде — BP-01 (FR-12).
  - А3 (настройки трея): что именно настраивается у трея — не описано (BP-12.1, «Область вне
    требований»).
- **Постусловие:** тема и автозапуск применены; трей работает по правилам темы 4.7.
- **Трассировка:** UC-10 → FR-01, FR-12, FR-13, FR-14 → триггер BP-12; BP-12, шаг 7; результат BP-12;
  тема 4.7; BP-01.

## UC-11. Вернуться к шагу онбординга из настроек

- **Актор:** Пользователь (возвращается к шагу), Система.
- **Предусловие:** настройки открыты; визард онбординга уже пройден (BP-01).
- **Основной поток:**
  1. Пользователь выбирает возврат к шагу онбординга. (FR-15)
  2. Система открывает выбранный шаг визарда (тема → язык → обращение → память). (FR-15; BP-01, шаг 1)
  3. Изменение, сделанное на шаге, сохраняется и применяется. (FR-01)
- **Альтернативные потоки:**
  - А1 (любой шаг): доступен возврат к любому из четырёх шагов — BP-01, шаг 5 (FR-15; приложение и
    жизненный цикл).
  - А2 (пароль): шаг памяти предлагает пароль шифрования — UC-12, BP-15 (FR-16).
- **Постусловие:** шаг визарда открыт из настроек; изменения применены.
- **Трассировка:** UC-11 → FR-01, FR-15, FR-16 → триггер BP-12; BP-01, шаг 5 («см. BP-12»); результат
  BP-12; BP-01.

## UC-12. Включить пароль шифрования памяти из настроек

- **Актор:** Пользователь (включает пароль), Система.
- **Предусловие:** память создана (BP-01); пароль не включён.
- **Основной поток:**
  1. Пользователь включает пароль шифрования в настройках. (FR-16)
  2. Система передаёт включение пароля в BP-15: текст-файлы памяти шифруются. (FR-16; BP-15)
- **Альтернативные потоки:**
  - А1 (заблокированная память): при запуске без пароля запросы, которым нужна память, отклоняются,
    интерфейс предлагает ввести пароль — BP-15 (краевые состояния).
  - А2 (забытый пароль): восстановления нет — BP-15, открытый вопрос о забытом пароле.
  - А3 (бинарные файлы): PDF, картинки, записи остаются открытыми — BP-15 (текущее ограничение).
- **Постусловие:** пароль включён; поведение шифрования — по правилам BP-15.
- **Трассировка:** UC-12 → FR-16 → триггер BP-12; BP-15, «Триггер»; BP-15.

## UC-13. Удалить секрет из настроек

- **Актор:** Пользователь (удаляет), Система.
- **Предусловие:** секрет подключения задан: ключ API, логин Telegram или VPN-ключ (данные пользователя).
- **Основной поток:**
  1. Пользователь удаляет секрет в настройках. (FR-17)
  2. Система удаляет секрет по правилам BP-16 и темы 4.1. (FR-17; BP-16, шаг 4)
- **Альтернативные потоки:**
  - А1 (хранение): секреты хранятся в защищённом хранилище системы отдельно от памяти — BP-16, тема 4.1
    (FR-17; данные пользователя).
  - А2 (журналы): в журналах секретов нет — только счётчики скрытого — BP-16, тема 4.1 (FR-17).
- **Постусловие:** секрет удалён; в журналах его не было.
- **Трассировка:** UC-13 → FR-17 → триггер BP-12; BP-16, шаг 4 («см. BP-12»); тема 4.1; BP-16.
