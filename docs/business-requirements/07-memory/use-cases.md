# BP-07.3. Сценарии использования: память: чтение, правка, история, undo

## 0. Сценарий ввода → BP-07

Путь клиента из CLIENT_JOURNEY (раздел 2.5): вкладка «Память» → карточки/проекты/люди/решения →
читать/править → журнал/undo. Сценарий покрывается UC-01–UC-10.

## UC-01. Записать факт в память

- **Актор:** Пользователь (пишет факт) или ИИ (инструмент памяти — запись в пределах прав клиента, тема 4.1, BP-12).
- **Предусловие:** память создана (см. BP-01); приложение открыто.
- **Основной поток:**
  1. Пользователь открывает «Память» (или ИИ запрашивает запись факта). (FR-01; триггер BP-07)
  2. Пользователь записывает факт одной строкой с датой — в Inbox, карточку или журнал проекта. (FR-02, FR-03)
  3. Система сохраняет факт и регистрирует запись в журнале. (FR-10)
  4. Система начисляет достижение за событие в памяти. (FR-15; тема 4.6)
- **Альтернативные потоки:**
  - А1 (отмена): запись ошибочна — пользователь отменяет её через «Память → История» — UC-04 (FR-11).
  - А2 (обновление): запись — новый статус существующей записи — UC-02 (FR-04).
  - А3 (удаление): пользователь хочет удалить факт — удаление через интерфейс и журнал — см. BP-16 (раздел 15).
  - А4 (повтор): заметка-источник исправлена — система пересобирает индекс — UC-06 (FR-06).
- **Постусловие:** факт записан; журнал пополнен; индекс актуален.
- **Трассировка:** UC-01 → FR-01, FR-02, FR-03, FR-10, FR-15 → BP-07, шаги 1–3, 7; тема 4.6.

## UC-02. Обновить статус

- **Актор:** Пользователь (или ИИ — инструмент памяти).
- **Предусловие:** в памяти есть запись со статусом.
- **Основной поток:**
  1. Пользователь открывает запись со статусом. (FR-01)
  2. Пользователь вводит новый статус «(статус ДД.ММ.ГГГГ)». (FR-03)
  3. Система заменяет старую версию новой. (FR-04)
  4. Старая версия уходит в факт-архив. (FR-04)
  5. Изменение попадает в ленту событий и регистрируется в журнале. (FR-04, FR-10)
- **Альтернативные потоки:**
  - А1 (устаревший статус): прочитанный статус старше 30 дней — система не подаёт его как текущий и
    задаёт вопрос в чате при первом упоминании темы (FR-09; решение владельца 20.11.2026).
  - А2 (приватность): факт-архив модели не отправляется — старые версии не попадают в запросы ИИ
    (FR-05; тема 4.1).
  - А3 (отмена): неверный статус — отмена через «Память → История» — UC-04 (FR-11).
- **Постусловие:** запись содержит последний статус; старая версия в факт-архиве; изменение в ленте и
  журнале.
- **Трассировка:** UC-02 → FR-01, FR-03, FR-04, FR-05, FR-09, FR-10 → BP-07, шаги 1–2, 6, 7.

## UC-03. Прочитать память без приложения

- **Актор:** Пользователь.
- **Предусловие:** память создана; шифрование выключено (см. BP-15).
- **Основной поток:**
  1. Пользователь открывает папку памяти средствами компьютера, без приложения. (FR-01)
  2. Пользователь видит фиксированную раскладку. (FR-02)
  3. Пользователь читает или правит заметки. (FR-01)
  4. При следующем обращении приложение пересобирает индекс по изменённым источникам. (FR-06)
- **Альтернативные потоки:**
  - А1 (шифрование включено): чтение без приложения недоступно; доступ — только в приложении после
    ввода пароля — см. BP-15.
  - А2 (дополнительные папки): Obsidian-хранилища и командные папки доступны только для чтения —
    UC-09 (FR-14).
- **Постусловие:** память прочитана или исправлена напрямую; индекс актуален.
- **Трассировка:** UC-03 → FR-01, FR-02, FR-06 → BP-07, шаги 1, 3.

## UC-04. Отменить запись через «Память → История»

- **Актор:** Пользователь.
- **Предусловие:** в журнале есть запись о сделанной записи.
- **Основной поток:**
  1. Пользователь открывает «Память → История». (FR-10)
  2. Пользователь выбирает запись для отмены. (FR-11)
  3. Система отменяет запись и возвращает память к предыдущему состоянию. (FR-11)
  4. Отмена регистрируется в журнале. (FR-10; регистрация самой отмены отдельно не описана — следует из
     «журнала каждого чтения/записи», раздел 1)
- **Альтернативные потоки:**
  - А1 (удаление, а не отмена): удаление факта/чата — через интерфейс и журнал — см. BP-16 (раздел 15).
  - А2 (снапшоты): отмена опирается на снапшоты журнала. (FR-10)
- **Постусловие:** запись отменена; память в предыдущем состоянии; журнал пополнен.
- **Трассировка:** UC-04 → FR-10, FR-11 → BP-07, шаг 7; тема 4.2.

## UC-05. Найти источник факта («откуда я это знаю»)

- **Актор:** Пользователь.
- **Предусловие:** факт записан; источник зафиксирован в журнале.
- **Основной поток:**
  1. Пользователь открывает факт. (FR-01)
  2. Система показывает «откуда я это знаю» — ссылку на источник факта. (FR-12)
  3. Пользователь переходит к источнику. (FR-12)
- **Альтернативные потоки:**
  - А1 (нет источника): источник не зафиксирован — поведение не описано в источниках.
  - А2 (источник в архиве): источник — старая версия в факт-архиве; архив модели не отправляется, но
    пользователю доступен (FR-05; доступность архива пользователю следует из раздела 1 «старая уходит
    в факт-архив»).
- **Постусловие:** источник факта показан и прослеживается.
- **Трассировка:** UC-05 → FR-01, FR-05, FR-12 → BP-07, шаги 1–2, 7.

## UC-06. Индекс пересобирается после правки

- **Актор:** Пользователь (или ИИ).
- **Предусловие:** память создана; индекс собран.
- **Основной поток:**
  1. Пользователь (или ИИ) правит заметку-источник. (FR-01, FR-03)
  2. Система пересобирает индекс автоматически. (FR-06)
  3. Индекс соответствует обновлённым заметкам. (FR-06)
- **Альтернативные потоки:**
  - А1 (ручная правка индекса): не предусмотрена — индекс не пишется руками. (FR-06)
- **Постусловие:** индекс актуален.
- **Трассировка:** UC-06 → FR-01, FR-03, FR-06 → BP-07, шаги 1–3.

## UC-07. Портрет: чтение и ручная правка

- **Актор:** Пользователь.
- **Предусловие:** профиль создан (память создана — см. BP-01).
- **Основной поток:**
  1. Пользователь открывает профиль. (FR-01, FR-02)
  2. Система показывает портрет из 2–3 предложений вверху профиля. (FR-07)
  3. Пользователь правит портрет руками. (FR-07)
- **Альтернативные потоки:**
  - А1 (пополнение обучением): портрет пополняется обучением — см. BP-08 (ссылка).
  - А2 (первый ИИ): портрет — первое, что читает каждый ИИ при сборке контекста — см. BP-02 (ссылка).
- **Постусловие:** портрет актуален; правится руками.
- **Трассировка:** UC-07 → FR-01, FR-02, FR-07 → BP-07, шаги 1, 4.

## UC-08. Карта памяти: пузыри, пульс, замки

- **Актор:** Пользователь.
- **Предусловие:** в памяти есть темы (карточки).
- **Основной поток:**
  1. Пользователь открывает карту памяти. (FR-08)
  2. Система показывает темы-пузыри; размер пузыря — сколько Mnemai знает о теме. (FR-08)
  3. Недавно изменённые темы показываются с пульсом. (FR-08)
  4. Темы, скрытые от части ИИ, показываются с замком. (FR-08)
- **Альтернативные потоки:**
  - А1 (скрытые теги): замок у тем с тегами #money/#health/#private — скрытие настраивается по правилам
    темы 4.1, BP-12 (ссылка).
- **Постусловие:** карта памяти отражает объём знаний, свежесть изменений и скрытость тем.
- **Трассировка:** UC-08 → FR-08 → BP-07, шаг 5; тема 4.1.

## UC-09. Подключить дополнительную папку только для чтения

- **Актор:** Пользователь.
- **Предусловие:** приложение открыто; есть Obsidian-хранилище или командная папка.
- **Основной поток:**
  1. Пользователь подключает дополнительную папку. (FR-14)
  2. Система открывает её только для чтения. (FR-14)
  3. Пользователь читает содержимое папки. (FR-14)
- **Альтернативные потоки:**
  - А1 (попытка записи): любая запись в подключённую папку блокируется. (FR-14)
  - А2 (командная папка): авторизация командных папок не вводится — папка остаётся только для чтения
    (FR-14; решение владельца 20.11.2026).
- **Постусловие:** папка подключена только для чтения; запись в неё заблокирована.
- **Трассировка:** UC-09 → FR-14 → BP-07, шаг 8.

## UC-10. Экспорт журнала и ротация

- **Актор:** Пользователь.
- **Предусловие:** журнал ведётся (есть записи или чтения).
- **Основной поток:**
  1. Пользователь открывает «Память → История». (FR-10)
  2. Пользователь экспортирует журнал в Markdown/JSON. (FR-13)
  3. Система выгружает журнал по правилам BP-16. (FR-13)
- **Альтернативные потоки:**
  - А1 (ротация): при превышении 10 МБ система архивирует журнал с датой и хранит последних 5 архивов
    (FR-13; решение владельца 20.11.2026).
  - А2 (повтор): повторный экспорт выполняется так же; отмена экспорта не требуется (undo относится к
    записям памяти; отмена экспорта в источниках не описана).
- **Постусловие:** журнал экспортирован; ротация выполнена: порог 10 МБ, хранится 5 архивов.
- **Трассировка:** UC-10 → FR-10, FR-13 → BP-07, шаг 7; экспорт — BP-16.
