# BP-01.3. Сценарии использования: онбординг и первый запуск

## 0. Сценарий ввода → BP-01

Путь клиента из CLIENT_JOURNEY (раздел 2.1): открыл приложение → язык/тема → создать/открыть память →
обращение → подключить ИИ → первый вопрос. Каталог BP-01 зафиксировал порядок по разделу 8 (тема → язык →
обращение → память); примечание о расхождении — в BP-01.1. Сценарий покрывается UC-01–UC-07.

## UC-01. Первый запуск: создать память и задать первый вопрос

- **Актор:** Пользователь.
- **Предусловие:** приложение установлено и запускается впервые; папка памяти не создана (триггер BP-01).
- **Основной поток:**
  1. Пользователь запускает приложение; система открывает визард. (FR-01)
  2. Пользователь выбирает тему — светлую или тёмную. (FR-02)
  3. Пользователь выбирает язык из девяти. (FR-03)
  4. Пользователь вводит, как к нему обращаться. (FR-04)
  5. Пользователь выбирает «создать новую память»; система предлагает путь по умолчанию в домашней папке. (FR-05, FR-06)
  6. Пользователь пропускает пароль (задание пароля — UC-03). (FR-07)
  7. Система завершает визард и предлагает подключить хотя бы один ИИ. (FR-08)
  8. Пользователь подключает первый ИИ (UC-04).
  9. Пользователь задаёт первый вопрос в чате (см. BP-02).
- **Альтернативные потоки:**
  - А1 (выход): пользователь закрывает приложение на шагах 1–6 до создания памяти → память не создана; при следующем запуске без памяти визард начинается заново (FR-01; решение владельца 20.11.2026).
  - А2 (отказ): на шаге 8 пользователь не подключает ИИ → чат не отправляет запрос, объясняет причину и ведёт в настройки; память, журнал и команды без модели работают (FR-08; UC-05).
  - А3 (повтор): выборы темы/языка/обращения можно изменить позже через настройки (FR-09; см. BP-12).
- **Постусловие:** память создана; язык, тема и обращение выбраны; подключён хотя бы один ИИ; возможен первый вопрос (BR-08).
- **Трассировка:** UC-01 → FR-01, FR-02, FR-03, FR-04, FR-05, FR-06, FR-07, FR-08 → BP-01, шаги 1–4.

## UC-02. Первый запуск: открыть существующую память

- **Актор:** Пользователь.
- **Предусловие:** запуск без настроенной памяти (визард открыт); на компьютере есть существующая папка памяти.
- **Основной поток:**
  1. Система открывает визард. (FR-01)
  2. Пользователь выбирает тему, язык и обращение. (FR-02, FR-03, FR-04)
  3. На шаге «память» пользователь выбирает «открыть существующую» и указывает папку. (FR-05)
  4. Система открывает указанную память.
  5. Пользователь подключает первый ИИ (FR-08; UC-04).
  6. Пользователь задаёт первый вопрос в чате (см. BP-02).
- **Альтернативные потоки:**
  - А1 (отказ/блокировка): указанная папка зашифрована и пароль не введён → запросы, которым нужна память, отклоняются ошибкой блокировки, интерфейс предлагает ввести пароль (см. BP-15; раздел 14); после ввода пароля — продолжение с шага 4.
  - А2 (повтор): пользователь передумал — на шаге «память» выбирает «создать новую» вместо открытия (FR-05; UC-01).
- **Постусловие:** память открыта; язык, тема и обращение выбраны; подключён хотя бы один ИИ (BR-08).
- **Трассировка:** UC-02 → FR-01, FR-02, FR-03, FR-04, FR-05, FR-08 → BP-01, шаги 1–2, 4.

## UC-03. Пароль шифрования при создании памяти

- **Актор:** Пользователь.
- **Предусловие:** визард открыт; пользователь выбрал «создать новую память» (UC-01, шаги 1–5).
- **Основной поток:**
  1. Система предлагает задать пароль шифрования (необязательно). (FR-07)
  2. Пользователь задаёт и подтверждает пароль.
  3. Система включает шифрование по правилам BP-15.
  4. Визард продолжается: подключение первого ИИ (FR-08; UC-04).
- **Альтернативные потоки:**
  - А1 (отказ): пользователь пропускает пароль → память остаётся открытой, шифрование выключено (раздел 1; см. BP-15).
  - А2 (повтор): включить пароль позже можно в настройках (см. BP-15).
  - А3 (забыт): пароль забыт → восстановление только по ключу восстановления (см. BP-15; раздел 12, пункт 3).
- **Постусловие:** память создана; пароль задан (память зашифрована — BP-15) или пропущен по выбору пользователя.
- **Трассировка:** UC-03 → FR-05, FR-06, FR-07 → BP-01, шаги 2–3.

## UC-04. Подключить первый ИИ

- **Актор:** Пользователь.
- **Предусловие:** визард завершён; не подключён ни один ИИ.
- **Основной поток:**
  1. Система предлагает подключить хотя бы один ИИ. (FR-08)
  2. Пользователь выбирает провайдера: подписка Claude (Claude Code), подписка ChatGPT (Codex), ключ API, локальная модель, Harness-агент (тема 4.3 каталога).
  3. Подключение и проверка работоспособности (детали — BP-12).
  4. Провайдер доступен; модель попадает в списки выбора (см. BP-12, тема 4.3).
  5. Пользователь задаёт первый вопрос в чате (см. BP-02).
- **Альтернативные потоки:**
  - А1 (сбой): провайдер упал / лимит / нет денег / ключ отклонён → сообщение с причиной; провайдер помечается нерабочим и не попадает в списки моделей (тема 4.3).
  - А2 (отказ): пользователь откладывает подключение → состояние «нет ИИ»: чат не отправляет запрос, объясняет причину и ведёт в настройки; память, журнал и команды без модели работают (FR-08; UC-05; BP-02, шаг 7).
- **Постусловие:** подключён хотя бы один работающий ИИ (BR-05, BR-08) — либо зафиксировано состояние «нет ИИ».
- **Трассировка:** UC-04 → FR-08 → BP-01, шаг 4.

## UC-05. Работа без подключённых ИИ (краевое состояние)

- **Актор:** Пользователь.
- **Предусловие:** память создана или открыта; не подключён ни один ИИ.
- **Основной поток:**
  1. Пользователь открывает чат.
  2. Система не отправляет запрос, объясняет, что нужно подключить хотя бы один ИИ, и ведёт в настройки (FR-08; BP-02, шаг 7).
  3. Память, журнал и команды без модели («открой …») работают (тема 4.4; раздел 14).
  4. Пользователь подключает первый ИИ (UC-04).
- **Альтернативные потоки:**
  - А1 (повтор): подключение откладывается повторно — состояние «нет ИИ» сохраняется; на каждый запрос чат объясняет причину (FR-08; BP-02).
  - А2 (выход): пользователь выходит из приложения — при следующем запуске визард не открывается (память есть), состояние «нет ИИ» сохраняется (FR-11; тема 4.7).
- **Постусловие:** подключён хотя бы один ИИ (BR-05) — или состояние «нет ИИ» продолжается без ошибок.
- **Трассировка:** UC-05 → FR-08, FR-11 → BP-01, шаг 4; BP-02, шаг 7.

## UC-06. Первый запуск с пустой памятью

- **Актор:** Пользователь.
- **Предусловие:** память создана или открыта; записей в ней нет.
- **Основной поток:**
  1. Пользователь открывает разделы приложения.
  2. Система показывает пустые списки и подсказки вместо ошибок. (FR-10)
  3. Пользователь подключает первый ИИ (UC-04) или наполняет память (см. BP-02, BP-07, BP-09).
- **Альтернативные потоки:**
  - А1 (отказ): пользователь ничего не делает — интерфейс остаётся в состоянии пустых списков и подсказок, ошибок нет (FR-10).
- **Постусловие:** приложение работает; пустые списки и подсказки показаны; сообщений об ошибках нет.
- **Трассировка:** UC-06 → FR-10 → BP-01, шаг 6.

## UC-07. Повторный запуск и возврат к шагам визарда

- **Актор:** Пользователь.
- **Предусловие:** память уже создана или открыта; приложение запускается повторно.
- **Основной поток:**
  1. Пользователь запускает приложение.
  2. Визард не открывается; открывается рабочее окно. (FR-11)
  3. При желании пользователь открывает настройки и меняет тему, язык, обращение или память — возврат к любому шагу визарда (FR-09; см. BP-12).
- **Альтернативные потоки:**
  - А1 (блокировка): память зашифрована и пароль не введён → запросы, которым нужна память, отклоняются ошибкой блокировки; интерфейс предлагает ввести пароль (см. BP-15; раздел 14).
  - А2 (повторный запуск): приложение уже работает → повторный запуск показывает первое окно (один экземпляр; FR-11; тема 4.7).
- **Постусловие:** рабочее окно открыто; память доступна или предложен ввод пароля; изменения онбординга доступны через настройки.
- **Трассировка:** UC-07 → FR-09, FR-11 → BP-01, шаг 5; тема 4.7.
