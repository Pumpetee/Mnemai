# BP-06.3. Сценарии использования: конструктор схем

Цепочка прослеживаемости: сценарий ввода → BP-06 (каталог бизнес-процессов) → BP-06.1…4 (эта папка).
Каждый UC трассирован «UC → FR → BP-06 шаг», включая FR альтернативных потоков.

## 0. Сценарий ввода → BP-06

Путь клиента из описания клиентского пути (конструктор схем): «Схема» → задача → «Предложить варианты» →
3 варианта (Быстро/Оптимально/Качественно) с ценой и бюджетом → «Запустить» → цепочка шагов с
live-статусами → итог — совпадает с описанием конструктора схем, расхождений нет (BP-06.1). Описание
архитектуры конструктор схем не описывает — отсутствие описания, а не расхождение (BP-06.1). Сценарий
покрывается UC-01–UC-07.

## UC-01. Предложить варианты схемы

- **Актор:** Пользователь (описывает задачу, запрашивает варианты), ИИ-планировщик (подбирает шаги и
  исполнителей), Система.
- **Предусловие:** в настройках подключён хотя бы один ИИ (FR-01); поведение без подключённых ИИ не
  описано (BP-06.1, «Область вне требований»; ср. BP-02, шаг 7).
- **Основной поток:**
  1. Пользователь открывает «Схему» и описывает задачу. (FR-01; триггер BP-06)
  2. Пользователь просит предложить варианты. (FR-01)
  3. Планировщик подбирает шаги и исполнителей из подключённых ИИ. (FR-01)
  4. Система показывает три варианта — «Быстро», «Оптимально», «Качественно» — с оценкой времени,
     токенов и цены. (FR-02)
  5. Длина каждого варианта — не более 6 шагов, «Качественно» — не более 5. (FR-03)
  6. Цены в смете — по правилам темы 4.3: точные — для моделей OpenRouter, для остальных — ориентир.
     (FR-04)
  7. Вместе с вариантами показан рекомендуемый бюджет из дешёвой сметы; варианты укладываются в него.
     (FR-05, FR-06; допущение: варианты предлагаются сразу с рекомендуемым бюджетом — BP-06.4, 2.6)
- **Альтернативные потоки:**
  - А1 (нет подключённых ИИ): поведение «Схемы» не описано (BP-06.1, «Область вне требований»; FR-01).
  - А2 (пустое описание задачи): поведение не описано (BP-06.1, «Область вне требований»).
  - А3 (сбой провайдера планировщика): краевые состояния описывают фолбэк только для цепочки; для этапа
    подбора вариантов не описано (BP-06.1, «Область вне требований»).
  - А4 (смена бюджета): пользователь задаёт свой бюджет — UC-02 (FR-05, FR-06).
  - А5 (экономия): экономия применена при подборе — FR-07.
  - А6 (правка шагов): шаги и исполнители правятся до запуска — UC-07 (FR-16).
- **Постусловие:** показаны три варианта с оценками и ценами, в пределах рекомендуемого бюджета; длины
  в лимитах.
- **Трассировка:** UC-01 → FR-01, FR-02, FR-03, FR-04, FR-05, FR-06, FR-07 → BP-06, шаги 1–4.

## UC-02. Задать свой бюджет

- **Актор:** Пользователь (задаёт бюджет), Система (пересчитывает варианты).
- **Предусловие:** варианты предложены (UC-01); бюджет задаётся в долларах (FR-05).
- **Основной поток:**
  1. Пользователь задаёт свой бюджет в долларах вместо рекомендуемого. (FR-05)
  2. Система пересчитывает варианты: дорогие шаги понижаются до дешёвых моделей, все варианты
     укладываются в бюджет. (FR-06)
  3. Пользователь видит варианты в пределах своего бюджета. (FR-06)
- **Альтернативные потоки:**
  - А1 (возврат к рекомендуемому): рекомендуемый бюджет снова рассчитывается из дешёвой сметы (FR-05).
  - А2 (бюджет меньше любого варианта): честно показан минимум (FR-06); что именно показывает «минимум»,
    не описано (BP-06.1, «Область вне требований»).
  - А3 (нечисловой или пустой бюджет): поведение не описано (BP-06.1, «Область вне требований»).
  - А4 (цены после пересчёта): показываются по правилам темы 4.3, включая точные цены OpenRouter (FR-04).
- **Постусловие:** показаны варианты в пределах своего бюджета — или честный минимум; понижения дорогих
  шагов отражены.
- **Трассировка:** UC-02 → FR-04, FR-05, FR-06 → BP-06, шаги 3–4.

## UC-03. Запустить цепочку в чате

- **Актор:** Пользователь (запускает), ИИ-исполнители (выполняют шаги), Система.
- **Предусловие:** предложены варианты (UC-01), бюджет задан (UC-01/UC-02); пользователь выбрал вариант
  для запуска (допущение: запускается выбранный вариант — BP-06.4, 2.3).
- **Основной поток:**
  1. Пользователь запускает цепочку. (FR-08)
  2. Система запускает цепочку в чате; шаги выполняются назначенными исполнителями в составе, подобранном
     с применённой экономией. (FR-08, FR-07)
  3. Ход выполнения показывается live-статусами шагов, обновляемыми не реже чем каждые 200 мс. (FR-09)
  4. На каждом шаге действуют лимиты: вызов провайдера — не более 300 с; действий — до 80; «да» на
     карточку разрешения — не более 600 с. (FR-14)
  5. Действия исполнителей исполняются по правилам BP-04; записи действий отменяются через журнал
     (BP-07, тема 4.2).
  6. Перед облачными вызовами шагов секреты скрываются по правилам темы 4.1. (FR-15)
  7. Все шаги выполнены — итог в чате. (FR-08; результат BP-06)
- **Альтернативные потоки:**
  - А1 (остановка пользователем) — UC-04 (FR-10, FR-13).
  - А2 (сбой провайдера) — UC-05 (FR-12).
  - А3 (цикл) — UC-06 (FR-11).
  - А4 (заблокированная память): вызовы, которым нужна память, отклоняются — BP-15 (краевые состояния).
  - А5 (офлайн): облачные провайдеры недоступны, локальные модели работают — BP-02, шаг 8, темы 4.3, 4.8
    (краевые состояния); для цепочки отдельно не описано (BP-06.1, «Область вне требований»).
  - А6 (закрытие окна во время цепочки): цепочка продолжает выполняться в фоне (FR-08; решение владельца,
    20.11.2026).
- **Постусловие:** цепочка выполнена, итог в чате; или цепочка остановлена с понятной причиной.
- **Трассировка:** UC-03 → FR-07, FR-08, FR-09, FR-14, FR-15 (тема 4.1) → BP-06, шаги 4–5; результат.

## UC-04. Остановить цепочку

- **Актор:** Пользователь (останавливает), Система (останавливает и помечает).
- **Предусловие:** цепочка выполняется (UC-03).
- **Основной поток:**
  1. Пользователь останавливает цепочку. (FR-10)
  2. Система прекращает выполнение шагов. (FR-10)
  3. Шаг помечается понятной причиной остановки. (FR-13)
  4. Цепочка не «зависает» и не продолжается молча. (FR-13)
- **Альтернативные потоки:**
  - А1 (остановка между шагами): следующий шаг не запускается (допущение: остановка действует на цепочку
    в целом, а не только на текущий шаг).
  - А2 (частичные результаты): что видит пользователь после остановки (итог, частичные результаты) —
    не описано (BP-06.1, «Область вне требований»).
  - А3 (причина «цикл»): остановка по защите от зацикливания — UC-06 (FR-11).
  - А4 (причина «сбой провайдера» без замены): шаг помечается с причиной — UC-05, А1 (FR-12, FR-13).
- **Постусловие:** цепочка остановлена; причина показана понятно; прерванный шаг помечен; итог — в чате
  (результат BP-06).
- **Трассировка:** UC-04 → FR-10, FR-11, FR-12, FR-13 → BP-06, шаги 5–6; результат.

## UC-05. Сбой провайдера на шаге (фолбэк)

- **Актор:** ИИ-исполнитель (вызов не удался), Система (заменяет и помечает), Пользователь (видит
  причину).
- **Предусловие:** цепочка выполняется (UC-03); провайдер исполнителя отказал: упал / лимит / нет денег /
  ключ отклонён (тема 4.3; краевые состояния).
- **Основной поток:**
  1. Вызов исполнителя на шаге не удаётся. (FR-12)
  2. Система показывает сообщение с причиной сбоя. (FR-12)
  3. Система подменяет исполнителя шага (фолбэк на другого исполнителя). (FR-12)
  4. Шаг повторяется с новым исполнителем (допущение: порядок «фолбэк → повтор шага» — BP-06.1, «Область
     вне требований»; BP-06.4, раздел 1).
  5. Отказавший провайдер помечается нерабочим и не попадает в списки моделей. (FR-12; тема 4.3)
- **Альтернативные потоки:**
  - А1 (замены нет): шаг помечается с причиной, цепочка не «зависает» и не продолжается молча (FR-13;
    допущение — BP-06.4, раздел 1).
  - А2 (повторный сбой у замены): поведение не описано (BP-06.1, «Область вне требований»).
  - А3 (таймаут вызова): вызов дольше 300 с завершается по лимиту (FR-14; тема 4.3).
  - А4 (остановка во время сбоя): пользователь останавливает цепочку — UC-04 (FR-10).
  - А5 (локальная модель): сбой облачного провайдера не затрагивает локальных исполнителей (тема 4.3;
    краевые состояния — офлайн).
- **Постусловие:** шаг выполнен другим исполнителем — или шаг помечен с причиной; отказавший провайдер —
  нерабочий.
- **Трассировка:** UC-05 → FR-10, FR-12, FR-13, FR-14 → BP-06, шаги 5–6; тема 4.3; краевые состояния.

## UC-06. Защита от зацикливания (цикл)

- **Актор:** ИИ-исполнитель (повторяет действие), Система (останавливает шаг), Пользователь (видит
  причину).
- **Предусловие:** цепочка выполняется (UC-03); исполнитель на шаге выполняет действия (механика —
  BP-04).
- **Основной поток:**
  1. Исполнитель на шаге повторяет одно и то же действие. (FR-11)
  2. Действие повторено три раза подряд. (FR-11; действующие лимиты)
  3. Система останавливает шаг с причиной «цикл». (FR-11)
  4. Шаг помечается с причиной; цепочка не «зависает» и не продолжается молча. (FR-13)
- **Альтернативные потоки:**
  - А1 (лимит действий): на шаге схемы — до 80 действий; при превышении шаг останавливается с сообщением
    «Слишком много действий подряд — шаг остановлен» (FR-14; решение владельца, 20.11.2026); исчерпание
    лимита 12 действий в чате остаётся открытым (BP-04).
  - А2 (карточка разрешения): действия, требующие «да», ожидают решения не более 600 с по правилам BP-04
    (FR-14).
  - А3 (остановка пользователем раньше цикла): UC-04 (FR-10).
- **Постусловие:** шаг остановлен с причиной «цикл»; цепочка остановлена; причина показана понятно.
- **Трассировка:** UC-06 → FR-10, FR-11, FR-13, FR-14 → BP-06, шаги 5–6; действующие лимиты; BP-04, шаг 5.

## UC-07. Править шаги и исполнители до запуска

- **Актор:** Пользователь (правит вариант), Система (принимает правки).
- **Предусловие:** варианты предложены (UC-01); цепочка ещё не запущена (FR-16).
- **Основной поток:**
  1. Пользователь открывает предложенный вариант и правит шаги и исполнителей. (FR-16)
  2. Система принимает правки: изменённые шаги и исполнители сохраняются в варианте. (FR-16)
  3. Пользователь запускает отредактированный вариант — UC-03. (FR-16, FR-08)
- **Альтернативные потоки:**
  - А1 (исполнитель): исполнитель выбирается из подключённых ИИ (FR-01).
  - А2 (длина цепочки): после правок длина цепочки — в лимитах: до 6 шагов, «Качественно» — до 5 (FR-03).
- **Постусловие:** вариант отредактирован; запуск выполняет отредактированную цепочку.
- **Трассировка:** UC-07 → FR-01, FR-03, FR-08, FR-16 → BP-06, шаги 1–2, 5; решение владельца, 20.11.2026.
