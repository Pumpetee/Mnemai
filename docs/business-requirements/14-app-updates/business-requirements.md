# BP-14.1. Бизнес-требования: обновления приложения

## Цель

Доставка новых версий приложения: тихая проверка релизов, кнопка Update, установка по ОС и проверка
целостности; при несовпадении контрольной суммы или сбое обновление не применяется.

## Бизнес-результат

Установлена новая версия — или обновление безопасно не применено.

## Требования

- Система должна тихо (в фоне) проверять наличие новых релизов при каждом запуске приложения и при нажатии кнопки Update.
- Система должна показывать кнопку Update, когда доступна новая версия.
- Система должна начинать установку обновления по нажатию кнопки Update.
- Система должна на Windows устанавливать обновление при выходе из приложения.
- Система должна на Linux заменять установочный файл новой версией и перезапускать приложение.
- Система должна на macOS открывать образ установки новой версии и показывать инструкцию по установке в окне.
- Система должна проверять целостность обновления по контрольной сумме: основной источник — метаданные
  релиза, запасной вариант — отдельный файл контрольной суммы.
- Система должна не применять обновление при несовпадении контрольной суммы, сбое установки или сбое самой проверки; при сбое проверки цикл пропускается без установки.

## Бизнес-правила

- Проверка релизов выполняется в фоне при каждом запуске приложения и по нажатию кнопки Update; канал проверки стабильный.
- Источник релизов — GitHub-релизы; бета-каналы не предусмотрены.
- Установка выполняется по правилам своей ОС: Windows — при выходе, Linux — замена установочного файла и перезапуск, macOS — открытие образа установки с инструкцией по установке в окне.
- Целостность проверяется до применения; при несовпадении суммы или сбое обновление не применяется, приложение остаётся на текущей версии; при сбое самой проверки цикл пропускается без установки.
- Откат на прежнюю версию выполняется переустановкой приложения.
- Пользователь не вводит системных идентификаторов: установку запускает кнопка Update.

## Область вне требований

- Выпуск релизов: версии выпускаются партиями, выпуск новой версии — только по прямой просьбе владельца;
  здесь не описывается.
- Выход из приложения, трей и автозапуск описываются правилами жизненного цикла окна (закреплены за
  BP-01 и BP-12); настройки — BP-12; синхронизация — BP-13; данные пользователя — BP-16.
