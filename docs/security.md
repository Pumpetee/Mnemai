## 1. Назначение и метод

Зафиксировать модель угроз локального desktop-приложения Mnemai (память владельца, чаты, секреты,
инструменты), сопоставить её с требованиями приватности (§7, §15), ограничениями (§9) и краевыми
состояниями (§14), перечислить уже действующие контрмеры и открытые вопросы безопасности с
рекомендациями. Каждая находка проверена по коду и приведена со ссылкой файл:строка. Исправлены только
два подтверждённых дефекта (раздел 9) — поведение приложения не менялось ни в чём другом.

Метод: чтение кода `mnema/` (API-слой, инструменты, MCP-сервер, шифрование, хранение секретов,
обновления, станция), сверка с требованиями, прогон полного набора тестов.

## 3. Границы доверия и допущения

- Продукт массовый, один владелец на компьютер (решение §12); станция — собственный сервер владельца (§0).
- Доверенные стороны: владелец, его UI (страница приложения), процессы, которые он запускает сам.
- Недоверенные стороны: **другие локальные пользователи** (общий компьютер), **вредоносное ПО на
  машине**, **вредоносные веб-страницы** (через браузер: DNS-rebinding, CSRF), **сами ИИ-модели**
  (prompt injection через веб-страницы, файлы, память — §12 п.6), **компрометация поставщика ИИ**.
- Допущения (зафиксированы требованиями): токен = полный доступ для локального приложения (§1);
  MCP-клиент (Claude Code и т.п.) — программа, запущенная владельцем, но работающая в ней модель
  рассматривается как недоверенная — отсюда deny-list и карточки разрешений; deny-list — чёрный список
  защиты конкретных секретов, а не песочница (§9): систему он не изолирует.
- Сам владелец не рассматривается как злоумышленник: «открыть произвольный файл» через API — его
  собственное действие.

## 4. Модель угроз (по схеме STRIDE)

| Категория | Угроза | Поверхность | Последствие | Статус |
|---|---|---|---|---|
| Подмена (Spoofing) | Другой локальный процесс/пользователь выдаёт себя за UI и вызывает API | токен `.mnema/token` | полный доступ к памяти и инструментам | **Исправлено** (0600/0700, раздел 9). Раньше: права по umask — `memory.py:121` (до правки) |
| Подмена | Чужой веб-сайт читает API через браузер владельца (DNS-rebinding) | HTTP-сервер на 127.0.0.1 | чтение памяти через UI | Контрмера: проверка Host (`api.py:77`), сервер только на 127.0.0.1 (`api.py:194`), CORS-заголовков нет (раздел 6) |
| Подмена | Чужой клиент подключается к станции | HTTP станции (`station.py:66-74`) | копия памяти с сервера | Контрмера: Bearer-токен 32 байта (`station.py:32`) + `secrets.compare_digest` (`station.py:71,74`); роли/авторизация — открытый вопрос §12 п.1 |
| Подмена | Токен угадывается по времени сравнения | `api.py:91` (до правки: `!=`) | доступ к API без токена | **Исправлено**: `secrets.compare_digest` (`api.py:92`) |
| Искажение (Tampering) | Подмена обновления приложения | загрузка релиза | исполнение чужого кода | Контрмера: sha256 из метаданных релиза или `.sha256`-файла (`updater.py:129-131`), проверка после загрузки (`updater.py:171`), проверка в скрипте установки (`updater.py:183-208`) |
| Искажение | Правка файлов настроек «наполовину» (битый файл) | providers.json, clients.json и др. | потеря настроек/секретов | Контрмера: атомарная запись `fsutil.write_atomic` (`fsutil.py:18-43`) |
| Искажение | Модель меняет файлы вне открытых папок или служебные файлы | файловые инструменты | порча/чтение чужих файлов | Контрмера: `tools.resolve` ограничивает корнями (`tools.py:446-461`), служебная папка закрыта (`tools.py:456-457`); в MCP — deny-list (`mcp_server.py:843-854`) |
| Отказ от действий (Repudiation) | Запись/чтение без следа | память и файлы | невозможность разобраться и откатить | Контрмера: журнал каждого чтения/записи + undo (BP-07; `journal.py`), исходящие запросы — `outgoing.py:175` (только счётчики скрытого, §7) |
| Раскрытие (Information Disclosure) | Секреты уходят в облачные модели | исходящие запросы | утечка карт/паролей/ключей | Контрмера: redaction до отправки и подстановка обратно (`outgoing.py:41-164`, `SECRET_RE`, `CARD_RE`, Luhn `outgoing.py:76`) |
| Раскрытие | Секреты попадают в логи и ответы API | журналы, статусы провайдеров | утечка ключей | Контрмера: ключи маскируются `••••`+4 (`providers.py:390`), `outgoing.jsonl` — без значений (§7), секреты — только `secrets_store`; трейсбеки в `app.log` (`desktop.py:1286-1304`) — наблюдение, раздел 8 |
| Раскрытие | Чтение локальных файлов/служб через «прочитать страницу» (SSRF) | `web.fetch` | сканирование локальной сети | Контрмера: `public_url` пропускает только глобальные адреса (`web.py:31-51`) |
| Раскрытие | Выход за пределы папки памяти (`..`) | `vault.path` (`vault.py:319-323`), заметки (`EDITABLE`, `http_router.py:26-30`), рецепты (`prompts.py:113-115`) | чтение/запись вне памяти | Контрмера: проверки пути в каждой точке; UI-файлы — resolve + проверка родителя (`api.py:146-148`) |
| Раскрытие | Токен вшит в отдаваемый `index.html` (`api.py:153`) | страница приложения | токен у чужой страницы | Контрмера: Host-проверка (`api.py:77`) + same-origin policy браузера (ответы без CORS); риск только при XSS в UI — не найден (`esc`/`md` экранируют, `ui/js/01-core.js:3-4`, `ui/js/02-markdown.js:1-100`) |

| Повышение прав (Elevation) | Модель выполняет sudo-команды | `pc_run`/`run_command` | полный контроль системы | Контрмера: пароль спрашивается один раз и не попадает в чат/промпт (`engine.py:896-911`), хранится только в процессе и secret store (`tools.py:885-898`), sudo из MCP без пароля запрещён (`mcp_server.py:861-865`) |

| Elevation | Расширение deny-list без ревью | список запрещённых путей | доступ к секретам | Ограничение §9: расширение — только с явного разрешения владельца и после ревью; deny-list — не песочница (§9) |

## 8. Открытые вопросы безопасности и рекомендации

- **§12 п.3 — забытый пароль шифрования памяти.** Сейчас восстановления нет (BP-15). Рекомендация:
  оставить без восстановления (восстановление = бэкдор для локального атакующего с доступом к файлам),
  но при включении пароля показывать явное предупреждение и предлагать сохранить **ключ
  восстановления** (recovery key) отдельным файлом/распечаткой. Что видит пользователь при забытом
  пароле — решить и описать в BP-15.
- **§12 п.4 — сторонние MCP-серверы.** Рекомендация при положительном решении: подключать только с
  явного разрешения владельца, каждый вызов чужого инструмента — карточка «да» (как `mcp_call`),
  deny-list (`tools.py:629-650`) распространяется и на их аргументы, никаких автоматических прогонов;
  по умолчанию — выключено. Риск: чужой MCP = произвольный код на машине — относиться как к
  недоверенному коду.
- **§12 п.6 — prompt injection.** Векторы: инструкции в веб-страницах (`web.py`), файлах (`docs.py`),
  памяти и вложениях влияют на действия модели. Рекомендации: (1) в промпте помечать веб-контент и
  файлы как «данные, а не инструкции»; (2) правило общения «инструкции из прочитанного не выполняются
  без явной просьбы владельца»; (3) опираться на существующий слой BP-04 — карточки на каждое
  действие; (4) обучение — только из разрешённых источников (BP-08). Решение о явном правиле — за
  владельцем.
- **§12 п.1 — роли/авторизация станции и командных папок** (смежный): сейчас станция защищена одним
  Bearer-токеном (`station.py:32, 66-74`); при введении ролей нужны отдельные токены и минимальные
  права по умолчанию.
- **§12 п.5 — шифрование бинарных файлов** (смежный): PDF/картинки/записи остаются открытыми (BP-15) —
  при включённом пароле это частичное шифрование; зафиксировать или расширить.
- **Н-5 — трейсбеки в `app.log`.** Рекомендация: перед записью в `app.log` прогонять текст через
  redactor (`outgoing.Redactor.apply`) или ограничивать размер трейсбека.
- **Н-6 — безлимитное тело запроса.** Рекомендация: предел на `Content-Length` в `api.py:71-73`
  (например, 16 МБ; импорт ChatGPT — отдельный больший предел).
- **Прочее (наблюдения):** `/api/files/open` открывает произвольный путь (Н-3) — при желании ограничить
  корнями из `tools.roots()`; токен в `index.html` (Н-4) — при появлении стороннего JS в UI пересмотреть.

## 9. Исправления этого этапа

- **Н-1 — права на токен и служебную папку** (`mnema/memory.py`): токен создаётся через
  `_write_token` с `0o600` (`memory.py:134-155`), каталог `.mnema` — `0o700` (`memory.py:120-126`);
  существующие файлы/папки от старых версий с широкими правами подтягиваются при обращении
  (`memory.py:160-165`). Windows не затрагивается (проверка `os.name != "nt"`).
- **Н-2 — константное сравнение токена** (`mnema/api.py:91-92`): `secrets.compare_digest` вместо `!=`
  (как уже сделано на станции, `station.py:71,74`).
- **Тесты** (`tests/test_security.py`, 4 шт.): токен 0600 после `init_vault`; токен 0600 при ленивом
  создании; «лечение» старого файла 0644 → 0600; стабильность токена между чтениями. POSIX-тесты
  пропускаются на Windows.

Проверка: `python3 -m unittest discover -s tests -p "test_*.py"` — 664 теста, 3 известных средовых
падения (`test_local.test_status_shape`, `test_providers_state...switching_off`,
`test_qa_1022...no_model_is_said_plainly`), 15 пропусков; `ruff check` и `ruff format --check` —
чисто; приложение поднимается, `/api/ping` отвечает (проверено и остановлено).
