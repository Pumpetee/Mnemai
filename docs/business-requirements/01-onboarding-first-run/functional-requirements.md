# BP-01.2. Функциональные требования: онбординг и первый запуск

## 1. Визард (BP-01, шаг 1)

### FR-01 — Открытие визарда
Система должна при первом запуске без памяти открыть визард онбординга из четырёх шагов в фиксированном порядке: тема (светлая/тёмная) → язык → «как к тебе обращаться» → память.
**Приёмка:** при запуске без созданной памяти открывается визард; шаги следуют в указанном порядке; после завершения система переходит к предложению подключить первый ИИ (FR-08). Если визард закрыт до завершения, при следующем запуске без памяти он начинается заново (решение владельца 20.11.2026).
(BP-01, шаг 1; раздел 8)

### FR-02 — Выбор темы
Система должна на первом шаге дать выбрать тему: светлую или тёмную.
**Приёмка:** доступны ровно два варианта; выбранная тема применяется к интерфейсу; позже тему можно сменить через настройки (FR-09; см. BP-12).
(BP-01, шаг 1; раздел 8)

### FR-03 — Выбор языка
Система должна на шаге «язык» дать выбрать язык интерфейса из девяти доступных.
**Приёмка:** выбор — из девяти языков; интерфейс отображается на выбранном языке; язык общения фиксируется в профиле, ответы ИИ следуют выбранному языку (тема 4.5 каталога).
(BP-01, шаг 1; раздел 8; тема 4.5)

### FR-04 — Обращение к пользователю
Система должна на шаге «как к тебе обращаться» принять обращение (и имя) пользователя; при создании памяти обращение и имя сохраняются в профиль, изменить их можно в настройках.
**Приёмка:** введённые обращение и имя сохраняются в профиль при создании памяти; их можно изменить через настройки (FR-09; см. BP-12).
(BP-01, шаг 1; раздел 8, сохранение выбора онбординга)

## 2. Память (BP-01, шаги 2–3)

### FR-05 — Создать или открыть память
Система должна на шаге «память» предложить создать новую папку памяти или открыть существующую; создание структуры папки — по правилам BP-07.
**Приёмка:** доступны оба варианта; при создании структура папки создаётся по правилам BP-07; при открытии используется указанная пользователем существующая папка.
(BP-01, шаг 2; раздел 8)

### FR-06 — Путь памяти по умолчанию
Система должна при создании новой памяти предлагать путь по умолчанию в домашней папке пользователя (папка Mnemai).
**Приёмка:** предлагаемый путь по умолчанию — домашняя папка пользователя; вместо создания пользователь может открыть существующую папку (FR-05).
(BP-01, шаг 2; разделы 1, 8)

### FR-07 — Пароль шифрования (необязательно)
Система должна на шаге «память» предложить задать пароль шифрования как необязательный.
**Приёмка:** пароль можно задать или пропустить; при задании дальнейшее поведение — по правилам BP-15 (шифрование, блокировка, восстановление по ключу восстановления).
(BP-01, шаг 3; раздел 8)

## 3. Подключение первого ИИ (BP-01, шаг 4)

### FR-08 — Первый ИИ и состояние «нет ИИ»
Система должна после визарда предложить подключить хотя бы один ИИ; пока не подключён ни один, чат не отправляет запрос, объясняет причину и ведёт в настройки, а память, журнал и команды без модели продолжают работать.
**Приёмка:** после визарда есть предложение подключить ИИ; при отсутствии ИИ чат объясняет причину и ведёт в настройки (см. BP-02, шаг 7), при этом память, журнал и команды без модели работают (тема 4.4); подключение первого ИИ выполняется в рамках BP-01, детальная настройка провайдеров — BP-12.
(BP-01, шаг 4; раздел 14)

## 4. Возврат к шагам и пустая память (BP-01, шаги 5–6)

### FR-09 — Возврат к любому шагу через настройки
Система должна позволять вернуться к любому шагу визарда (тема, язык, обращение, память) через настройки.
**Приёмка:** из настроек доступны все четыре выбора онбординга; изменение применяется по правилам BP-12.
(BP-01, шаг 5; раздел 8)

### FR-10 — Пустая память без ошибок
Система должна при первом запуске с пустой памятью показывать пустые списки и подсказки вместо ошибок.
**Приёмка:** при пустой памяти разделы интерфейса показывают пустые списки и подсказки, сообщений об ошибках нет.
(BP-01, шаг 6; раздел 14)

## 5. Жизненный цикл первого окна (тема 4.7 каталога — закреплена за BP-01)

### FR-11 — Один экземпляр приложения
Система должна работать в одном экземпляре на пользователя: повторный запуск показывает первое окно; при запуске с созданной памятью визард не открывается.
**Приёмка:** повторный запуск при работающем приложении открывает существующее окно; онбординг не перезапускается, если память уже создана.
(тема 4.7; раздел 8)

### FR-12 — Восстановление окна после сбоя
Система должна при падении страницы перезагрузить её сама (нарастающие паузы, затем раз в минуту) и восстановить неотправленный текст из черновика.
**Приёмка:** после сбоя страница перезагружается без участия пользователя; неотправленный текст восстанавливается. Сейчас — только Linux; на Windows и macOS — заложено (раздел 9).
(тема 4.7; раздел 8)

### FR-13 — Контроль памяти окна
Система должна проверять потребление памяти окна раз в 30 с: выше 1500 МБ — запись в лог, выше 3000 МБ — перезапуск страницы.
**Приёмка:** пороги срабатывают как описано; после перезапуска работа продолжается. Сейчас — только Linux (раздел 9).
(тема 4.7; разделы 8, 10)

## 6. SLA первого запуска (раздел 10; тема 4.8 каталога — буллет закреплён за BP-02/BP-06)

### FR-14 — Холодный старт при первом запуске
Система должна открывать готовое окно при холодном старте не более чем за 5 с — предлагаемая цель SLA, числа подтверждаются замерами.
**Приёмка:** после подтверждения чисел замерами (раздел 12, пункт 2) время холодного старта до готового окна не превышает 5 с.
(раздел 10 — предлагаемая цель SLA; в каталоге буллет «холодный старт» закреплён за BP-02/BP-06 (тема 4.8), для BP-01 — ограничение первого запуска)
