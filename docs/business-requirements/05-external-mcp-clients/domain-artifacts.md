# BP-05.4. Артефакты предметной области: внешние MCP-клиенты


## 1. Модель состояний вызова инструмента внешним клиентом

```
Внешний MCP-клиент подключается (триггер BP-05)
        │
        ▼
Подключён (отдельное MCP-подключение; BP-05, шаг 1; FR-01)   [жизненный цикл подключения — допущение]
        │ ИИ клиента запрашивает инструмент (FR-02)
        ▼
Запрошено ──► проверка прав клиента: скоупы чтения/записи, скрытые теги (BP-05, шаг 2; FR-03, FR-04)
        ├─ вне прав ──► Отклонено (вне прав) ──► отказ клиенту (FR-05)
        ├─ запрещённый путь (тема 4.1; FR-08) ──► Отклонено (всегда, ни при каком разрешении)
        ├─ память заблокирована (BP-15) ──► Отклонено с запросом пароля (FR-13)
        ├─ офлайн ──► только локальные модели (FR-14)
        └─ в рамках прав ──► Ждёт «да» (всегда, независимо от тумблера чата; BP-05, шаг 3; FR-06)
                ├─ «нет» ──► Отклонено ──► отказ клиенту (FR-05)
                └─ «да» ──► Исполняется (в пределах прав; записи — в журнал, BP-07) ──► Выполнено
                        └─► результат возвращён клиенту (результат BP-05; FR-05)

Целевое состояние (BP-05, шаг 4; FR-09, FR-12): весь инструментальный слой — единый каталог
MCP-инструментов; блоки ```mnema остаются до полного перехода, после перехода удаляются
[решение владельца, 20.11.2026]
```

| Переход | Откуда → куда | Правило |
|---|---|---|
| Подключение клиента | — → Подключён | BP-05, шаг 1; FR-01 (жизненный цикл подключения/отключения — допущение) |
| Запрос инструмента | Подключён → Запрошено | Триггер BP-05; FR-01, FR-02 |
| Вне прав | Запрошено → Отклонено (вне прав) | BP-05, шаг 2; FR-03 |
| Запрещённый путь | Запрошено → Отклонено (всегда) | BP-05, шаг 1 — «см. BP-04»; FR-08; тема 4.1 |
| Ожидание «да» | Запрошено → Ждёт «да» (всегда) | BP-05, шаг 3; FR-06 |
| «да» | Ждёт «да» → Исполняется | BP-05, шаг 3; FR-06, FR-05 |
| «нет» | Ждёт «да» → Отклонено | BP-05, шаг 3; FR-06, FR-05 |
| Исполнение | Исполняется → Выполнено; результат клиенту | Результат BP-05; FR-05 |
| Отмена записи | Выполнено → Отменено (через «Историю») | FR-05; BP-07, BP-11 (тема 4.2) |
| Таймаут «да» | Ждёт «да» → ожидание прекращено (600 с — BP-04; дальнейшее не описано) | FR-06; BP-04; тема 4.8 |
| Проверочный прогон | Запрошено → Ждёт «да» (всегда) → Исполняется → Завершён (записи удалены, буфер обмена восстановлен) | BP-05, шаг 3; FR-06, FR-07; BP-04, шаг 7 |
| Заблокированная память | Запрошено → Отклонено с запросом пароля | FR-13; BP-15 (решение владельца, 20.11.2026) |
| Офлайн | Запрошено → обслужено локальной моделью | FR-14; крайние состояния (решение владельца, 20.11.2026) |
| Целевое состояние | текущее состояние → единый каталог MCP-инструментов (блоки ```mnema — до полного перехода, после перехода удаляются) | BP-05, шаг 4; FR-09, FR-12; решение владельца, 20.11.2026 |

## 2. Сущности, состояния и переходы

### 2.1 Внешний MCP-клиент

| Поле | Значение |
|---|---|
| Определение | Программа-клиент, в которой работает ИИ и которая подключается к инструментам Mnemai через MCP: Claude Code, Claude Desktop, Cursor «и другие» (вводные про MCP, инструменты; «и другие» — уточнение CLIENT_JOURNEY, раздел 2.3 («и т.п.»), ARCHITECTURE.ru, раздел «Процессы»; каталог BP-05, «Акторы») |
| Атрибуты | Свои скоупы чтения (2.3); свои скоупы записи (2.3); скрытые теги (2.4) (инструменты; тема 4.1); права задаёт пользователь — BP-12, шаг 4 |
| Состояния | Не подключён → Подключён → Не подключён (жизненный цикл подключения — допущение: источниками не описан) |
| Переходы | Подключиться через отдельное MCP-подключение (FR-01); отключиться (допущение) |
| Идентификаторы | Системные id генерирует система (каталог, раздел 1); человекочитаемых кодов нет (каталог, раздел 6) |

### 2.2 MCP-подключение (MCP-сервер)

| Поле | Значение |
|---|---|
| Определение | Отдельный MCP-сервер поверх stdio, через который внешние клиенты получают инструменты Mnemai (вводные про MCP «сейчас»; инструменты; каталог BP-05, шаг 1); архитектурная сверка — ARCHITECTURE.ru, раздел «Процессы» |
| Правила | Каталог 56 инструментов доступен как MCP-инструменты (BR-06; FR-02); каждый вызов — только с «да» (BR-03; FR-06); права клиентов применяются (BR-02); deny-list применяется (BR-05); сторонние MCP-серверы как источники инструментов не поддерживаются (FR-11) |
| Целевое состояние | Единый слой: весь инструментальный слой — единый каталог MCP-инструментов; блоки ```mnema остаются до полного перехода, после перехода удаляются (BR-07; FR-09, FR-12; решение владельца, 20.11.2026) |

### 2.3 Скоуп чтения / записи

| Поле | Значение |
|---|---|
| Определение | Скоуп — раздел памяти: профиль, правила, проекты, карточки, люди, решения, входящие, заметки (словарь терминов; перечень — BP-07, память). У внешнего клиента — свои скоупы чтения и свои скоупы записи (инструменты) |
| Правила | Клиент читает только разрешённые части памяти и пишет только в разрешённые (FR-03); правило одно для чата и внешних MCP-клиентов (тема 4.1); настройка чек-боксами по частям памяти — BP-12 (тема 4.1) |
| Допущение | Взаимное соотношение скоупов чтения и записи (например, запись шире чтения) источниками не описано; вызов вне соответствующего скоупа отклоняется (FR-03) |

### 2.4 Скрытые теги

| Поле | Значение |
|---|---|
| Определение | Теги, которые клиент не видит никогда (инструменты «скрытые теги»); названы `#money`, `#health`, `#private` (память); замок на тему — тема 4.1 |
| Правила | Содержимое со скрытыми от клиента тегами клиенту не отдаётся (FR-04); факт-архив не отдаётся никогда (память; BP-07); настройка — BP-12 (тема 4.1) |
| Допущение | Полный перечень возможных скрытых тегов источниками не приведён (названы только три) |

## 3. Правила процесса

- **Правило отдельного подключения.** Инструменты Mnemai доступны внешним клиентам через отдельное
  MCP-подключение, а не через блоки ```mnema чата (BP-05, шаг 1; BR-01).
- **Правило прав клиента.** У каждого клиента свои скоупы чтения/записи и скрытые теги — то же правило,
  что в чате; задаёт права пользователь (BP-05, шаг 2; BR-02; BP-12).
- **Правило обязательного «да».** Каждый вызов инструмента внешним клиентом и каждый проверочный прогон —
  отдельное «да» всегда; «Да для этого разговора» не применяется (BP-05, шаг 3; BR-03).
- **Правило выполнения и результата.** Инструмент выполняется в пределах прав запросившего клиента; исход —
  выполнение или отказ — возвращается клиенту (результат BP-05; BR-04).
- **Правило deny-list.** Запрещённые пути недоступны ни при каком разрешении; расширение — только с явного
  разрешения пользователя и после ревью (BP-05, шаг 1 — «см. BP-04»; BR-05; ограничения; тема 4.1).
- **Правило каталога.** Внешним клиентам доступен каталог 56 инструментов указанных групп, не считая
  служебного списка (BP-05, шаг 4; BR-06; инструменты).
- **Правило целевого состояния.** Весь инструментальный слой — единый каталог MCP-инструментов; ИИ
  подключаются только своим MCP-клиентом; параллельных механизмов не остаётся (BP-05, шаг 4; BR-07; вводные про MCP).
- **Правило источников инструментов.** Сторонние MCP-серверы как источники инструментов не поддерживаются;
  инструменты даёт только собственный MCP-сервер Mnemai (решение владельца, 20.11.2026; FR-11).
- **Правило перехода.** Блоки ```mnema остаются до полного перехода к цели «вся программа — MCP»; после
  перехода блоки удаляются (решение владельца, 20.11.2026; FR-12).
- **Правило заблокированной памяти.** Вызовы, которым нужна память, отклоняются с запросом пароля — как
  BP-15 (решение владельца, 20.11.2026; FR-13).
- **Правило офлайна.** В офлайне вызовы внешних клиентов обслуживаются только локальными моделями (решение
  владельца, 20.11.2026; FR-14).
- **Правило скрытия секретов.** К исходящим облачным запросам, связанным с работой внешних клиентов,
  применяются единые правила темы 4.1; механизм применения к внешним клиентам — пробел (BR-08; тема 4.1;
  BP-05.1, «Область вне требований»).
