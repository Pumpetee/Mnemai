# BP-12.2. Функциональные требования: настройки

Каждое требование сформулировано как «Система должна…», без технических деталей; шаги чужих процессов и
сквозных тем не дублируются — только ссылки на процессы каталога. В скобках после требования — источник:
шаг BP-12 или описание процесса во вводных. Факты, которые вводные не задают, отмечены ссылкой на BP-12.1
(«Область вне требований») или словом «допущение».

## 1. Сохранение и применение (назначение и результат BP-12)

### FR-01 — Сохранение и применение настроек
Система должна сохранять изменения настроек и применять их в чате, обучении, инструментах и интерфейсе.
**Приёмка:** изменённая настройка сохранена и действует в чате, обучении, инструментах и интерфейсе
(результат BP-12); какие настройки требуют перезапуска — источники не описывают: допущение — применяются
сразу, без перезапуска (BP-12.1, «Область вне требований»).
(Назначение и результат BP-12; приложение и жизненный цикл)

## 2. ИИ и модели (BP-12, шаг 1; тема 4.3)

### FR-02 — Подключение ИИ: подписки, ключи, локальные модели, Harness-агент
Система должна давать подключать ИИ всех типов: подписки Claude (Claude Code) и ChatGPT (Codex), ключи
API, локальные модели (встроенная, Ollama, Strata), Harness-агент.
**Приёмка:** подключение доступно для каждого типа (описание чата); использование подключённых ИИ —
BP-02, BP-03, BP-06 (тема 4.3); хранение ключей — по правилам темы 4.1, BP-16; подключение первого ИИ
(визард) — BP-01.
(BP-12, шаг 1; описание чата; тема 4.3)

### FR-03 — Проверка работоспособности и списки моделей
Система должна проверять работоспособность подключения и показывать списки моделей по правилам темы 4.3.
**Приёмка:** проверка запускается для подключения; по правилам темы 4.3 нерабочий провайдер (упал / лимит
/ нет денег / ключ отклонён) получает сообщение с причиной, помечается нерабочим и не попадает в списки
моделей; что именно видит пользователь при неудачной проверке в BP-12, детально не описано (BP-12.1,
«Область вне требований»); сверка с описанием клиентского пути (настройки): проверка и списки моделей — в
составе настроек.
(BP-12, шаг 1; тема 4.3; описание чата)

## 3. Движок и лимиты (BP-12, шаг 2; тема 4.8)

### FR-04 — Движок и лимиты через пресеты
Система должна давать настраивать движок через пресеты «Быстрый», «Сбалансированный», «Качественный»;
числа лимитов настраиваются в продвинутом разделе настроек.
**Приёмка:** доступны три пресета — «Быстрый», «Сбалансированный», «Качественный» (решение владельца,
20.11.2026); числа лимитов настраиваются в продвинутом разделе (решение владельца, 20.11.2026);
действующие лимиты (вызов провайдера, действия, ожидания, live-статусы) — тема 4.8, действующие лимиты;
конкретные значения чисел лимитов — целевые показатели, подтверждаются замерами.
(BP-12, шаг 2; действующие лимиты; тема 4.8; решения владельца, 20.11.2026)

## 4. Правила общения (BP-12, шаг 3)

### FR-05 — Каталог правил общения с тумблерами
Система должна вести каталог правил общения с тумблерами по темам: как говорить, работа с задачей, факты,
память, приватность, оформление; правила участвуют в сборке ответа.
**Приёмка:** каждая тема правил включается и выключается тумблером; включённые правила попадают в сборку
ответа (BP-02, шаг 2); полный перечень правил внутри тем и значения по умолчанию не приведены (BP-12.1,
«Область вне требований»).
(BP-12, шаг 3; описание чата; BP-02)

## 5. Память и приватность (BP-12, шаг 4)

### FR-06 — Доступы ИИ по частям памяти и скрытые теги
Система должна давать задавать доступы ИИ: чек-боксы по частям памяти (чтение/запись) и скрытые теги с
замком на тему; локальная модель видит всё.
**Приёмка:** доступы чтения и записи задаются чек-боксами по частям памяти; темы скрываются замком
(приватность и безопасность); правило доступов едино для чата и внешних MCP-клиентов (тема 4.1);
применение доступов — тема 4.1, BP-02, BP-07; скрытые теги `#money`/`#health`/`#private` — описание памяти.
(BP-12, шаг 4; приватность и безопасность; тема 4.1)

### FR-07 — Тумблер разрешений на действия
Система должна давать тумблер разрешений на действия; по умолчанию он выключен (действия выполняются
сразу, отмена — в «Истории»).
**Приёмка:** тумблер есть и по умолчанию выключен (описание чата); поведение тумблера — BP-04 (карточка
«Да / Нет / Да для этого разговора»; вызовы внешних MCP-инструментов и проверочные прогоны спрашивают «да»
всегда).
(BP-12, шаг 4; описание чата; BP-04)

### FR-08 — Настройки обучения: порог автозаписи и кулдаун
Система должна давать настраивать порог автозаписи обучения (по умолчанию 0.8 = 80 %) и кулдаун
повторного вопроса (по умолчанию 10 минут).
**Приёмка:** порог автозаписи настраивается, по умолчанию 0.8 (описание обучения); кулдаун повторного
вопроса настраивается, по умолчанию 10 минут (решение владельца, 20.11.2026; согласовано с BP-08);
применение порогов — BP-08, шаги 4–5.
(BP-12, шаг 4; описание обучения; BP-08; решение владельца, 20.11.2026)

### FR-09 — Дополнительные папки памяти
Система должна давать подключать дополнительные папки памяти (Obsidian-хранилища, командные папки);
поведение папок (только чтение) — BP-07.
**Приёмка:** папка подключается в настройках; чтение — только, запись блокируется (BP-07, шаг 8);
авторизация командных папок — открытый вопрос о ролях станции и командных папок (BP-12.1, «Область вне
требований»).
(BP-12, «Входит» — память; описание памяти; BP-07)

## 6. VPN (BP-12, шаг 5)

### FR-10 — Настройка VPN: автодетект и VPN-ключ
Система должна давать находить рабочий VPN пользователя без ввода данных (автодетект локальных
прокси-клиентов на Windows) либо подключаться по VPN-ключу или ссылке-подписке через встроенный механизм;
локальный прокси — только для Mnemai, система не трогается; при неудачном автодетекте или неверном ключе —
показывать ошибку и предлагать ввести ключ вручную.
**Приёмка:** автодетект доступен на Windows; VPN-ключ или ссылка-подписка принимается и применяется
(приватность и безопасность); при неудачном автодетекте прокси или неверном ключе система показывает
ошибку и предлагает ввести ключ вручную (решение владельца, 20.11.2026); детали механики (перечень
прокси-клиентов, форматы ключей) и хранение ключа — тема 4.1, BP-16.
(BP-12, шаг 5; приватность и безопасность; тема 4.1; решение владельца, 20.11.2026)

## 7. Язык, тема, автозапуск, трей (BP-12, шаги 6–7)

### FR-11 — Девять языков интерфейса и язык общения
Система должна поддерживать девять языков интерфейса и давать задавать язык общения в профиле; ответы
ИИ следуют выбранному языку.
**Приёмка:** доступны девять языков интерфейса (приложение и жизненный цикл; тема 4.5); язык общения
задаётся в профиле (приложение и жизненный цикл); следование ответов выбранному языку — тема 4.5, BP-02;
выбор языка при первом запуске — BP-01.
(BP-12, шаг 6; приложение и жизненный цикл; тема 4.5)

### FR-12 — Тема
Система должна давать переключать тему: светлая/тёмная.
**Приёмка:** тема переключается между светлой и тёмной (приложение и жизненный цикл); выбор темы при
первом запуске — BP-01.
(BP-12, шаг 7; приложение и жизненный цикл)

### FR-13 — Автозапуск
Система должна давать включать и выключать автозапуск.
**Приёмка:** автозапуск — опция, включается и выключается (приложение и жизненный цикл); поведение —
тема 4.7.
(BP-12, шаг 7; приложение и жизненный цикл; тема 4.7)

### FR-14 — Трей
Система должна держать иконку приложения в трее.
**Приёмка:** иконка в трее есть (приложение и жизненный цикл); поведение трея и выхода (выход
останавливает обучение, трей и окно) — тема 4.7; что именно настраивается у трея — не описано (BP-12.1,
«Область вне требований»).
(BP-12, «Входит» — трей; приложение и жизненный цикл; тема 4.7)

## 8. Точки входа в смежные процессы (BP-01, BP-15, BP-16)

### FR-15 — Возврат к шагам онбординга
Система должна давать вернуться к любому шагу онбординга через настройки.
**Приёмка:** шаги визарда доступны из настроек (приложение и жизненный цикл); состав визарда (тема →
язык → обращение → память) — BP-01, шаги 1–5.
(BP-01, шаг 5 — «см. BP-12»; приложение и жизненный цикл)

### FR-16 — Включение пароля шифрования из настроек
Система должна давать включить пароль шифрования памяти из настроек; поведение шифрования — BP-15.
**Приёмка:** пароль включается из настроек (BP-15, «Триггер»: «при создании памяти или в настройках»);
шифрование, блокировка и отсутствие восстановления пароля — BP-15.
(BP-15, «Триггер»; описание памяти; BP-15)

### FR-17 — Удаление секретов из настроек
Система должна давать удалять секреты (ключи API, логин Telegram, VPN-ключи) из настроек; правила
хранения и удаления — тема 4.1, BP-16.
**Приёмка:** секреты удаляются из настроек (BP-16, шаг 4 — «выполняется из настроек (см. BP-12)»); в
журналах секретов нет — только счётчики скрытого (тема 4.1, BP-16); хранение секретов — BP-16, тема 4.1.
(BP-16, шаг 4 — «см. BP-12»; данные пользователя; тема 4.1)

Примечания:

- Тема 4.1 (приватность) каталогом привязана к BP-12 через настройки: доступы ИИ (чек-боксы, замок на
  тему) и VPN — FR-06, FR-10; механика и хранение секретов — по ссылке (BP-16).
- Тема 4.3 (провайдеры и цены): BP-12 настраивает подключения и списки моделей — FR-02, FR-03;
  использование провайдеров — BP-02, BP-03, BP-06.
- Тема 4.5 (локализация): девять языков интерфейса и язык общения — FR-11; следование ответов языку —
  по ссылке (BP-02).
- Тема 4.7 (жизненный цикл): автозапуск и трей — FR-13, FR-14; поведение — по ссылке.
- Тема 4.8 (лимиты): пресеты движка и лимитов — FR-04; действующие лимиты — по ссылке (BP-02, BP-04,
  BP-06).
- Темы 4.2 (журнал/undo — BP-07), 4.4 (команды без модели — BP-02) и 4.6 (достижения) к BP-12 каталогом
  не привязаны; настройки достижений не описаны (BP-12.1, «Область вне требований»).
