# BP-16.3. Сценарии использования: данные пользователя

Цепочка прослеживаемости: сценарий ввода → BP-16 (каталог процессов) → BP-16.1…4 (эта папка). Каждый UC
трассирован «UC → FR → BP-16 шаг»; FR альтернативных потоков включены в трассировку.

## 0. Сценарий ввода → BP-16

Отдельного пути «данные пользователя» в описании клиентского пути нет; его разделы 2.1 и 2.7 подтверждают
хранение ключей в системном хранилище, раздел 2.5 — журнал и отмену (примечание — BP-16.1). Сценарий
покрывается UC-01–UC-08.

## UC-01. Экспортировать память

- **Актор:** Пользователь.
- **Предусловие:** память создана (см. BP-01, BP-07); пользователь хочет экспортировать данные
  (триггер BP-16).
- **Основной поток:**
  1. Пользователь запускает экспорт памяти.
  2. Система выгружает память открытыми Markdown-файлами (папкой). (FR-02)
  3. Данные остаются на компьютере пользователя (FR-01); собственных серверов нет.
- **Альтернативные потоки:**
  - А1 (шифрование): память зашифрована — экспорт памяти запрещён (FR-02; см. BP-15).
  - А2 (повтор): повторный экспорт выгружает актуальную версию (допущение, FR-02).
  - А3 (выход): пользователь отменяет экспорт — ничего не выгружается (FR-02).
- **Постусловие:** память экспортирована папкой открытых Markdown-файлов.
- **Трассировка:** UC-01 → FR-01, FR-02 → триггер BP-16; BP-16, шаги 1–2.

## UC-02. Экспортировать журнал

- **Актор:** Пользователь.
- **Предусловие:** есть журнал записей (см. BP-07); пользователь хочет экспортировать журнал
  (триггер BP-16).
- **Основной поток:**
  1. Пользователь открывает «Память → История».
  2. Пользователь запускает экспорт журнала; система выгружает журнал в Markdown/JSON. (FR-03)
- **Альтернативные потоки:**
  - А1 (числа): размер, при котором журнал архивируется, и число хранимых архивов — подтвердить
    (FR-03; BP-16.1, раздел 7; механика ротации — BP-07).
  - А2 (повтор): повторный экспорт выгружает актуальный журнал (допущение, FR-03).
  - А3 (выход): пользователь отменяет экспорт — ничего не выгружается (FR-03).
- **Постусловие:** журнал экспортирован из «Память → История».
- **Трассировка:** UC-02 → FR-03 → триггер BP-16; BP-16, шаг 2; тема 4.2.

## UC-03. Экспортировать чат

- **Актор:** Пользователь.
- **Предусловие:** есть чат с сообщениями (см. BP-02); пользователь хочет экспортировать чат
  (триггер BP-16).
- **Основной поток:**
  1. Пользователь открывает чат и запускает экспорт из чата. (FR-04)
  2. Система выгружает чат.
- **Альтернативные потоки:**
  - А1 (формат): формат экспорта чата в источниках не описан (FR-04; BP-16.1, раздел 7).
  - А2 (повтор): повторный экспорт выгружает актуальную версию чата (допущение, FR-04).
  - А3 (выход): пользователь отменяет экспорт — ничего не выгружается (FR-04).
- **Постусловие:** чат экспортирован из чата.
- **Трассировка:** UC-03 → FR-04 → триггер BP-16; BP-16, шаг 2; BP-02.

## UC-04. Удалить папку памяти

- **Актор:** Пользователь.
- **Предусловие:** папка памяти существует; пользователь хочет удалить данные (триггер BP-16).
- **Основной поток:**
  1. Пользователь закрывает приложение или останавливает синхронизацию.
  2. Пользователь удаляет папку памяти; система удаляет память и чаты. (FR-05)
  3. Вложения остаются в Saves. (FR-06)
- **Альтернативные потоки:**
  - А1 (порядок): при работающем приложении или активной синхронизации удаление не выполняется — папка
    удаляется после закрытия приложения или остановки синхронизации (FR-05; см. BP-13).
  - А2 (отмены нет): отмены удаления папки памяти нет; отмена предусмотрена только для чата и факта
    (FR-05; UC-05).
- **Постусловие:** папка памяти удалена вместе с памятью и чатами; вложения остаются в Saves.
- **Трассировка:** UC-04 → FR-05, FR-06 → триггер BP-16; BP-16, шаг 3.

## UC-05. Удалить чат или факт с отменой

- **Актор:** Пользователь.
- **Предусловие:** есть чат или факт; пользователь хочет его удалить (триггер BP-16).
- **Основной поток:**
  1. Пользователь удаляет чат или факт через интерфейс. (FR-06)
  2. Система удаляет его; удаление зафиксировано в журнале.
  3. Пользователь может отменить удаление через журнал. (FR-06; см. BP-07)
- **Альтернативные потоки:**
  - А1 (undo): пользователь отменяет удаление через журнал — запись возвращается (FR-06; BP-07;
    тема 4.2).
  - А2 (повтор): повторное удаление — снова с возможностью отмены через журнал (FR-06).
  - А3 (вложения): вложения удалённого чата остаются в Saves (FR-06).
- **Постусловие:** чат или факт удалён; отмена доступна через журнал.
- **Трассировка:** UC-05 → FR-06 → триггер BP-16; BP-16, шаг 3; тема 4.2.

## UC-06. Хранение и удаление секретов в настройках

- **Актор:** Пользователь.
- **Предусловие:** в настройках есть секреты (ключи API, логин Telegram, VPN-ключи); пользователь хочет
  удалить секрет (триггер BP-16 — удаление данных).
- **Основной поток:**
  1. Система хранит секреты в защищённом хранилище системы, отдельно от папки памяти. (FR-07)
  2. Пользователь открывает настройки и удаляет секрет. (FR-07; см. BP-12)
  3. Система удаляет секрет из хранилища; в журналах и журнале исходящих секрета не было — только
     счётчики скрытого. (FR-07, FR-08)
- **Альтернативные потоки:**
  - А1 (Linux): на Linux без Secret Service секрет хранится файлом в служебной папке памяти — не шифрован,
    защищён только правами владельца (FR-07; требования, раздел 7; тема 4.1).
  - А2 (повтор): удаление повторяется для каждого секрета отдельно (допущение, FR-07).
  - А3 (отказ): пользователь отменяет удаление — секрет остаётся в хранилище (FR-07).
- **Постусловие:** секрет удалён из хранилища; хранение секретов — отдельно от папки памяти.
- **Трассировка:** UC-06 → FR-07, FR-08 → триггер BP-16; BP-16, шаги 4–5; тема 4.1; BP-12.

## UC-07. Снапшот до первой правки дня

- **Актор:** Пользователь (проверяет сейв), Система (делает снапшот).
- **Предусловие:** начинается рабочий день; пользователь хочет проверить резервную копию (триггер BP-16).
- **Основной поток:**
  1. До первой правки дня система делает снапшот в папку сейвов. (FR-09)
  2. Пользователь проверяет сейв дня в папке сейвов (требования, раздел 1).
  3. Пользователь может восстановить снапшот по кнопке «восстановить» в журнале. (FR-09)
- **Альтернативные потоки:**
  - А1 (нет правок): правок в день не было — снапшот не создаётся (допущение: «до первой правки дня»
    означает снапшот только перед первой правкой; FR-09).
  - А2 (восстановление): восстановление — по кнопке «восстановить» в журнале (FR-09).
- **Постусловие:** сейв дня доступен в папке сейвов (если правки были); восстановление — по кнопке
  «восстановить» в журнале.
- **Трассировка:** UC-07 → FR-09 → триггер BP-16; BP-16, шаг 6; требования, раздел 1.

## UC-08. Полная копия папки — на усмотрение пользователя

- **Актор:** Пользователь.
- **Предусловие:** пользователь хочет полную копию папки (триггер BP-16 — «проверить резервную копию»).
- **Основной поток:**
  1. Пользователь сам решает о полной копии папки; система копию не навязывает. (FR-10)
  2. Копирование через синхронизацию — см. BP-13. (FR-10)
- **Альтернативные потоки:**
  - А1 (синк): полная копия поддерживается синхронизацией — BP-13 (FR-10).
  - А2 (отказ): пользователь не делает полную копию — данные остаются в папке памяти (FR-10).
- **Постусловие:** полная копия папки сделана (или не делается) по решению пользователя.
- **Трассировка:** UC-08 → FR-10 → триггер BP-16; BP-16, шаг 6; BP-13.
