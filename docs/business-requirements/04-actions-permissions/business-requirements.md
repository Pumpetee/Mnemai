# BP-04.1. Бизнес-требования: действия и разрешения

## Цель

Обеспечить исполнение действий (инструментов), которые запрашивают ИИ в чате и на шагах схем: разрешения,
обязательные подтверждения, пароль администратора, лимиты, отмена через журнал, защита секретов.

## Бизнес-результат

Действие выполнено или отклонено; результат возвращён модели; каждая запись отменяема через журнал.

## Требования

- Система должна предоставлять модели каталог из 56 инструментов (на 18.11.2026, не считая служебного
  списка): память, файлы, команды, веб, задачи, буфер обмена, уведомления, снимок экрана, фоновые задачи,
  субагенты.
- Система должна при выключенном тумблере разрешений выполнять действие сразу, без вопроса (отмена — в
  «Истории»), а при включённом — показывать карточку с кнопками «Да / Нет / Да для этого разговора».
- Система должна по ответу «Да для этого разговора» заносить действие в список разрешённых действий
  разговора (действует только в пределах чата); mcp_call спрашивает одно «да» на вызов, но «Да для этого
  разговора» разрешает его на весь разговор; проверочные прогоны mcp_smoke* — всегда по одному «да» на
  каждый прогон, в список разговора они не попадают.
- Система должна спрашивать пароль администратора (sudo) один раз (не попадает ни в файл чата, ни в
  запросы модели), исполнять действие и возвращать результат модели; записи в память и файлы идут через
  журнал с отменой.
- Система должна ограничивать действия модели: до 12 на один ответ в чате, до 80 на шаге схемы; один
  вызов провайдера — не более 300 с.
- Система должна останавливать выполнение при трёх одинаковых действиях подряд с причиной «цикл» и ждать
  решения по карточке разрешения не более 600 с; одинаковость действия определяется с учётом аргументов.
- Система должна не давать файловым инструментам читать или писать запрещённые пути секретов (`.ssh`,
  `.gnupg`, `.aws`, keyring и секретные хранилища браузеров) ни при каком разрешении и отклонять команды,
  в которых эти пути встречаются.
- Система должна выполнять полный проверочный прогон всех инструментов в безопасной приватной временной
  папке: тестовые записи помечаются и удаляются, буфер обмена восстанавливается, инструменты рабочего
  стола пропускаются.

## Бизнес-правила

- Пользователь отвечает на карточку кнопками «Да / Нет / Да для этого разговора» и не вводит системных
  идентификаторов действий.
- «Да для этого разговора» действует только в пределах чата; вызовы внешних MCP-инструментов и
  проверочные прогоны принимают только отдельное «да» и в список разрешённых действий разговора не
  попадают.
- Одинаковость действия при защите от цикла определяется с учётом аргументов.
- Deny-list — чёрный список защиты конкретных секретов, а не песочница; расширение доступа — только с
  явного разрешения пользователя и после ревью.
- Тумблер разрешений задаётся в настройках по BP-12; применяет его к каждому действию BP-04.
- Действия участников консорциума исполняются по правилам BP-04.

## Область вне требований

- Поведение при исчерпании лимита действий (12 на ответ / 80 на шаге), судьба действия после истечения
  600 с ожидания «да» и что именно останавливается при «цикле» в чате (на шаге схемы — шаг, по BP-06) не
  описаны.
- Полный перечень 56 инструментов не приведён — заданы только группы.
- Сторонние MCP-серверы как источники инструментов и защита от prompt injection — открытые вопросы; при
  положительном решении по серверам каталог пополнится, см. BP-05.
- Сами инструменты по областям описываются в BP-07 (память), BP-11 (файлы), BP-02 (чтение веб-страниц);
  внешние MCP-клиенты — BP-05; запуск схем — BP-06; журнал и отмена — BP-07.
