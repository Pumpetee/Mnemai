# BP-14.2. Функциональные требования: обновления приложения

Процесс: BP-14 каталога бизнес-процессов; основание — человеко-требования. Каждое требование сформулировано «Система должна…», без технических деталей; шаги чужих процессов и сквозных тем не дублируются — только ссылки («см. BP-XX», «тема 4.x»). Каждый FR трассирован на шаг BP-14, на триггер BP-14 или на раздел человеко-требований (в скобках).

## 1. Проверка релизов и кнопка Update (BP-14, шаг 1)

### FR-01 — Тихая проверка релизов
Система должна тихо (в фоне) проверять наличие новых релизов при каждом запуске приложения и при
нажатии кнопки Update.
**Приёмка:** проверка выполняется при каждом запуске и при нажатии кнопки Update без действий
пользователя; приложение продолжает работать на текущей версии во время проверки.
(BP-14, шаг 1; раздел «Desktop и жизненный цикл»; пункт о частоте проверки обновлений; решение владельца)

### FR-02 — Кнопка Update
Система должна показывать кнопку Update, когда доступна новая версия.
**Приёмка:** при обнаруженной новой версии кнопка Update видна пользователю; при отсутствии новой версии
кнопка не показывается, работа продолжается.
(BP-14, шаг 1; раздел «Desktop и жизненный цикл»)

### FR-03 — Запуск установки по кнопке Update
Система должна начинать установку обновления по нажатию кнопки Update.
**Приёмка:** нажатие кнопки Update запускает установку по правилам ОС (FR-04, FR-05, FR-06); фоновая
проверка при этом выполняется при каждом запуске приложения (FR-01).
(Триггер BP-14; раздел «Desktop и жизненный цикл»)

## 2. Установка по ОС (BP-14, шаг 2)

### FR-04 — Windows: установка при выходе
Система должна на Windows устанавливать обновление при выходе из приложения.
**Приёмка:** установка выполняется при выходе из приложения; сам выход и его последствия — по правилам
темы 4.7 (см. BP-12).
(BP-14, шаг 2; раздел «Desktop и жизненный цикл»; тема 4.7 — ссылка)

### FR-05 — Linux: замена установочного файла и перезапуск
Система должна на Linux заменять установочный файл новой версией и перезапускать приложение.
**Приёмка:** после установки приложение перезапускается и работает на новой версии.
(BP-14, шаг 2; раздел «Desktop и жизненный цикл»)

### FR-06 — macOS: открытие образа установки
Система должна на macOS открывать образ установки новой версии и показывать инструкцию по установке в
окне.
**Приёмка:** система открывает образ установки и показывает в окне инструкцию по установке.
(BP-14, шаг 2; раздел «Desktop и жизненный цикл»; решение владельца)

## 3. Целостность и отказ (BP-14, шаг 3)

### FR-07 — Проверка целостности обновления
Система должна проверять целостность обновления по контрольной сумме: основной источник — метаданные
релиза, запасной вариант — отдельный файл контрольной суммы.
**Приёмка:** перед применением обновление проверяется по контрольной сумме; при недоступности основного
источника используется запасной файл контрольной суммы.
(BP-14, шаг 3; раздел «Desktop и жизненный цикл»)

### FR-08 — Отказ применять при несовпадении или сбое
Система должна не применять обновление при несовпадении контрольной суммы, сбое установки или сбое
самой проверки; при сбое проверки цикл пропускается без установки.
**Приёмка:** при несовпадении суммы или сбое установки обновление не применяется; при сбое самой
проверки цикл пропускается без установки; приложение продолжает работать на текущей версии.
(BP-14, шаг 3; раздел «Desktop и жизненный цикл»; решение владельца)

### FR-09 — Источник и канал проверки
Система должна проверять релизы из GitHub-релизов по стабильному каналу.
**Приёмка:** проверка выполняется из GitHub-релизов по стабильному каналу; бета-каналы не предусмотрены.
(BP-14, шаг 1; пункт о частоте проверки обновлений; решение владельца)
