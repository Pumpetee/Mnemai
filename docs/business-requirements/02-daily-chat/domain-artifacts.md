# BP-02.4. Артефакты предметной области: ежедневный чат с ИИ

Процесс: BP-02 каталога бизнес-процессов; основание — человеко-требования (разделы «Термины и роли», «Память (ядро)», «Чат с любым ИИ», «Приватность и безопасность», «Краевые состояния и отказы»). Сущности, их состояния и переходы, правила сборки ответа и словарь терминов процесса. Механика обучения, действий, вложений, памяти и приватности не дублируется — ссылки на BP-04, BP-07, BP-08, BP-11, BP-12 и темы 4.1, 4.3.

## 1. Модель состояний чата

```
Отправка сообщения в чате (триггер BP-02)
        │
        ├─ нет подключённых ИИ ──► «Нет ИИ»: объяснение + настройки;
        │                          память, журнал, команды без модели работают (BP-02, шаг 7)
        ▼
Сохранение сообщения; обучение в фоне (BP-08)
        │
        ▼
Сборка ответа: правила общения (BP-12) + память по скоупам (тема 4.1)
             + живое описание Mnemai + части базы знаний
        │
        ├─ облачный провайдер ──► правила темы 4.1 (скрытие секретов, журнал исходящих)
        ▼
Генерация (стриминг)
        ├─ «Стоп» ──► Остановлен
        ├─ redo / regenerate ──► новая генерация
        ├─ сбой провайдера ──► сообщение с причиной; провайдер нерабочий (тема 4.3)
        └─ офлайн ──► локальные модели; облачные недоступны
        ▼
Ответ выведен; под ответом — сэкономленные токены;
модель может попросить действие: до 12 на ответ — задано инструкцией модели, жёсткого счётчика нет;
без ответа 600 с действие отменяется, генерация останавливается (BP-04)
```

| Переход | Откуда → куда | Правило |
|---|---|---|
| Отправка сообщения | — → Сообщение сохранено | BP-02, шаг 1; FR-01; обучение — BP-08 |
| Нет ИИ | Отправка → «Нет ИИ» | BP-02, шаг 7; FR-13 |
| Сборка ответа | Сообщение сохранено → Генерация | BP-02, шаги 2–3; FR-03, FR-04 |
| Облачный запрос | Генерация → Запрос к облаку | BP-02, шаг 9; тема 4.1; FR-16 |
| Стриминг | Генерация → Ответ выводится | BP-02, шаг 4; FR-06 |
| «Стоп» | Генерация → Остановлен | BP-02, шаг 4; FR-07 |
| Redo / Regenerate | Остановлен / Ответ → Новая генерация | BP-02, шаг 4; FR-08 |
| Сбой провайдера | Генерация → Сообщение с причиной | BP-02, шаг 8; тема 4.3; FR-14 |
| Офлайн | Генерация → Локальная модель | BP-02, шаг 8; FR-15 |
| Ответ | Генерация → Ответ выведен (+ сэкономленные токены) | BP-02, шаг 3; FR-05 |
| Команда без модели | — → Выполнена без вызова ИИ | Тема 4.4; FR-17 |

## 2. Сущности, состояния и переходы

### 2.1 Сообщение

| Поле | Значение |
|---|---|
| Определение | Текст, который пользователь отправляет в чате; сохраняется, обучение на нём запускается в фоне (BP-02, шаг 1; раздел «Чат с любым ИИ») |
| Атрибуты | Текст; принадлежность чату/сессии; прикреплённые вложения (2.8); автор — пользователь (ответы ИИ — сущность «Ответ», 2.3) |
| Состояния | Черновик (неотправленный текст; восстановление после перезагрузки страницы — тема 4.7, BP-01) → Отправлено → Сохранено |
| Переходы | Отправить (BP-02, шаг 1; FR-01); восстановить черновик (тема 4.7 — BP-01); дальнейшее — обучение (BP-08) |

### 2.2 Чат (сессия)

| Поле | Значение |
|---|---|
| Определение | Сессия разговора с моделью; в приложении — список чатов (раздел «Чат с любым ИИ») |
| Атрибуты | Сообщения (2.1); ответы (2.3); выбранный ИИ (FR-02); список разрешённых действий этого разговора — BP-04 (ссылка) |
| Состояния | Создан (пустой) → Активный (есть сообщения; генерация идёт или завершена) |
| Переходы | Создать чат (FR-09); добавить сообщение (FR-01); экспортировать в Markdown (FR-10; владение данными — BP-16); импорт из ChatGPT создаёт чат (FR-11); удалить — BP-16 |

### 2.3 Ответ

| Поле | Значение |
|---|---|
| Определение | Потоковый текст модели, выводится в чате по мере генерации (раздел «Чат с любым ИИ») |
| Атрибуты | Текст (выводится потоком — FR-06); сэкономленные токены, показываемые под ответом (FR-05); причина остановки при сбое (тема 4.3) |
| Состояния | Генерируется (стриминг) → Выведен; Остановлен («Стоп» — FR-07); Прерван (сбой провайдера — тема 4.3) |
| Переходы | Стриминг (FR-06); «Стоп» (FR-07); redo / regenerate → новый ответ на тот же запрос (FR-08); сбой → сообщение с причиной (FR-14) |

### 2.4 Провайдер / модель

| Поле | Значение |
|---|---|
| Определение | Источник ИИ, отвечающий в чате (раздел «Термины и роли» «Провайдер»; тема 4.3) |
| Атрибуты | Тип: подписка Claude (Claude Code), подписка ChatGPT (Codex), ключи API (Anthropic, OpenAI, Gemini, DeepSeek, OpenRouter, YandexGPT, OpenCode Go), локальные модели (встроенная, Ollama, Strata), DeepSeek Harness-агент (раздел «Чат с любым ИИ»; тема 4.3); модель по выбору пользователя (FR-02) |
| Состояния | Подключён и работает; Нерабочий (помечен, в списки моделей не попадает); в офлайне: облачные недоступны, локальные работают (раздел «Краевые состояния и отказы») |
| Переходы | Подключение и проверка работоспособности — BP-12; сбой (упал / лимит / нет денег / ключ отклонён) → Нерабочий (тема 4.3; раздел «Краевые состояния и отказы»); возврат в работу — через проверку в настройках (BP-12) |
| Причины сбоя | Провайдер упал; лимит; нет денег; ключ отклонён (тема 4.3; раздел «Краевые состояния и отказы») — словарь причин для сообщений в чате (FR-14) |

### 2.5 Правила общения

| Поле | Значение |
|---|---|
| Определение | Каталог правил общения с тумблерами по темам: как говорить, работа с задачей, факты, память, приватность, оформление (раздел «Чат с любым ИИ») |
| Атрибуты | Тема правила; состояние тумблера (вкл/выкл — ведёт BP-12) |
| Состояния | Тумблер включён / выключен (владение — BP-12) |
| Переходы | Настройка тумблеров — BP-12; участие в сборке ответа — BP-02, шаг 2 (FR-03) |

### 2.6 Скоуп памяти

| Поле | Значение |
|---|---|
| Определение | Раздел памяти: профиль, правила, проекты, карточки, люди, решения, входящие, заметки (раздел «Термины и роли» «Скоуп») |
| Связь с клиентом | Клиент — правило доступа: какие части памяти и с какими правами видит конкретный ИИ (раздел «Термины и роли»); в чате модель получает только память в своих скоупах (тема 4.1) |
| Правило в чате | Скрытые разделы профиля, теги `#money`/`#health`/`#private`, скрытые от этого клиента части и факт-архив модели не передаются (тема 4.1; BP-07); настройка доступов — BP-12 |

### 2.7 Рецепт задачи

| Поле | Значение |
|---|---|
| Определение | Шаблон запроса, как в Obsidian (раздел «Чат с любым ИИ»); рецепты хранятся среди рецептов памяти (раздел «Память (ядро)») |
| Атрибуты | Текст шаблона; место хранения — рецепты памяти (раздел «Память (ядро)») |
| Состояния | Создан → Выбран в чате → Подставлен в сообщение |
| Переходы | Создать (FR-12); выбрать и подставить (FR-12); отменить подстановку (UC-06, А1) |

### 2.8 Вложение

| Поле | Значение |
|---|---|
| Определение | Файл, прикреплённый к сообщению; содержимое приложенных файлов входит в «что уходит в облако» (тема 4.1; раздел «Чат с любым ИИ», раздел «Приватность и безопасность») |
| Атрибуты | Файл; извлечённый текст (механика извлечения и распознавания — BP-11) |
| Состояния | Прикреплено → Обработано (текст извлечён; детали — BP-11) |
| Переходы | Прикрепить (BP-11 — ссылка); модели уходят только релевантные части содержимого (BP-02, шаг 3; FR-04) |

## 3. Правила сборки ответа (выбора контекста)

- Контекст ответа — только четыре источника: правила общения, видимая память, живое описание Mnemai,
  части базы знаний (BP-02, шаг 2; FR-03; BR-03).
- Память — только в скоупах клиента модели; скрытые части и факт-архив не уходят (тема 4.1; BP-07;
  BR-04).
- Документы, память и веб-страницы читаются на компьютере; модели уходят только релевантные части
  (BP-02, шаг 3; FR-04; BR-05).
- Части базы знаний включаются, когда вопрос касается Mnemai; веб-страницы читаются, когда вопрос
  требует свежих внешних данных (архитектурное описание «Одно сообщение в чате» — сверка фактов).
- Перед облачным запросом — скрытие секретов и журнал исходящих; локальная модель — без замен (BP-02,
  шаг 9; тема 4.1; FR-16).
- Под ответом — число сэкономленных токенов (BP-02, шаг 3; FR-05).
- Список разрешённых действий разговора («Да для этого разговора») ведёт BP-04 — здесь не дублируется.
