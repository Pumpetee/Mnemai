# BP-03.4. Артефакты предметной области: консорциум

## 1. Модель состояний консорциума

```
Запуск консорциума в чате; тема — первое сообщение (триггер BP-03; решение владельца)
        │
        ▼
Настройка: формат; участники (2–4 ИИ); число раундов; суммаризатор; лимит длины (BP-03, шаг 1)
        │
        ▼
Раунды: ведущий ведёт, участники выступают по очереди; память — по правам каждого (BP-03, шаг 2)
        ├─ «Стоп» ──► Пауза: сказанное сохранено; можно продолжить (BP-03, шаг 3)
        │                └─ продолжить ──► Раунды (решение владельца)
        ├─ спор под ответом ──► автор защищает, остальные ищут слабости (BP-03, шаг 4)
        ├─ действие участника ──► по правилам BP-04 (BP-03, шаг 5)
        └─ сбой провайдера ──► причина; провайдер нерабочий (BP-03, шаг 5; тема 4.3)
        ▼
Итог: выбранный суммаризатор подводит итог ──► итог в чате (результат BP-03)
```

| Переход | Откуда → куда | Правило |
|---|---|---|
| Запуск | — → Настроен | Триггер BP-03; FR-01 |
| Настройка | Настроен → Идёт (раунды) | BP-03, шаг 1; FR-02–FR-06 |
| Раунд | Идёт → выступления по очереди | BP-03, шаг 2; FR-07 |
| Реплика участника | — → Выступает → Выступил | BP-03, шаг 2; FR-07, FR-08 |
| «Стоп» | Раунды → Пауза (сказанное сохранено; можно продолжить) | BP-03, шаг 3; FR-09; решение владельца |
| Продолжить | Пауза → Раунды | Решение владельца; FR-09 |
| Спор | Под ответом → Идёт → Завершён | BP-03, шаг 4; FR-10 |
| Действие участника | Раунды → исполнение по BP-04 | BP-03, шаг 5; FR-12 |
| Сбой провайдера | Раунды → Сообщение с причиной; нерабочий | BP-03, шаг 5; тема 4.3; FR-13 |
| Итог | Раунды → Итог в чате | Результат BP-03; FR-11 |

## 2. Сущности, состояния и переходы

### 2.1 Консорциум

| Поле | Значение |
|---|---|
| Определение | Живая дискуссия 2–4 ИИ по одной теме (определения; требования чата) |
| Атрибуты | Тема — первое сообщение пользователя (решение владельца); формат (2.4); участники — 2–4 ИИ (2.3); число раундов; суммаризатор (2.5); лимит длины реплик (2.6); роли (2.8) |
| Состояния | Настроен → Идёт (раунды) → Завершён (итог в чате); Пауза («Стоп», сказанное сохранено, можно продолжить) |
| Переходы | Запуск в чате (триггер BP-03; FR-01); настройка (BP-03, шаг 1; FR-02–FR-06); раунды (FR-07); «Стоп» — пауза (FR-09); продолжить (FR-09); итог (FR-11) |

### 2.2 Раунд

| Поле | Значение |
|---|---|
| Определение | Круг выступлений: участники выступают по очереди; число раундов задаётся (требования чата; BP-03, шаги 1–2) |
| Атрибуты | Порядок в дискуссии; участники; реплики участников (сказанное — сохраняется при «Стоп», BP-03, шаг 3) |
| Состояния | Начат → Выступления по очереди → Завершён |
| Переходы | Очередь следующего участника (FR-07); «Стоп» прерывает текущую реплику (FR-09); по завершении заданного числа раундов — итог (FR-11) |

### 2.3 Участник (спикер)

| Поле | Значение |
|---|---|
| Определение | Один из 2–4 ИИ дискуссии; выступает по очереди (требования чата; назначение BP-03) |
| Атрибуты | ИИ — провайдер/модель (тема 4.3); права доступа к памяти — клиент (определения «Клиент»; тема 4.1); текущая реплика (сказанное); роль — участник (2.8) |
| Состояния | Выбран → Выступает (реплика генерируется) → Выступил; Остановлен («Стоп», FR-09). В споре: Автор ответа (защищает) / Ищущий слабости (BR-07) |
| Переходы | Очередь (FR-07); «Стоп» (FR-09); сбой провайдера — тема 4.3 (FR-13); роль в споре — FR-10 |
| Причина сбоя | Провайдер упал; лимит; нет денег; ключ отклонён (тема 4.3; краевые состояния) — словарь причин для сообщений (FR-13) |

### 2.4 Формат

| Поле | Значение |
|---|---|
| Определение | Способ ведения дискуссии из фиксированного набора: совет, дебаты, мозговой штурм, ред-тим, roast (требования чата; назначение BP-03) |
| Атрибуты | Название из фиксированного набора |
| Состояния | Выбран → Применяется в ходе дискуссии |
| Переходы | Выбор (FR-02); смена до запуска (UC-02, А1) |
| Примечание | Чем форматы различаются — источники не описывают; описание архитектуры («Консорциум») называет четыре формата без roast — расхождение отмечено в BP-03.1 |

### 2.5 Суммаризатор

| Поле | Значение |
|---|---|
| Определение | Выбранный ИИ, который подводит итог дискуссии (требования чата «выбранный суммаризатор»; описание архитектуры («Консорциум») — «кто подводит итог») |
| Атрибуты | ИИ (провайдер/модель — тема 4.3); роль — суммаризатор (2.8) |
| Состояния | Выбран → Подводит итог → Итог в чате |
| Переходы | Выбор (FR-05); итог по завершении раундов (FR-11) |
| Примечание | Является ли суммаризатор участником — не описано (BP-03.1, «Область вне требований») |

### 2.6 Лимит длины

| Поле | Значение |
|---|---|
| Определение | Ограничение длины реплик участников (требования чата «лимит длины»; BP-03, шаг 1 — «лимит длины реплик») |
| Атрибуты | Значение лимита |
| Состояния | Задан → Применяется к репликам |
| Переходы | Задание (FR-06) |
| Примечание | В каких единицах задаётся лимит и есть ли значение по умолчанию — не описано (BP-03.1, «Область вне требований») |

### 2.7 Спор

| Поле | Значение |
|---|---|
| Определение | Режим под любым ответом: автор ответа защищает его, остальные участники ищут слабости (требования чата; BP-03, шаг 4) |
| Атрибуты | Ответ, под которым запущен; автор ответа (защищается); остальные участники (ищут слабости) |
| Состояния | Запущен → Идёт → Завершён |
| Переходы | Запуск под ответом (FR-10); «Стоп» применим и в споре (FR-09) |
| Примечание | Чем спор завершается (итог спора) — не описано (BP-03.1, «Область вне требований») |

### 2.8 Роль

| Поле | Значение |
|---|---|
| Определение | Фиксированные роли дискуссии: ведущий, участники, суммаризатор (решение владельца) |
| Атрибуты | Ведущий — ведёт дискуссию по очереди; участники — выступают; суммаризатор — подводит итог |
| Состояния | Закреплена за дискуссией |
| Переходы | Роли закреплены при запуске (FR-07); суммаризатора выбирает пользователь (FR-05) |

## 3. Правила доступа участников к памяти

- Каждый участник получает память только по своим правам доступа (BP-03, шаг 2; FR-08; BR-05).
- Права участника — его клиент: какие части памяти и с какими правами видит конкретный ИИ (определения «Клиент»);
  одно правило прав для чата и внешних MCP-клиентов (тема 4.1).
- Скрытые разделы профиля, теги `#money`/`#health`/`#private`, скрытые от этого клиента части и факт-архив
  участнику не передаются (тема 4.1; BP-07).
- Локальная модель видит всё — с компьютера ничего не уходит (тема 4.1).
- Настройка доступов — BP-12. Механика чтения памяти — BP-07.

## 4. Словарь терминов процесса

Термины согласованы с определениями вводных требований; определения приводятся дословно, новые термины процесса выводятся
из требований чата, лимитов, краевых состояний и каталога BP-03.

| Термин | Определение | Источник |
|---|---|---|
| Пользователь (владелец) | Человек, чья это память и компьютер. В массовом продукте — любой человек | определения (дословно) |
| Клиент | Правило доступа: какие части памяти и с какими правами видит конкретный ИИ | определения (дословно) |
| Провайдер | Источник ИИ: подписка Claude (Claude Code), подписка ChatGPT (Codex), ключ API, локальная модель, Harness-агент | определения (дословно) |
| Консорциум | Живая дискуссия 2–4 ИИ по одной теме | определения (дословно); детали — требования чата |
| Скоуп | Раздел памяти: профиль, правила, проекты, карточки, люди, решения, входящие, заметки | определения (дословно) |
| Формат | Способ ведения дискуссии из фиксированного набора: совет, дебаты, мозговой штурм, ред-тим, roast; различия форматов не описаны | требования чата; BP-03, шаг 1 |
| Участник (спикер) | Один из 2–4 ИИ дискуссии; выступает по очереди | требования чата; BP-03, шаг 2 |
| Раунд | Круг выступлений: участники выступают по очереди; число раундов задаётся | требования чата; BP-03, шаги 1–2 |
| Суммаризатор | Выбранный ИИ, который подводит итог дискуссии | требования чата; описание архитектуры («Консорциум») |
| Лимит длины | Ограничение длины реплик участников | требования чата; BP-03, шаг 1 |
| «Стоп» | Команда: поставить дискуссию на паузу — остановить текущего ИИ, сохраняя сказанное; можно продолжить | требования чата; BP-03, шаг 3; решение владельца |
| Спор | Режим под любым ответом: автор защищает, остальные ищут слабости | требования чата; BP-03, шаг 4 |
| Реплика (сказанное) | Выступление участника; сохраняется при «Стоп» | BP-03, шаг 3; требования чата |
| Итог | Результат дискуссии в чате; подводит выбранный суммаризатор | Результат BP-03; требования чата |
| Тема | Первое сообщение пользователя | Решение владельца; определения («по одной теме») |
| Роль | Фиксированный набор: ведущий (ведёт по очереди), участники (выступают), суммаризатор (подводит итог) | Решение владельца; BP-03, шаг 2 |
| Лимит вызова | Один вызов провайдера — не более 300 с; применим и к репликам участников | Тема 4.3; лимиты |
