# BP-08.3. Сценарии использования: обучение из источников

Цепочка прослеживаемости: сценарий ввода → BP-08 (каталог бизнес-процессов) → BP-08.1…4 (эта папка). Каждый UC трассирован «UC → FR → BP-08 шаг»; трассировка включает FR альтернативных потоков.

## 0. Сценарий ввода → BP-08

Путь клиента, шаг 2.6: «настройки → обучение» → подключить чаты/почту/Telegram/Obsidian
→ периодический разбор. CLIENT_JOURNEY перечисляет четыре источника из восьми; каталог BP-08 зафиксировал
набор по раздел «Обучение» (примечание — в BP-08.1). Сценарий покрывается UC-01–UC-07.

## UC-01. Новый факт из разрешённого источника (пример — выбранный Telegram-чат)

- **Актор:** Mnemai (чтение и разбор), ИИ (разбор), Пользователь (разрешение источника — BP-12).
- **Предусловие:** источник (например, выбранный Telegram-чат) включён и разрешён (настройка — BP-12);
  память доступна.
- **Основной поток:**
  1. Срабатывает таймер обучения (раз в час). (FR-03; триггер BP-08)
  2. Система читает только включённые и разрешённые источники. (FR-01, FR-02)
  3. Telegram читается строго на чтение; доступ — через логин, хранящийся по правилам темы 4.1.
     (FR-04, FR-16)
  4. Система формирует эпизоды из прочитанного. (FR-05)
  5. Система разбирает эпизоды способом по типу источника (Telegram — сигналы, файлы и веб — локальная
     модель) — получаются факты-кандидаты. (FR-06)
  6. Журнал уверенности фиксирует кандидата с днём «said_at». (FR-07)
  7. Уверенность не ниже порога автозаписи → решение «записать». (FR-09, FR-08)
  8. Система записывает факт по правилам BP-07. (FR-13)
  9. Система начисляет достижение за обучение. (FR-15; тема 4.6)
- **Альтернативные потоки:**
  - А1 (нет разрешения): источник не разрешён или выключен → не читается (FR-02).
  - А2 (чужой чат): Telegram-чат не выбран → не читается; читаются только выбранные чаты (FR-01).
  - А3 (запись в Telegram): невозможна — Telegram строго чтение (FR-04).
  - А4 (личное): кандидат на личную тему (деньги, здоровье, приватное) → только в скрытые карточки —
    UC-02 (FR-10).
  - А5 (ниже порога): уверенность ниже порога → «подождать» — UC-04 (FR-09).
  - А6 (офлайн): сеть недоступна → пауза сетевых источников — UC-06 (FR-14).
- **Постусловие:** факт записан в память (BP-07); решение с причиной — в фиде (FR-08).
- **Трассировка:** UC-01 → FR-01, FR-02, FR-03, FR-04, FR-05, FR-06, FR-07, FR-08, FR-09, FR-10, FR-13,
  FR-14, FR-15, FR-16 → BP-08, шаги 1–4, 6–7; темы 4.1, 4.6.

## UC-02. Личный факт — только в скрытые карточки

- **Актор:** Mnemai; Пользователь (не участвует при разборе вне чата — Mnemai решает сам).
- **Предусловие:** кандидат на личную тему (деньги, здоровье, приватное) получен из источника вне чата.
- **Основной поток:**
  1. Система определяет кандидата как личный. (FR-10)
  2. Система принимает решение с причиной в фиде. (FR-08)
  3. Система записывает факт только в скрытые карточки по правилам BP-07. (FR-10, FR-13)
- **Альтернативные потоки:**
  - А1 (из разговора): личное найдено в разговоре в Mnemai → один вопрос под разговором — UC-03 (FR-11).
  - А2 (отмена): пользователь отменяет выученную запись → «нет» навсегда — UC-05 (FR-12).
  - А3 (скрытые теги): скрытые карточки и теги — по правилам темы 4.1, настройка — BP-12 (ссылка).
- **Постусловие:** личный факт — только в скрытых карточках; причина решения — в фиде.
- **Трассировка:** UC-02 → FR-08, FR-10, FR-11, FR-12, FR-13 → BP-08, шаги 3–6; тема 4.1.

## UC-03. Противоречие или личный факт в разговоре — вопрос под разговором

- **Актор:** Mnemai (вопрос), Пользователь (ответ), ИИ (разбор разговора).
- **Предусловие:** в чате Mnemai появилось новое сообщение (триггер BP-08); при разборе найден личный
  факт или противоречие.
- **Основной поток:**
  1. Система находит личный факт или противоречие в разговоре. (FR-11; триггер BP-08)
  2. Система задаёт один вопрос под этим разговором, с учётом кулдауна повторного вопроса и порога
     уверенности. (FR-11)
  3. Пользователь отвечает «Да» или «Нет». (FR-11)
  4. «Да» — факт записывается по правилам BP-07; «Нет» — запись не выполняется. (FR-11, FR-13)
  5. Система принимает решение с причиной в фиде. (FR-08)
- **Альтернативные потоки:**
  - А1 (кулдаун): кулдаун повторного вопроса не истёк → повторный вопрос не задаётся (FR-11).
  - А2 (не гарантируется): «спросить один раз» не гарантируется при каждой находке — вопрос может не
    появиться (FR-11).
  - А3 (отмена): пользователь отменяет выученную запись → «нет» навсегда — UC-05 (FR-12).
  - А4 (личное): если запись принята — личное только в скрытые карточки — UC-02 (FR-10).
- **Постусловие:** ответ пользователя учтён в решении; факт записан (BP-07) или пропущен; причина — в
  фиде.
- **Трассировка:** UC-03 → FR-08, FR-10, FR-11, FR-12, FR-13 → BP-08, шаги 3–6.

## UC-04. Сомнительная догадка — ждать повторения

- **Актор:** Mnemai, ИИ (разбор).
- **Предусловие:** у кандидата уверенность ниже порога автозаписи.
- **Основной поток:**
  1. Система сравнивает уверенность с порогом автозаписи. (FR-09)
  2. Уверенность ниже порога → решение «подождать» с причиной в фиде. (FR-08, FR-09)
  3. При повторном упоминании журнал уверенности повышает уверенность; день «said_at» хранится. (FR-07)
  4. Когда уверенность достигает порога → решение «записать». (FR-09, FR-08)
  5. Система записывает факт по правилам BP-07. (FR-13)
- **Альтернативные потоки:**
  - А1 (без повтора): повтор не наступает — кандидат остаётся в ожидании (FR-07).
  - А2 (личное): кандидат на личную тему — только в скрытые карточки — UC-02 (FR-10).
  - А3 (пропустить): система решает «пропустить» — причина в фиде (FR-08).
- **Постусловие:** кандидат записан после достижения порога — или остаётся в ожидании/пропущен с
  причиной в фиде.
- **Трассировка:** UC-04 → FR-07, FR-08, FR-09, FR-10, FR-13 → BP-08, шаги 2–4, 6.

## UC-05. Отмена выученного — «нет» навсегда

- **Актор:** Пользователь.
- **Предусловие:** запись сделана обучением (BP-07); пользователь решает её отменить.
- **Основной поток:**
  1. Пользователь отменяет выученную запись (отмена записи — через журнал памяти, BP-07). (FR-12)
  2. Система трактует отмену как «нет» навсегда. (FR-12)
  3. Тот же факт больше не предлагается и не записывается обучением. (FR-12)
- **Альтернативные потоки:**
  - А1 (новая находка): обучение снова находит тот же факт → запись не повторяется (FR-12).
  - А2 (просто отмена записи): отмена факта в памяти без «нет» навсегда — механика BP-07 (ссылка,
    тема 4.2).
- **Постусловие:** факт выученным не считается; повторная запись исключена.
- **Трассировка:** UC-05 → FR-12 → BP-08, шаг 6; тема 4.2.

## UC-06. Офлайн — пауза сетевых источников

- **Актор:** Mnemai.
- **Предусловие:** интернет недоступен; обучение настроено (источники разрешены — BP-12).
- **Основной поток:**
  1. Срабатывает таймер обучения (раз в час). (FR-03)
  2. Сетевые источники недоступны — система приостанавливает обучение из них. (FR-14)
  3. Память, журнал и остальные локальные возможности продолжают работать (раздел «Краевые состояния и отказы»).
- **Альтернативные потоки:**
  - А1 (сеть вернулась): интернет появился — разбор сетевых источников возобновляется по таймеру
    (FR-03, FR-14).
  - А2 (запись невозможна): память заблокирована — запись фактов невозможна — см. BP-15 (раздел «Краевые состояния и отказы»).
- **Постусловие:** обучение из сетевых источников приостановлено до появления сети; после — по таймеру.
- **Трассировка:** UC-06 → FR-03, FR-14 → BP-08, шаги 1, 7; тема 4.8.

## UC-07. Фид «Что я понял и почему»

- **Актор:** Пользователь.
- **Предусловие:** обучение принимало решения (есть записи в фиде).
- **Основной поток:**
  1. Пользователь открывает фид «Что я понял и почему». (раздел «Термины и роли» «Фид»)
  2. Система показывает решения обучения с причинами. (FR-08)
  3. Пользователь видит по каждому решению, почему факт записан, спрошен, отложен или пропущен. (FR-08)
- **Альтернативные потоки:**
  - А1 (пустой фид): решений ещё не было — фид пуст, ошибок нет (допущение: поведение пустого фида в
    источниках не описано; соответствует правилу пустых списков без ошибок — BP-01, шаг 6).
- **Постусловие:** причины решений обучения просматриваются в фиде.
- **Трассировка:** UC-07 → FR-08 → BP-08, шаг 3; раздел «Термины и роли».
