# BP-02.3. Сценарии использования: ежедневный чат с ИИ

Цепочка прослеживаемости: сценарий ввода → BP-02 (каталог бизнес-процессов) → BP-02.1…4 (эта папка). Каждый UC трассирован «UC → FR → BP-02 шаг»; трассировка включает FR альтернативных потоков.

## 0. Сценарий ввода → BP-02

Путь клиента, шаг 2.2: открыл чат → написал → отправил → карточка действия (если модель
попросила инструмент) → «да/нет/всегда» → ответ → «откуда я это знаю» → память пополняется. Каталог BP-02
покрывает часть «чат — ответ»; карточка действия и «да/нет» — BP-04 (формулировка зафиксирована по раздел «Чат с любым ИИ»:
«Да / Нет / Да для этого разговора»); «откуда я это знаю» — BP-07; пополнение памяти — BP-08. Примечание о
расхождениях — в BP-02.1. Сценарий покрывается UC-01–UC-10.

## UC-01. Вопрос — ответ

- **Актор:** Пользователь (ИИ — отвечающая сторона).
- **Предусловие:** подключён хотя бы один работающий ИИ (иначе — UC-07); открыт чат; память доступна.
- **Основной поток:**
  1. Пользователь выбирает, к какому подключённому ИИ обратиться. (FR-02)
  2. Пользователь вводит сообщение (при желании — через рецепт задачи, FR-12; UC-06).
  3. Пользователь отправляет сообщение; система сохраняет его и запускает обучение в фоне. (FR-01;
     см. BP-08)
  4. Система собирает ответ: правила общения, видимая память, живое описание Mnemai, части базы
     знаний. (FR-03)
  5. Система читает документы, память и веб-страницы на компьютере; модели уходят только релевантные
     части. (FR-04)
  6. Для облачного провайдера система применяет правила темы 4.1 — скрытие секретов и журнал исходящих
     (FR-16); для локальной модели — без замен.
  7. Система выводит ответ потоком; живой статус обновляется по мере генерации. (FR-06, FR-22)
  8. Под ответом система показывает сэкономленные токены. (FR-05)
- **Альтернативные потоки:**
  - А1 (действие): модель просит действие → карточка разрешения по правилам BP-04; результат
    возвращается модели, ответ продолжается. В чате — до 12 действий на ответ: это задано инструкцией
    модели, жёсткого счётчика нет; действие, на которое не ответили за 600 с, отменяется, генерация
    останавливается (BP-04).
  - А2 (управление): пользователь останавливает, повторяет или перегенерирует ответ — UC-02. (FR-07,
    FR-08)
  - А3 (сбой): провайдер упал / лимит / нет денег / ключ отклонён — UC-08. (FR-14)
  - А4 (блокировка): память зашифрована и заблокирована → запросы, которым нужна память, отклоняются;
    интерфейс предлагает ввести пароль (см. BP-15; раздел «Краевые состояния и отказы»).
  - А5 (выход): пользователь закрывает окно приложения; восстановление окна и черновика — тема 4.7
    (см. BP-01).
- **Постусловие:** ответ в чате; сообщение сохранено; обучение запущено в фоне; при необходимости модель
  попросила действие (результат BP-02).
- **Трассировка:** UC-01 → FR-01, FR-02, FR-03, FR-04, FR-05, FR-06, FR-12, FR-16, FR-22 → BP-02,
  шаги 1–4, 6, 9.

## UC-02. Остановка и повтор генерации (stop / redo / regenerate)

- **Актор:** Пользователь.
- **Предусловие:** идёт генерация ответа (для «Стоп») или ответ уже выведен (для redo / regenerate).
- **Основной поток:**
  1. Во время генерации пользователь жмёт «Стоп»; система прекращает генерацию. (FR-07)
  2. Пользователь жмёт redo или regenerate; система генерирует новый ответ на тот же запрос и выводит
     его потоком. (FR-08, FR-06)
  3. Под новым ответом система показывает сэкономленные токены. (FR-05)
- **Альтернативные потоки:**
  - А1 (повтор): «Стоп» применим и к новой генерации — генерация прекращается (FR-07).
  - А2 (отказ): повторная генерация упирается в сбой провайдера → сообщение с причиной (FR-14; UC-08).
- **Постусловие:** генерация остановлена; или в чате — новый ответ на тот же запрос.
- **Трассировка:** UC-02 → FR-05, FR-06, FR-07, FR-08 → BP-02, шаг 4.

## UC-03. Сессии и список чатов

- **Актор:** Пользователь.
- **Предусловие:** приложение запущено; память доступна.
- **Основной поток:**
  1. Пользователь создаёт новый чат; система создаёт сессию. (FR-09)
  2. Пользователь открывает чат из списка; система показывает его сообщения. (FR-09)
  3. Сообщения каждой сессии ведутся отдельно. (FR-09)
- **Альтернативные потоки:**
  - А1 (блокировка): память зашифрована и заблокирована — по правилам BP-15 (раздел «Краевые состояния и отказы»).
  - А2 (удаление): удаление чата — через интерфейс и журнал с отменой — BP-16.
- **Постусловие:** список чатов актуален; выбранный чат открыт.
- **Трассировка:** UC-03 → FR-09 → BP-02, шаг 5.

## UC-04. Экспорт чата

- **Актор:** Пользователь.
- **Предусловие:** есть чат с сообщениями.
- **Основной поток:**
  1. Пользователь открывает чат и выбирает экспорт. (FR-10)
  2. Система выгружает чат в Markdown. (FR-10)
  3. Владение данными в целом, экспорт памяти и журнала — BP-16, BP-07.
- **Альтернативные потоки:**
  - А1 (отказ): пользователь отменяет экспорт → ничего не выгружается.
  - А2 (повтор): повторный экспорт → выгружается актуальная версия чата.
- **Постусловие:** чат экспортирован в Markdown.
- **Трассировка:** UC-04 → FR-10 → BP-02, шаг 5.

## UC-05. Импорт из ChatGPT

- **Актор:** Пользователь.
- **Предусловие:** у пользователя есть данные чата из ChatGPT.
- **Основной поток:**
  1. Пользователь запускает импорт из ChatGPT. (FR-11)
  2. Система импортирует чат и показывает его в списке чатов. (FR-11, FR-09)
- **Альтернативные потоки:**
  - А1 (отказ): пользователь отменяет импорт → ничего не создаётся.
  - А2 (повтор): повторный импорт выполняется заново.
- **Постусловие:** импортированный чат доступен в списке чатов. Формат импорта в источниках не описан.
- **Трассировка:** UC-05 → FR-09, FR-11 → BP-02, шаг 5.

## UC-06. Рецепт задачи

- **Актор:** Пользователь.
- **Предусловие:** открыт чат; рецепты доступны (хранение рецептов — раздел «Память (ядро)»).
- **Основной поток:**
  1. Пользователь создаёт рецепт задачи (шаблон запроса). (FR-12)
  2. В чате пользователь выбирает рецепт; система подставляет шаблон в сообщение. (FR-12)
  3. Пользователь отправляет сообщение (UC-01).
- **Альтернативные потоки:**
  - А1 (отказ): пользователь отменяет подстановку → сообщение остаётся без шаблона.
  - А2 (повтор): шаблон подставляется в новое сообщение повторно (FR-12).
- **Постусловие:** рецепт создан; сообщение с подставленным шаблоном отправлено (или отправка отменена).
- **Трассировка:** UC-06 → FR-12 → BP-02, шаг 6.

## UC-07. Работа без подключённых ИИ (краевое состояние)

- **Актор:** Пользователь.
- **Предусловие:** не подключён ни один ИИ (подключение первого ИИ — BP-01; настройка — BP-12).
- **Основной поток:**
  1. Пользователь открывает чат и пытается отправить сообщение.
  2. Система не отправляет запрос, объясняет, что нужно подключить хотя бы один ИИ, и ведёт в
     настройки. (FR-13)
  3. Память, журнал и команды без модели работают. (FR-13, FR-17; раздел «Краевые состояния и отказы»)
  4. Пользователь подключает ИИ (см. BP-12).
- **Альтернативные потоки:**
  - А1 (повтор): подключение откладывается — состояние сохраняется; объяснение показывается на каждый
    запрос (FR-13).
  - А2 (выход): пользователь работает только с памятью, журналом и командами без модели — они работают
    (FR-13, FR-17).
- **Постусловие:** подключён хотя бы один ИИ — или состояние «нет ИИ» продолжается без ошибок.
- **Трассировка:** UC-07 → FR-13, FR-17 → BP-02, шаг 7; тема 4.4.

## UC-08. Сбой провайдера

- **Актор:** Пользователь.
- **Предусловие:** отправлен запрос; провайдер упал / лимит / нет денег / ключ отклонён.
- **Основной поток:**
  1. Система показывает сообщение с причиной сбоя. (FR-14)
  2. Система помечает провайдера нерабочим; в списки моделей он не попадает. (FR-14; тема 4.3)
  3. Пользователь выбирает другого провайдера и повторяет запрос. (FR-02)
- **Альтернативные потоки:**
  - А1 (таймаут): вызов длится более 300 с → завершается по лимиту (FR-21).
  - А2 (повтор): повторный запрос к тому же нерабочему провайдеру → сообщение с причиной повторяется
    (FR-14).
  - А3 (отказ): в цепочке схемы — замена исполнителя (см. BP-06).
- **Постусловие:** ответ получен от другого провайдера — или сбой зафиксирован с причиной; нерабочий
  провайдер исключён из списков моделей.
- **Трассировка:** UC-08 → FR-02, FR-14, FR-21 → BP-02, шаг 8; тема 4.3.

## UC-09. Офлайн

- **Актор:** Пользователь.
- **Предусловие:** интернет недоступен; подключена хотя бы одна локальная модель.
- **Основной поток:**
  1. Пользователь отправляет сообщение.
  2. Система обслуживает запрос локальной моделью. (FR-15)
  3. Память, журнал, команды без модели и файлы работают. (FR-15)
- **Альтернативные потоки:**
  - А1 (отказ): запрос к облачному провайдеру → облачные провайдеры недоступны; показана причина
    (FR-15; тема 4.3).
  - А2 (повтор): интернет появился → облачные провайдеры снова доступны (FR-15).
  - А3 (пауза): обучение из сетевых источников приостанавливается (см. BP-08).
- **Постусловие:** работа продолжается на локальных моделях до появления сети.
- **Трассировка:** UC-09 → FR-15 → BP-02, шаг 8; темы 4.3, 4.8.

## UC-10. Команды без модели

- **Актор:** Пользователь.
- **Предусловие:** приложение запущено; подключённые ИИ не требуются — команды работают и без них
  (FR-17).
- **Основной поток:**
  1. Пользователь вводит «открой …»: сайт из фиксированного каталога, ссылку, программу или файл.
  2. Система выполняет команду сразу, без вызова ИИ. (FR-17)
- **Альтернативные потоки:**
  - А1 (отказ): сайт не из каталога → не поддерживается: каталог фиксирован, свои сайты пользователь не
    добавляет (FR-17).
  - А2 (сайт из разговора): «открой этот сайт» — открыть ссылку из сообщения или вложения в системном
    браузере (FR-18).
  - А3 (офлайн): команды работают офлайн и без подключённых ИИ (FR-17).
- **Постусловие:** целевое действие выполнено (открыт сайт, ссылка, программа или файл) без вызова
  модели.
- **Трассировка:** UC-10 → FR-17, FR-18 → тема 4.4; BP-02, шаг 7.
