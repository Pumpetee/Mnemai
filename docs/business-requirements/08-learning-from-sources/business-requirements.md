# BP-08.1. Бизнес-требования: обучение из источников

## Цель

Пополнять память из разрешённых источников по таймеру: конвейер «источники → эпизоды → разбор →
факты-кандидаты → решение с причиной», с порогами уверенности, вопросами пользователю и фидом
«Что я понял и почему».

## Бизнес-результат

Факты записаны, спрошены или пропущены — с причиной в фиде; память пополнена (запись фактов — BP-07).

## Требования

- Система должна читать раз в час только включённые и разрешённые источники: AI-чаты, заметки, почта,
  Telegram (только выбранные чаты), Obsidian, календарь, документы, история браузера; каждый источник —
  отдельное разрешение.
- Система должна обращаться к Telegram только на чтение.
- Система должна формировать из прочитанного эпизоды и разбирать их способом по типу источника
  (Telegram — явные сигналы, файлы и веб — локальная модель и т. п.); результат разбора —
  факты-кандидаты.
- Система должна вести по кандидатам журнал уверенности: повторения повышают уверенность; хранится
  день, когда сказано (said_at).
- Система должна по каждому кандидату принимать одно из решений: записать / спросить / подождать /
  пропустить — с причиной в фиде «Что я понял и почему».
- Система должна при уверенности не ниже порога автозаписи (настройка auto_confidence, по умолчанию
  0.8 — 80 %) записывать факт сразу; сомнительное — ждать повторения.
- Система должна записывать личное (деньги, здоровье, приватное) только в скрытые карточки.
- Система должна из разговора в Mnemai спрашивать личный факт или противоречие одним вопросом с
  вариантами ответа «Да» и «Нет» под этим разговором, с учётом кулдауна повторного вопроса и порога
  уверенности; «Да» — факт записывается, «Нет» — запись не выполняется.
- Система должна трактовать отмену выученной записи как «нет» навсегда.
- Система должна в офлайне приостанавливать обучение из сетевых источников.
- Система должна начислять события достижений (опыт, уровни, серии, бейджи) в обучении.
- Система должна хранить логин Telegram по общим правилам хранения секретов и использовать его только
  для чтения источника.

## Бизнес-правила

- Читаются только включённые и разрешённые источники; каждое разрешение — отдельное.
- Чтение источников выполняется раз в час.
- Способ разбора назначается по типу источника: Telegram — явные сигналы, файлы и веб — локальная
  модель и т. п.
- На вопрос под разговором пользователь отвечает «Да» (записать) или «Нет» (не записывать).
- Telegram — строго чтение и только выбранные чаты.
- Решение по кандидату — одно из четырёх, с причиной в фиде.
- Факт с уверенностью не ниже порога записывается сразу; «спросить один раз» при каждой находке не
  гарантируется.
- Личное (деньги, здоровье, приватное) — только в скрытые карточки.
- Отмена выученной записи — «нет» навсегда: тот же факт больше не предлагается и не записывается.
- Пользователь выдаёт разрешения на источники и задаёт пороги в настройках (BP-12), не вводя системных
  идентификаторов.

## Область вне требований

- Запись фактов в память — BP-07; «Знакомство» и квиз — BP-09; настройка порогов и разрешений — BP-12.
- Перечень текстов причин фида не задан.
- Сбои провайдеров при разборе здесь не описываются — общие правила сбоев закреплены за BP-02 и BP-06.
- Защита от prompt injection в источниках обучения остаётся открытым вопросом.
