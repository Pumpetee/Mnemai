# BP-08.2. Функциональные требования: обучение из источников

Процесс: BP-08 каталога бизнес-процессов; основание — человеко-требования. Каждое требование сформулировано «Система должна…», без технических деталей; шаги чужих процессов и сквозных тем не дублируются — только ссылки («см. BP-XX», «тема 4.x»). Каждый FR трассирован на шаг BP-08 (в скобках); FR, которые вводятся сквозными темами каталога (4.1–4.8), трассируются на тему каталога и на раздел человеко-требований.

## 1. Источники и разрешения (BP-08, шаг 1)

### FR-01 — Набор источников
Система должна читать источники обучения: AI-чаты, заметки, почта, Telegram (только выбранные чаты),
Obsidian, календарь, документы, история браузера.
**Приёмка:** разбор охватывает перечисленные источники; из Telegram читаются только выбранные чаты;
подключение источников — BP-12.
(BP-08, шаг 1; раздел «Обучение»)

### FR-02 — Только включённые и разрешённые источники
Система должна читать только включённые и разрешённые источники; каждый источник — отдельное разрешение.
**Приёмка:** источник без разрешения не читается; разрешение каждого источника выдаётся отдельно
(настройка — BP-12).
(BP-08, шаг 1; раздел «Обучение»)

### FR-03 — Чтение по таймеру раз в час
Система должна запускать чтение и разбор источников по таймеру раз в час.
**Приёмка:** разбор запускается раз в час без действий пользователя; после разбора источники читаются
снова при следующем срабатывании таймера.
(BP-08, шаг 1; раздел «Обучение»; решение владельца)

### FR-04 — Telegram строго чтение
Система должна обращаться к Telegram только на чтение.
**Приёмка:** запись в Telegram невозможна; чтение — только выбранные чаты (FR-01).
(Граница BP-08 «Ограничение»; раздел «Ограничения»; тема 4.1)

## 2. Конвейер разбора (BP-08, шаг 2)

### FR-05 — Формирование эпизодов
Система должна формировать из прочитанного эпизоды для разбора.
**Приёмка:** прочитанное разбивается на эпизоды; каждый эпизод несёт источник и место происхождения
(состав атрибутов — сверка фактов, архитектурное описание «Обучение»).
(BP-08, шаг 2; раздел «Обучение»)

### FR-06 — Разбор эпизодов способом по типу источника
Система должна разбирать эпизоды способом по типу источника: Telegram — явные сигналы, файлы и веб —
локальная модель и т. п.; результат разбора — факты-кандидаты.
**Приёмка:** каждый тип источника разбирается назначенным ему способом; результатом становятся
факты-кандидаты.
(BP-08, шаг 2; раздел «Обучение»; решение владельца)

### FR-07 — Журнал уверенности
Система должна вести по кандидатам журнал уверенности: повторения повышают уверенность; хранится день,
когда сказано (`said_at`).
**Приёмка:** у кандидата ведётся уверенность; повторное упоминание повышает её; день «said_at»
сохраняется.
(BP-08, шаг 2; раздел «Обучение»)

## 3. Решение и порог (BP-08, шаги 3–4)

### FR-08 — Решение по кандидату с причиной
Система должна по каждому кандидату принимать одно из решений: записать / спросить / подождать /
пропустить — с причиной в фиде «Что я понял и почему».
**Приёмка:** каждому кандидату назначено одно из четырёх решений; причина решения видна в фиде.
(BP-08, шаг 3; раздел «Обучение»)

### FR-09 — Порог автозаписи
Система должна при уверенности не ниже порога автозаписи (настройка `auto_confidence`, по умолчанию 0.8 —
80 %) записывать факт сразу; при уверенности ниже порога — ждать повторения.
**Приёмка:** уверенность ≥ порога → решение «записать»; ниже порога → «подождать»; изменение порога —
в настройках (BP-12).
(BP-08, шаг 4; раздел «Обучение»)

### FR-10 — Личное только в скрытые карточки
Система должна записывать личное (деньги, здоровье, приватное) только в скрытые карточки.
**Приёмка:** факты на личные темы не попадают в открытые разделы памяти; скрытые карточки и теги — по
правилам темы 4.1, настройка — BP-12.
(BP-08, шаг 4; раздел «Обучение»; тема 4.1)

## 4. Вопросы под разговором (BP-08, шаг 5)

### FR-11 — Вопрос под разговором («Да / Нет»)
Система должна из разговора в Mnemai спрашивать личный факт или противоречие одним вопросом с
вариантами ответа «Да» и «Нет» под этим разговором, с учётом настроек обучения (кулдаун повторного
вопроса, порог уверенности); «Да» — факт записывается (FR-13), «Нет» — запись не выполняется.
**Приёмка:** вопрос появляется под соответствующим разговором; на находку — один вопрос; варианты
ответа — «Да» и «Нет»; кулдаун и порог применяются; «спросить один раз» не гарантируется при каждой
находке.
(BP-08, шаг 5; раздел «Обучение»; решение владельца)

## 5. Отмена и запись (BP-08, шаг 6)

### FR-12 — Отмена выученного: «нет» навсегда
Система должна трактовать отмену выученной записи как «нет» навсегда.
**Приёмка:** после отмены выученной записи тот же факт не предлагается повторно и не записывается снова.
(BP-08, шаг 6; раздел «Обучение»; тема 4.2)

### FR-13 — Запись фактов — по правилам BP-07
Система должна записывать принятые факты по правилам BP-07.
**Приёмка:** принятый факт записывается как обычный факт памяти (журнал, индекс, отмена — BP-07); BP-08
сам в память не пишет.
(BP-08, шаг 6; раздел «Обучение»; BP-07)

## 6. Офлайн и сквозные темы (BP-08, шаг 7; темы 4.1, 4.6, 4.8)

### FR-14 — Офлайн: пауза сетевых источников
Система должна в офлайне приостанавливать обучение из сетевых источников.
**Приёмка:** при отсутствии сети сетевые источники не читаются; после появления сети разбор
возобновляется по таймеру (FR-03).
(BP-08, шаг 7; раздел «Краевые состояния и отказы»; тема 4.8)

### FR-15 — Достижения за обучение
Система должна начислять события достижений (опыт, уровни, серии, бейджи) в обучении — по правилам
темы 4.6.
**Приёмка:** события достижений начисляются за обучение; события также начисляются в чате и памяти —
BP-02, BP-07.
(Тема 4.6; раздел «Desktop и жизненный цикл»)

### FR-16 — Логин Telegram по правилам темы 4.1
Система должна хранить логин Telegram по правилам темы 4.1 и использовать его только для чтения
источника.
**Приёмка:** логин Telegram хранится в защищённом хранилище системы (тема 4.1; детали хранения и
удаления — BP-16); используется только для чтения (FR-04).
(Тема 4.1; раздел «Приватность и безопасность»)
